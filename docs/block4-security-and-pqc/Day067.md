# Day 67: Sigstore & Code Signing

**Block:** Block 4: Security & PQC · Supply Chain Security

> **Goal of the day:** You can sign and verify a Rust binary with `cosign` (Sigstore), understand the "keyless" model (OIDC + transparency log), and know why the classic "GPG-signed" is being replaced by Sigstore's "identity-based, transparency-logged" model.

---

## 📖 Theory

Code signing proves **provenance** — "this binary comes from this entity". Classic: GPG keys that you manage and distribute. Problem: key-management overhead, no audit trail for revocation, records only local. **Sigstore** (CNCF, 2021) is the modern industry standard, used by Kubernetes, Sigstore itself, npm, Python PyPA.

### Sigstore architecture — three components

```text
[Builder/CI] ── sign ──> [Fulcio CA] (short-lived signing cert from OIDC)
                       │           │
                       │      [Rekor] (append-only transparency log)
                       │           │
                       └── signature + cert entry ──> [Artifact Registry]
[Verifier] <── verify ── [Rekor] + [Fulcio Root] ──> "valid, from GitHub Action run 123"
```

- **Fulcio**: CA that issues *only short-lived* signing certificates (~10 min). Identity from OIDC (GitHub, Google, GitLab). No long-term signing key needed.
- **Rekor**: append-only transparency log (Merkle tree). Every signature is publicly visible — a backdoor-in-a-build becomes discoverable.
- **Cosign**: CLI tool for signing/verifying.

### The keyless model (the default)

```text
1. The CI run authenticates via OIDC with GitHub Actions.
2. cosign asks Fulcio: "here is my OIDC token, give me a 10-min cert."
3. cosign signs the artifact with the ephemeral key + certified.
4. Signature + cert are entered in Rekor; the ephemeral key is destroyed.
```

Advantage: no stolen signing key that exists for 5 years. Identity is the email/issuer from the OIDC token, verifiable with the public Fulcio root CA.

### Classic vs. keyless

| Property | Classic GPG | Sigstore keyless |
| --- | --- | --- |
| Key lifetime | years | 10 min |
| Identity binding | KeyID, manual | OIDC email + issuer |
| Audit trail | local, opt-in | public (Rekor) |
| Rotation | manual, painful | per CI run, automatic |
| Revocation | CRL / web of trust | Fulcio CT log + Rekor search |

### What do you sign?

- **Container images** (cosign native): `cosign sign <registry>/<image>:tag`
- **Binaries / tarballs**: `cosign sign-blob --bundle out.sig target/release/pqc-tool`
- **SBOMs** (Day 66): `cosign attach sbom --sbom bom.json <image>` + sign the SBOM attestation
- **In-toto attestations**: "this binary was built from commit X, with SLSA level 3" — generic statements about provenance.

### Why this matters

The SolarWinds backdoor (2020) came via a build server with a long-term signing key. With Sigstore keyless the certificate would have expired after 10 min *and* the signature would have been visible in the transparency log — discovery would have been faster and the key would not have existed for years. Modern supply-chain engineering without Sigstore is a gap today.

### Pitfalls

- **Forgetting the OIDC issuer allowlist** — if you accept every OIDC provider, anyone who logs in to Google can sign. In verification set `--certificate-identity-regexp` + `--certificate-oidc-issuer` strictly.
- **Rekor offline?** — Cosign can verify offline *if* you have the bundle. Otherwise a Rekor lookup is needed (online dependency).
- **"GPG was good enough"** — Sigstore has identity trust (OIDC), GPG only key trust. Identity is more realistic in modern cloud builds.
- **Cosign bundle not committed** — without the bundle you cannot verify offline later; archive the bundle with release artifacts.
- **Cross-repo builds** — a build with a GitHub Action from repo A signs an artifact for repo B? The identity regexp must allow both, otherwise false negatives.

## 🛠️ Practice

**Task:** Sign your `pqc-tool` binary with `cosign` (locally with a self-managed key first, then optionally keyless with OIDC simulation via `COSIGN_EXPERIMENTAL=1`).

**Step by step:**

1. Install:
   ```bash
   brew install sigstore-cosign/cosign/cosign
   cosign version
   ```
2. Generate a key pair (for offline tests; production uses keyless):
   ```bash
   cosign generate-key-pair   # → cosign.key + cosign.pub, set a passphrase
   ```
3. Build + sign the binary:
   ```bash
   cd days/day65
   cargo build --release
   cosign sign-blob --key cosign.key --bundle pqc-tool.sig \
     --output-certificate pqc-tool.cert.pem target/release/pqc-tool
   ```
4. Verify:
   ```bash
   cosign verify-blob --key cosign.pub --bundle pqc-tool.sig \
     --certificate pqc-tool.cert.pem target/release/pqc-tool
   # → "Verified OK" + identity from the cert
   ```
5. Tamper test: `dd if=/dev/urandom of=target/release/pqc-tool bs=1 count=1 seek=100 conv=notrunc` → verify fails ("signature does not match").
6. **Keyless demo** (optional, needs OIDC; skippable if no GitHub workload):
   ```bash
   COSIGN_EXPERIMENTAL=1 cosign sign-blob --bundle pqc-tool.sig target/release/pqc-tool
   # A browser opens, login at GitHub/Google, Fulcio certifies short-lived.
   COSIGN_EXPERIMENTAL=1 cosign verify-blob \
     --certificate-identity your-email@example.com \
     --certificate-oidc-issuer https://github.com/login/oauth \
     --bundle pqc-tool.sig target/release/pqc-tool
   ```
7. **SBOM attestation** (connects with Day 66): `cosign attach sbom --sbom bom.json <image>` and `cosign attest --predicate bom.json --type cyclonedx <image>`.

**Definition of Done (DoD):**

- [ ] `cosign sign-blob` produces `pqc-tool.sig` + `pqc-tool.cert.pem`.
- [ ] `cosign verify-blob` with the correct key → "Verified OK".
- [ ] Tampered binary → verify fails (no false positive).
- [ ] You can explain in 2 sentences why keyless (OIDC + transparency log) is better than long-term GPG keys.
- [ ] You mentioned the identity-regexp setting (in README documentation of the verification workflow).
- [ ] Commit: `git commit -m "day67: cosign signing for pqc-tool (keyless via sigstore)"`.

**Extension (optional):** Set up a GitHub Action that on `git tag v*` automatically builds the binary, signs keyless, and attaches the bundle as a release asset — that is the production workflow.
