# Day 63: PQC in Rust & Production

**Block:** Block 4: Security & PQC · Post-Quantum Cryptography

> **Goal of the day:** You can perform ML-KEM encapsulate/decapsulate in Rust with `pqc_crypto` / `liboqs-rust`, know the differences between reference, hardened, and hardware implementations, and know how to harden PQC in production with fuzzing, constant-time tests, and side-channel hardening.

## 📖 Theory

Rust is the natural language for PQC implementations because memory safety + zeroizing + strict types eliminate whole side-channel classes. But: Rust alone does *not* automatically make PQC secure — the library behind it must be hardened.

### Three implementation categories

| Category | Sources | Advantage | Risk |
| --- | --- | --- | --- |
| **Reference implementation** | `liboqs`, NIST repo | available as fast as possible, current | not constant-time, leaks via cache/timing |
| **Hardened** | `aws-lc`, `rustls-pq` | constant-time, audited | effort, version lag |
| **Hardware / HSM** | PQC-capable HSMs | key never exfiltrable | still rare today, expensive |

For production: **hybrid** + hardened. For experiments/demos: the `pqc_crypto` crate is enough.

### ML-KEM API in Rust

```rust
use pqcrypto_kem::kyber768::{keypair, encapsulate, decapsulate};
use pqcrypto_traits::KEM;

let (pk, sk) = keypair();                    // public + secret key
let (ct, shared_kem) = encapsulate(&pk);     // sender: ciphertext + KEM shared
let shared_kem2 = decapsulate(&ct, &sk);     // receiver: derives the same
assert_eq!(shared_kem.as_bytes(), shared_kem2.as_bytes());
```

**Important:** the ML-KEM shared secret is **not** directly the AES key — it must be expanded through **HKDF** with a transcript hash (e.g. public keys, nonce) to get context binding:

```rust
let session_key = HKDF-SHA256(ikm = kem_shared || x25519_shared,
                              info = "tls13-X25519MLKEM768-v1")
```

### Hybrid X25519 + ML-KEM-768

Both shared secrets are concatenated and run through HKDF. **Both** secrets must be broken to crack the session — that is the security argument for the effort.

```rust
let classic = x25519_dh(private_classic, peer_classic);
let pq = kyber_decapsulate(ciphertext_pq, secret_pq);
let session = hkdf_extract(&[&classical, &pq], b"hybrid-v1");
```

### Production security: what comes on top

1. **Constant-time tests**: `dudect` harness or a `criterion` macro that measures runtime variance over inputs.
2. **Fuzzing**: `cargo fuzz` with random ciphertexts — decapsulate must never panic, only return an error result.
3. **Zeroize** all secret keys, shared secrets, error codes.
4. **Avoid decryption-failure oracles**: ML-KEM has a tiny failure rate; an attacker who can distinguish "decapsulate failed" vs. "succeeded" (timing) can reconstruct the key over many sessions. Therefore the failure path must take the same time as the success path.
5. **Key reuse forbidden** — ephemeral per handshake, then `zeroize`.

### Why this matters

Rust is today the dominant language for PQC prototypes (Signal, Mozilla, Cloudflare use Rust PQC code). Anyone who brings PQC to production will write these patterns in Rust — the theory of Day 61 becomes code here.

### Pitfalls

- **`pqcrypto_*` crates are version-maintained per parameter set** — Kyber512/768/1024 are separate crates. ML-KEM FIPS 203 has minor deviations from the last Kyber draft; mind that.
- **Using the shared secret directly as an AES key** — without an HKDF KDF this breaks context binding (cross-protocol attacks). ALWAYS use a KDF.
- **Side channels in the reference implementation** — `liboqs` documents itself that it is *not* constant-time. It is unusable in production.
- **Stack sizes** — ML-KEM public keys >1 KB; stack allocations in embedded systems can overflow. Heap or static buffer-size checks.
- **Version locking** — PQC APIs are in flux; commit `Cargo.lock`, re-test on minor upgrades.

## 🛠️ Practice

**Task:** Build a Rust hybrid encryptor: generates X25519 + ML-KEM-768 shared secrets, derives an AES-256-GCM session key via HKDF, and encrypts a file. Roundtrip + tamper test.

**Step by step:**

1. Project + deps:

   ```toml
   [dependencies]
   x25519-dalek = "2"
   pqcrypto-kyber = { version = "0.8", features = ["kyber768"] }
   pqcrypto-traits = "0.3"
   hkdf = "0.12"
   sha2 = "0.10"
   aes-gcm = "0.10"
   rand = "0.8"
   zeroize = "1"
   ```

2. Core logic (`src/main.rs`):
   > **Hints:**
   > - **Classical leg**: `EphemeralSecret::random()` + `PublicKey::from(&secret)` via `x25519-dalek`. Compute the shared secret with `secret.diffie_hellman(&peer_pub)`.
   > - **PQC leg**: `pqcrypto_kyber::kyber768::{keypair, encapsulate, decapsulate}` (import the `KEM` trait from `pqcrypto_traits`). `encapsulate(&pk)` returns `(ciphertext, kem_shared)`.
   > - **Hybrid KDF**: concatenate the X25519 shared bytes and the KEM shared bytes as `ikm`, then `Hkdf::<Sha256>::new(None, &ikm)` and `hk.expand(b"hybrid-v1", &mut session_key)` for the 32-byte AES key.
   > - **AEAD**: `Aes256Gcm` under the session key, random 12-byte nonce from `OsRng`. Build the output frame as `classic_pub || kyber_ct || nonce || aead_ct`. `session_key.zeroize()` after use.
   > - For the demo you can simulate the receiver by calling `decapsulate(&kyber_ct, &kyber_sk)` yourself; in production the receiver holds the secret key and does the DH + decapsulate independently.
3. CLI: `enc <file>` / `dec <file> <key>`, roundtrip.
4. Tamper test: flip 1 byte in the PQC ciphertext → `decapsulate` yields the wrong secret → AEAD verification fails.
5. Fuzzing prep: `cargo add cargo-fuzz; cargo fuzz add hybrid_decrypt` and send random bytes — should never panic, only `Err`.

**Definition of Done (DoD):**

- [ ] `cargo build` without warnings; all crypto RNGs are `OsRng`.
- [ ] `sha256sum` original vs. decrypt identical.
- [ ] Tampered ciphertext → decryption fails (neither panic nor silent partial).
- [ ] `session_key` is `zeroize()`d after use (code inspection proves it).
- [ ] You can explain why the `ikm` concatenation of both shared secrets + HKDF delivers the hybrid security argument (both must be broken).
- [ ] Commit: `git commit -m "day63: hybrid x25519+mlkem768 encryptor in rust"`.

**Extension (optional):** Write a `cargo bench` block comparing pure X25519 vs. X25519MLKEM768 (encapsulate+decapsulate) — measure overhead in µs and ciphertext bytes.
