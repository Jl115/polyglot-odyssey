# Day 75: Block-Capstone: PQC Migration CLI

**Block:** Block 4: Security & PQC · Block-Capstone

> **Goal of the day:** You build the final Block 4 artifact: a Rust CLI `pqc-migrator` with subcommands for inventory (crypto audit), hybrid keygen (X25519MLKEM768), encrypt/decrypt, Sigstore signing, and verification — and you formally verify it with Prusti/Kani. This is the consolidation of Day 56–74 into one auditable tool.

---

## 📖 Theory

This capstone is not a new concept but the **integration** of all Block 4 building blocks into a single tool a migration engineer would ship. It proves you can not only do individual topics but connect them into a coherent product — with formally verified security properties, supply-chain attestations, and a documented threat model.

### CLI design — all subcommands

```text
pqc-migrator
  ├─ inventory <dir>          # scans a codebase for crypto usage (Day 64)
  ├─ keygen [--out dir]        # hybrid X25519MLKEM768 keypair (Day 61/63)
  ├─ encrypt <file> --pubkey   # AEAD via hybrid session key (Day 56/63)
  ├─ decrypt <file> --seckey   # decrypt + verify (Day 63)
  ├─ sign <file> --seckey     # Sigstore signing (Day 67)
  ├─ verify <file> --pubkey   # Sigstore verification (Day 67)
  ├─ attest <file>            # SLSA provenance attestation (Day 68)
  └─ scan [--sbom]            # SBOM + cargo audit (Day 66)
```

### The formal verification — what is proven?

In the `crypto/` module these properties are verified:

- **Prusti**:
  - `encrypt(plain, pub)`: `ensures(result.len() == MAGIC_LEN + 1 + 32 + KEM_CT_LEN + 12 + plain.len() + 16)` — frame size is deterministic.
  - `hkdf_expand(ikm, info)`: `ensures(result.len() == 32)` — session-key length guaranteed to be 32.
- **Kani**:
  - `parse_frame(frame)`: for all possible inputs either a correct frame is returned or `Err` (no panic, no out-of-bounds).
  - `nonce_counter_increment(n)`: for `n < u64::MAX` the result is `n + 1`; for `n == MAX` it returns `Err` (no overflow).

This makes `pqc-migrator` the first *formally verified* mini-tool in your portfolio — a real quality leap.

### Why this is the block capstone

Senior-level engineering is not "can use X" but "can integrate X, Y, Z into a coherent, verified, documented system". This binary is the proof: crypto, key management, supply chain, formal verification, threat-model docs — all in one auditable repo.

### Pitfalls

- **Scope creep** — this capstone is large (8 subcommands). Realistic time: 6–10 hours. If you finish everything in 1 hour it was too thin. Split into "Core (keygen+encrypt+decrypt, verified)" + "Full (all subcommands)" — the DoD accepts Core as the minimum.
- **Forgetting verification specs** — specs are the value of the capstone; without them it is only Day 65 copied.
- **Inventory regex too coarse** — `grep "rsa\|ecdsa\|x25519"` finds a lot but also comments; an AST-based scan would be better but more effort. Implement both, as "basic" and "deep" mode.
- **Hardcoding Sigstore in the CLI** — in production you need a configurable identity allowlist; do not hardcode `your-email@example.com`.
- **No end-to-end tests** — a capstone without a roundtrip test is only code, not proof. Integration test: `keygen → encrypt → decrypt → verify → tamper → fail`.

## 🛠️ Practice

**Task:** Implement `pqc-migrator` as a Rust workspace with: core subcommands verified (Prusti + Kani), at least `keygen/encrypt/decrypt/scan` functional, Sigstore integration optional. Documentation: threat model (Day 59), migration plan (Day 64), SLSA-level assessment.

**Step by step:**

1. Create the workspace:

   ```bash
   cargo new --bin pqc-migrator
   cd pqc-migrator
   ```

   `Cargo.toml` (unites all Block 4 deps):

   ```toml
   [package]
   name = "pqc-migrator"
   version = "0.1.0"
   edition = "2024"

   [dependencies]
   clap = { version = "4", features = ["derive"] }
   x25519-dalek = "2"
   pqcrypto-kyber = { version = "0.8", features = ["kyber768"] }
   pqcrypto-traits = "0.3"
   hkdf = "0.12"
   sha2 = "0.10"
   aes-gcm = "0.10"
   rand = "0.8"
   zeroize = { version = "1", features = ["zeroize_derive"] }
   anyhow = "1"
   regex = "1"
   walkdir = "2"
   serde = { version = "1", features = ["derive"] }
   serde_json = "1"
   base64 = "0.22"

   [features]
   kani = ["dep:kani"]
   [dependencies.kani]
   version = "0.55"
   optional = true
   ```

2. **CLI struct** — implement `src/main.rs` yourself:

   > **Hints:**
   - Use `clap`'s `derive` API: `#[derive(Parser)]` with `#[command(name = "pqc-migrator")]`, a `cmd: Cmd` subcommand field.
   - `#[derive(Subcommand)] enum Cmd` with variants: `Inventory { dir: PathBuf }`, `Keygen { #[arg(long)] out: Option<PathBuf> }`, `Encrypt { file: PathBuf, #[arg(long)] pubkey: PathBuf }`, `Decrypt { file: PathBuf, #[arg(long)] seckey: PathBuf }`, `Scan { #[arg(long)] sbom: bool }`.
   - `sign`, `verify`, `attest` subcommands are optional (extension).

3. **Crypto module** (`src/crypto.rs`) — from Day 63 + 65 united. Frame format with magic `PQM1` + version 0x02 (block-capstone version).

4. **Inventory module** — implement `src/inventory.rs` yourself:

   > **Hints:**
   - Use `walkdir::WalkDir` to traverse the directory; filter to files with extensions `.rs`, `.ts`, `.c`, `.cpp`, `.py`.
   - Define a `Finding` struct with `file: String` and `algorithm: String` fields.
   - Build a `&[(&str, &str)]` pattern table mapping algorithm names to regexes (e.g. `("RSA", r"\bRSA[_\d]*\b")`, `("AES", r"\bAES[-_]?\d+\b")`, `("Kyber/ML-KEM", r"\b(Kyber|ML-KEM)\b")`, plus ECDSA and X25519).
   - For each file, `std::fs::read_to_string` and `Regex::is_match` against each pattern; collect matches into the result `Vec<Finding>`.

5. **Prusti specs** — add these contracts to `encrypt` in `src/crypto.rs` yourself:

   > **Hints:**
   - `#[requires(plain.len() <= 1_000_000)]` bounds the plaintext size.
   - `#[ensures(result.len() == 4 + 1 + 32 + 1088 + 12 + plain.len() + 16)]` — the frame length is deterministic: magic (4) + version (1) + ephemeral X25519 (32) + Kyber768 ciphertext (1088) + nonce (12) + plaintext + GCM tag (16).
   - The body reuses the Day 63/65 hybrid KEM + AEAD logic.

6. **Kani harness** — write a proof harness in `src/crypto.rs` yourself:

   > **Hints:**
   - Gate it with `#[cfg(kani)]` and annotate with `#[kani::proof]`.
   - Create an arbitrary byte vector with `kani::any_vec()`, pass it to `parse_frame`, and assert it does not panic (only returns `Err`). The harness name: `check_parse_frame_no_panic`.

7. **Tests** — write `tests/integration.rs` yourself:

   > **Hints:**
   - `roundtrip_encrypt_decrypt`: use `tempdir::TempDir`, run keygen → encrypt → decrypt → compare original and decrypted output.
   - `tamper_fails_decrypt`: flip one byte in the ciphertext and assert `decrypt` returns `Err` (not a panic).
   - `inventory_finds_aes_in_self`: run `scan_dir` on your own `src/` and assert at least one AES finding.
   - Each test is a `#[test]` function.
8. **Documentation** (`README.md`):
   - Architecture diagram
   - Threat model (references Day 59's `threat-model.md`)
   - Migration plan (references Day 64's `migration-plan.md`)
   - SLSA-level assessment (which level does this binary have?)
   - Verification status: which properties are formally proven?

**Definition of Done (DoD):**

- [ ] `cargo run -- keygen/encrypt/decrypt/scan` work; roundtrip test green.
- [ ] `cargo run -- inventory .` finds at least 3 crypto patterns in your own source.
- [ ] The `pqc-migrator` binary is in a Cargo workspace; modules are cleanly separated (`crypto/`, `inventory/`, `signing/`).
- [ ] **Prusti** verifies the `encrypt` frame-length spec successfully.
- [ ] **Kani** verifies the `parse_frame` no-panic spec successfully (for bounded input sizes).
- [ ] Tampered file → `decrypt` fails, no panic.
- [ ] `README.md` contains architecture, threat-model ref, migration-plan ref, SLSA level, verification status.
- [ ] `keysec.bin` in `.gitignore`, not committed.
- [ ] You can explain to an auditor in 3 sentences why this tool *provably supports* PQC migration (hybrid KEM + verification + supply chain).
- [ ] Commit: `git commit -m "day75: block4 capstone pqc-migrator (verified, supply-chain-hardened)"`.

**Note on time:** This capstone is deliberately large. If the 1-hour time is not enough (realistic), then:

- **Core (minimum for DoD acceptance)**: `keygen` + `encrypt` + `decrypt` + Prusti verification + roundtrip test.
- **Full**: all 8 subcommands + Kani + inventory + scan.
Mark in the README which level you reached.

**Extension (optional):** Extend `pqc-migrator` with `migrate-plan <repo>` — a subcommand that combines `inventory` + `scan` and generates a migration-plan draft (`migration-plan.md`) that applies the Mosca formula (Day 64) per found algorithm. That would be a real product feature.
