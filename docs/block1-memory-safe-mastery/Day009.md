# Day 9: Concurrency: Threads & Channels

**Block:** Block 1: Memory-Safe Mastery · Rust Fundamentals

> **Goal of the day:** You spawn threads with `Send` closures, communicate over `mpsc` channels, and use `Arc`/`Mutex` for shared state — *without* data races (the compiler forbids them).

---

## 📖 Theory

### `Send` and `Sync` — the auto-traits for thread safety

- **`Send`** — a type may transfer *ownership* to another thread (`T: Send`).
- **`Sync`** — `&T` may be given to another thread (`T: Sync` is equivalent to `&T: Send`).

These traits are **auto**: the compiler derives them when all fields satisfy them. For example, `Rc<T>` is not `Send` (refcount is not atomic) — `Arc<T>` is.

### `thread::spawn`

```rust
std::thread::spawn(move || {
    // closure must be 'static + Send (move is mandatory for captured data)
});
```

`'static` means: no non-`'static` references captured. `move` transfers ownership into the thread so the thread can outlive the scope.

### `mpsc` — multi-producer, single-consumer channel

```rust
use std::sync::mpsc;
use std::thread;

let (tx, rx) = mpsc::channel();
let tx2 = tx.clone();                    // second producer
thread::spawn(move || tx.send("hello").unwrap());
thread::spawn(move || tx2.send("world").unwrap());
println!("{}", rx.recv().unwrap());
println!("{}", rx.recv().unwrap());
```

Channels are **ownership-based**: `tx` is the sender, `rx` the sole receiver. When the receiver is dropped, senders fail with `SendError`.

### `Arc<Mutex<T>>` — shared mutable state

- **`Arc<T>`** — atomic reference counted. Allows multiple owners of the same value across threads.
- **`Mutex<T>`** — exclusive access, `lock()` returns a `MutexGuard` (RAII unlock).
- **`RwLock<T>`** — multiple-reader-OR-single-writer.

```rust
use std::sync::{Arc, Mutex};
let counter = Arc::new(Mutex::new(0));
let mut handles = vec![];
for _ in 0..10 {
    let c = Arc::clone(&counter);
    handles.push(thread::spawn(move || {
        *c.lock().unwrap() += 1;
    }));
}
for h in handles { h.join().unwrap(); }
println!("{}", *counter.lock().unwrap());   // 10
```

### Why this matters

Rust's killer feature: **"fearless concurrency"** — the borrow checker forbids data races *at compile time*. You can use threads freely because `Send`/`Sync` + ownership guarantee that two threads never hold unsynchronized `&mut T` to the same value at the same time.

### Pitfalls

- Sharing `Rc<T>` between threads → compile error ("Rc cannot be sent between threads"). Fix: `Arc`.
- `lock().unwrap()` panics if the other thread crashed while holding the lock (poisoned mutex). `.lock().unwrap()` is the idiomatic form; deliberate recovery via `.lock().unwrap_or_else(|e| e.into_inner())` for robust code.
- Not calling `join()` → the thread runs unsupervised in the background, crashes silently. The `JoinHandle` must be joined.
- Deadlocks with nested locks — Rust does *not* help here, that is logic.

## 🛠️ Practice

**Task:** Spawn 4 worker threads that receive tasks over an `mpsc` channel, square them, and send results back over a second channel. Measure the total time.

**Step by step:**

1. Implement the following in `src/main.rs`:

   > **Hints:**
   > - Create two `mpsc::channel::<i32>()` pairs: one for tasks (in), one for results (out).
   > - Wrap the task receiver in `Arc<Mutex<Receiver>>` so 4 worker threads can share it — each worker clones the `Arc`, locks the `Mutex`, calls `recv()`, squares the value, and sends it back on the result channel. Break the loop when `recv()` returns `Err` (channel closed).
   > - `drop(res_tx)` after spawning (so the result channel closes once all clones are gone), send `1..=100` into the task channel, then `drop(task_tx)` to signal workers to exit.
   > - Collect results with `res_rx.iter().sum::<i32>()`, join all handles, and print the sum plus elapsed time (`Instant::now()` … `start.elapsed()`).
2. `cargo run`.
3. Compare sequential vs parallel: sum the squares of `1..=100` in `main` without threads — measure the time.

**Definition of Done (DoD):**

- [ ] `cargo build` without warnings.
- [ ] 4 worker threads communicate via two channels.
- [ ] `Arc<Mutex<Receiver>>` used correctly so multiple workers share it.
- [ ] `drop(task_tx)` cleanly terminates the workers (recv error → break).
- [ ] Sum is correct: `sum_{n=1}^{100} n^2 = 338350`.
- [ ] Commit: `git commit -m "day9: threads and channels"`.

**Extension (optional):** Replace `Mutex<Receiver>` with a `crossbeam` channel (`crossbeam::channel::unbounded`), which natively supports multi-consumer — compare ergonomics and performance.
