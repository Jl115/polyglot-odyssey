## 📖 Theory

### Associated types in depth

```rust
trait Container {
    type Item;
    fn first(&self) -> Option<&Self::Item>;
}
impl Container for Vec<i32> {
    type Item = i32;                    // uniquely assigned
    fn first(&self) -> Option<&i32> { self.first() }
}
```

Unlike generic traits (`Container<T>`), a type here can only have *one* `Item` assignment — which often makes signatures clearer.

### Supertraits — trait dependencies

```rust
trait Named: Display {                 // Named requires Display
    fn name(&self) -> String;
}
fn print<N: Named>(n: N) { println!("{}", n.name()); }
```

`Named: Display` means: any type that implements `Named` must also implement `Display`. Common for "this trait builds on that one".

### `where` clauses — readable bounds

```rust
fn merge<K, V>(m1: &HashMap<K, V>, m2: &HashMap<K, V>) -> HashMap<K, V>
where K: Hash + Eq + Clone, V: Clone
{ /* ... */ }
```

When bounds get unwieldy (multiple types, long lists), `where` is more compact than `fn foo<T: A + B + C + D>`.

### Derive macros — `#[derive(...)]`

`#[derive(Debug, Clone, PartialEq)]` calls a **procedural macro** per trait that generates the code. The macro receives the struct's AST and emits the trait impl.

Standard derivable traits: `Debug`, `Clone`, `Copy`, `PartialEq`, `Eq`, `Hash`, `Default`, `PartialOrd`, `Ord`.

### Writing your own derive macro

A derive macro is a separate crate of type `proc-macro = true`:

```rust
// In a `day7_macro` crate with [lib] proc-macro = true
use proc_macro::TokenStream;
use quote::quote;
use syn::{parse_macro_input, DeriveInput};

#[proc_macro_derive(Announce)]
pub fn derive_announce(input: TokenStream) -> TokenStream {
    let ast = parse_macro_input!(input as DeriveInput);
    let name = &ast.ident;
    let expanded = quote! {
        impl #name {
            pub fn announce(&self) -> String {
                format!("I am a {}", stringify!(#name))
            }
        }
    };
    expanded.into()
}
```

In the main crate: `use day7_macro::Announce;` and `#[derive(Announce)] struct Foo;`.

### Why this matters

Derive macros are the reason Rust code is so short: instead of 50 lines of boilerplate for `Debug + Clone + PartialEq`, you write one attribute. In Block 4 you will build custom derive macros for crypto keys (e.g. `#[derive(ZeroizeOnDrop)]`). Today you learn how that works.

### Pitfalls

- `#[derive]` for `Copy` only works if *all* fields are `Copy` — otherwise a compile error.
- Procedural macros must live in a *separate* crate (proc-macro crates cannot sit alongside normal code in the same crate).
- `quote!` is hygienic — identifiers from the input (e.g. `name`) are mapped correctly; fresh identifiers do not collide with user code.

## 🛠️ Practice

**Task:** Build a derive macro `#[derive(Announce)]` that generates a method `announce(&self) -> String` for any struct, printing the type name. Use it on two structs in the main crate.

**Step by step:**

1. Workspace layout:

   ```
   day7/
     Cargo.toml          (workspace)
     day7_macro/
       Cargo.toml        [lib] proc-macro = true
       src/lib.rs
     src/main.rs
   ```

2. `day7/Cargo.toml`:

   ```toml
   [workspace]
   members = ["day7_macro"]

   [package]
   name = "day7"
   version = "0.1.0"
   edition = "2024"

   [dependencies]
   day7_macro = { path = "day7_macro" }
   ```

3. `day7_macro/Cargo.toml`:

   ```toml
   [lib]
   proc-macro = true

   [dependencies]
   syn = { version = "2", features = ["derive"] }
   quote = "1"
   proc-macro2 = "1"
   ```

4. `day7_macro/src/lib.rs`: see above.
5. Implement the following in `day7/src/main.rs`:

   > **Hints:**
   > - Import the derive macro with `use day7_macro::Announce;`.
   > - Define two unit structs (e.g. `Cat` and `Dog`) annotated with `#[derive(Announce)]`.
   > - In `main`, call `.announce()` on instances of each struct and print the result — the macro-generated method returns a `String` like `"I am a Cat"`.
6. `cargo run`.

**Definition of Done (DoD):**

- [ ] `cargo build` without warnings in the workspace.
- [ ] `Announce` macro in its own proc-macro crate.
- [ ] `Cat.announce()` and `Dog.announce()` return the correct strings.
- [ ] You can explain why proc-macros must live in a separate crate (isolation / hygiene).
- [ ] Commit: `git commit -m "day7: advanced traits and derive macro"`.

**Extension (optional):** Extend the macro so it only accepts structs with a `name: String` field and `announce` returns that field (via `syn::Data::Struct` pattern matching).
