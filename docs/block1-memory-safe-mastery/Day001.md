# Day 1: Ownership & Borrowing — The Foundation

**Block:** Block 1: Memory-Safe Mastery · Rust Fundamentals

> **Goal of the day:** You can explain why a Rust program compiles or is rejected the moment ownership rules are violated — and you write functions that hand data around without `clone()`.

---

## 📖 Theory

Rust's central innovation is the **ownership model**: the compiler enforces memory safety _at compile time_, with no garbage collector. Three rules form the foundation:

1. **Every value has exactly one owner.**
2. **When the owner goes out of scope, the value is dropped** (deterministic destructor → no leak, no double-free).
3. **Either one mutable reference `&mut T` OR any number of immutable references `&T` apply — never both at the same time.**

### Stack vs. Heap

- **Stack:** fixed, compact values (`i32`, `bool`, fixed-size arrays). Copy semantics — the value is duplicated bit-for-bit.
- **Heap:** dynamic values (`String`, `Vec`, `Box`). Move semantics — ownership is _transferred_, not copied.

```rust
let s1 = String::from("hi");   // heap allocation, s1 is the owner
let s2 = s1;                    // MOVE: s1 is now invalid
// println!("{}", s1);          // ❌ compile error: value borrowed after move
```

### Move vs. Borrow

A **move** (`let s2 = s1`) transfers ownership — the old owner is dead. A **borrow** (`let r = &s1`) only borrows read access; the owner stays alive.

```rust
fn len(s: &String) -> usize {  // borrow: no ownership taken
    s.len()
}
let s = String::from("hi");
let l = len(&s);               // s keeps living
println!("{s}, length {l}");    // ✅ OK
```

### Mutable borrowing — the "one writer OR many readers" rule

```rust
let mut v = vec![1, 2, 3];
let r1 = &mut v;               // exclusive write access
// let r2 = &mut v;            // ❌ second mutable borrow
// let r3 = &v;                // ❌ even an immutable borrow is blocked
r1.push(4);                   // r1's last use ends here (NLL)
println!("{v:?}");             // ✅ free again from here on
```

Rust uses **Non-Lexical Lifetimes (NLL)**: a reference "lives" only until its _last use_, not until the end of the scope. That is why the code above compiles.

### Why this matters

Without ownership you would need a GC (overhead, pauses) or manual `free()` calls (use-after-free, double-free, leaks — the top-3 CVE classes in C/C++). Rust makes this entire bug category _impossible to compile_. This is the base for the whole block: everything later (lifetimes, concurrency, FFI) builds on these three rules.

### Pitfalls

- `String::from(&s)` where `s: &String` is **not a borrow** — it allocates and copies (i.e. a hidden `clone`). If you are practicing "without clone", accept `&str` instead of `&String`.
- `return value;` at the end of a function is unidiomatic — Rust uses the last expression without `return` and without a semicolon.
- `Copy` types (`i32`, `&T`) are _not_ moved — they are copied bit-for-bit, the old name stays valid.

## 🛠️ Practice

**Task:** Write a function that receives a string by reference, _builds_ a new (extended) string from it, and returns it — **without `clone()` and without `String::from(&String)`**.

**Step by step:**

1. Create a new project: `cargo new day1 --bin` (already present).
2. Implement the following in `src/main.rs`:

   > **Hints:**
   >
   > - Write `fn append_suffix(input: &str) -> String` — accept `&str` (not `&String`) to avoid a hidden clone.
   > - Pre-allocate with `String::with_capacity(input.len() + N)` where `N` is the suffix length, then `push_str` the input and the suffix (`"world!"`).
   > - The return value is the **last expression** — no `return` keyword, no trailing semicolon.
   > - In `main`, call `append_suffix(&greeting)` and prove `greeting` is still usable afterwards (print it again) — that demonstrates a borrow, not a move.

3. Build and run: `cargo run`.
4. Deliberately provoke a compile error to _feel_ the rules: add a second `out.push_str(input);` after `let r = &out;` — observe the "cannot borrow mutably" message.
5. Compare with the old version (`String::from(&String)`): you don't need `cargo expand`, but look up in the Rust Book Ch. 4.2 _why_ `&String` → `String` is a copy.

**Definition of Done (DoD):**

- [ ] `cargo build` compiles without warnings (`cargo build 2>&1 | grep warning` is empty).
- [ ] `append_suffix` accepts `&str` (not `&String`).
- [ ] The original string is still usable after the function call (no move).
- [ ] No `clone()` and no `String::from(&…)` in the code.
- [ ] You can explain to a friend in 2 sentences why `let s2 = s1` moves for `String` but not for `i32`.
- [ ] Commit: `git commit -m "day1: ownership & borrowing without clone"`.

**Extension (optional):** Make `append_suffix` generic over anything that is `AsRef<str>` — then `&str`, `String`, `&&str` etc. work as input.

> **Hints:**
>
> - Change the signature to `fn append_suffix<S: AsRef<str>>(input: S) -> String`.
> - Call `input.as_ref()` once at the top to obtain a `&str`, then proceed exactly as in the non-generic version.
> - No other logic needs to change — `AsRef<str>` is the bridge that lets any string-like type produce a `&str`.
