## 📖 Theory

### The standard collections

- **`Vec<T>`** — growing array buffer on the heap. O(1) push/pop at the end, amortized.
- **`HashMap<K, V>`** — hash table (SipHash-1-3, DoS-resistant). O(1) lookup on average.
- **`BTreeMap<K, V>`** — sorted map as a B-tree. O(log n), iterates in key order.
- **`HashSet`/`BTreeSet`** — thin wrappers around the maps.

```rust
use std::collections::HashMap;
let mut counts: HashMap<&str, u32> = HashMap::new();
for word in "a b a c b a".split_whitespace() {
    *counts.entry(word).or_insert(0) += 1;
}
```

`entry()` is the idiomatic pattern: lookup-or-insert in a single call, without double hashing.

### Iterators are lazy and zero-cost

An iterator only computes values when they are consumed. Adapter chains create **no** intermediate `Vec`s — the compiler fuses everything into a single loop (often even faster than a hand-written `for`).

```rust
let sum: i32 = (1..=100)
    .filter(|x| x % 2 == 0)   // lazy
    .map(|x| x * x)            // lazy
    .sum();                    // consumes
```

### The three iterator traits

- `Iterator::next(&mut self) -> Option<T>` — the heart, you only implement this one.
- `IntoIterator` — everything that works in `for x in coll` has it. `Vec` consumes (owned), `&Vec` borrows (`&T`), `&mut Vec` borrows mutably (`&mut T`).
- `FromIterator` / `.collect()` — builds a collection from an iterator.

```rust
let v: Vec<i32> = [1,2,3].into_iter().collect();
let s: String  = ['h','i'].into_iter().collect();
```

### Custom iterator

```rust
struct Counter { current: u32, max: u32 }

impl Iterator for Counter {
    type Item = u32;
    fn next(&mut self) -> Option<u32> {
        if self.current >= self.max { None }
        else { self.current += 1; Some(self.current) }
    }
}
// all adapters (map, filter, take, ...) are available for free:
let pairs: Vec<(u32, u32)> = Counter { current: 0, max: 3 }
    .zip(Counter { current: 0, max: 3 })
    .collect();
```

### Why this matters

Iterators are Rust's functional processing layer — they replace `for` loops where more readable, with no performance loss. Zero-cost abstraction is the property that sets Rust apart from Python/JS iteration.

### Pitfalls

- Iterator invalidation as in C++ (`erase` during iteration) is impossible in Rust — the borrow checker forbids simultaneous `&mut`.
- `.collect()` often needs a type hint (`collect::<Vec<_>>()`) — otherwise type inference breaks.
- `for x in &vec` (immutable borrow) vs. `for x in vec` (consumes ownership) — choose deliberately.
- `HashMap` does **not** iterate in a fixed order (the hash salt is randomized per process). Use `BTreeMap` for stable iteration order.

**Task:** Write your own `Fibonacci` iterator that yields Fibonacci numbers infinitely, and an adapter that extracts the first 10 even Fibonacci numbers as a `Vec<u64>`.

**Step by step:**

1. Implement the following in `src/main.rs`:

   > **Hints:**
   > - Define `struct Fib { a: u64, b: u64 }` with a `new()` constructor that seeds `a = 0, b = 1`.
   > - Implement `Iterator` for `Fib` with `type Item = u64`: in `next`, save the current value (`self.a`), advance using `checked_add` (returns `None` on overflow, which naturally ends iteration), swap `a`/`b`, and return `Some(cur)`.
   > - In `main`, chain `Fib::new().filter(|x| x % 2 == 0).take(10).collect::<Vec<u64>>()` to get the first 10 even Fibonacci numbers.
   > - Also build a word-count demo: use `HashMap<&str, u32>` with the `entry(...).or_insert(0)` pattern over a split string, then find the most frequent word with `into_iter().max_by_key(...)`.
2. `cargo run`.
3. Build a function `fn top_n(words: &str, n: usize) -> Vec<(String, u32)>` that returns the `n` most frequent words — use `HashMap`, `into_iter`, `sort_by`/a `BTreeMap` detour, or a `max_by_key` loop.
