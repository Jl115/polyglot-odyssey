## 📖 Theory

This day is not new material, but a **self-assessment**. Memory-safe mastery is not "run through once", but "able to do it without looking it up". Today you check whether that holds for the core topics.

### The model: "Explain, Build, Debug"

For each concept you check three levels:
1. **Explain** — can you explain it to a friend in 2 sentences?
2. **Build** — can you write a minimal example in 10 min without copy-paste?
3. **Debug** — can you read and fix a typical compile error?

Only when all three are "yes" have you mastered the concept.

### Why this matters

One of the most common learning mistakes: "I read it once" does not replace fluent ability. Block 2 (C/C++/Zig) builds on ownership + traits + lifetimes; Block 4 (crypto) on error handling + generics. Whoever leaves gaps here pays in Block 2+ with increased friction.

### Pitfalls in self-assessment

- Familiarity illusion: "sounds familiar" ≠ "can actively use it". Writing code without a template is the test.
- Tutorial helmet: examples you typed out you can reproduce — but not necessarily vary. Invent your own mini-tasks.
- Skipping the debug level: writing code is easier than reading someone else's code + finding a bug. Train both.

### Mini-task as a final test (10 min.)

Without a template, write a 50-line Rust program that:
- Takes a CLI (`clap`) with `--input <file>`.
- Reads the file (error via a `thiserror` enum).
- Counts words (`HashMap`).
- Prints the top 5 as a sorted list.
- On error: `eprintln!` + `exit(1)`.

If that compiles without errors → the Block 1 core is solid.
