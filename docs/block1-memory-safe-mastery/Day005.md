## 📖 Theory

### Three error strategies in Rust

1. **`panic!`** — for *invariant* violations ("this should never happen"). Stack unwind (or abort). Avoid in libraries.
2. **`Result<T, E>`** — for *expected* errors (file missing, parse error). Normal values, propagatable with `?`.
3. **Abort with `Process::exit`** — only at the binary top level (`main`), never in libraries.

### `?` — propagation without boilerplate

```rust
fn read_config(path: &Path) -> Result<Config, io::Error> {
    let s = fs::read_to_string(path)?;   // io::Error propagates
    Ok(toml::from_str(&s)?)              // toml::Error too, via `From`
}
```

`?` implicitly calls `From::from` to convert the concrete error into the return type — that is why a single `AppError` that implements `From<io::Error>` etc. is enough.

### Typing errors with `thiserror`

```rust
use thiserror::Error;

#[derive(Debug, Error)]
enum AppError {
    #[error("io: {0}")]          Io(#[from] io::Error),
    #[error("parse: {0}")]       Parse(#[from] toml::de::Error),
    #[error("missing field {0}")] Missing(String),
}
```

`#[from]` generates `From<io::Error> for AppError` automatically — then `?` propagates without manual maps.

### CLI with `clap` (derive)

```rust
use clap::Parser;

#[derive(Parser, Debug)]
#[command(version, about = "Word frequency counter")]
struct Cli {
    /// Input file (defaults to stdin)
    #[arg(default_value = "-")]
    input: String,
    /// Show top N
    #[arg(short, long, default_value_t = 10)]
    top: usize,
}
```

Clap generates `--help`, `--version`, errors on wrong flags, and returns typed fields.

### Why this matters

Consistent error handling is the difference between "crashes with a stacktrace" and "works as a CLI tool the way users expect". In Block 4+ (Security) you will call cryptographic APIs that all return `Result` — this foundation is mandatory.

### Pitfalls

- `main` can return `Result<(), E>` where `E: Debug`. That gives Debug output on `Err` instead of a panic — practical, but ugly for end users. Better: `fn main()` with explicit `eprintln!` + `process::exit(1)`.
- `Box<dyn Error>` is a quick shortcut, but loses type information — only for prototypes.
- `?` in a `main()` return only works if the error type implements `Debug` (otherwise a compile error).

## 🛠️ Practice

**Task:** Build a CLI tool `freq` that reads a file (or stdin), counts words, and prints the top N — with `clap` + `thiserror` + `?` propagation.

**Step by step:**

1. `cargo new day5 --bin`, then in `Cargo.toml`:

   ```toml
   [dependencies]
   clap = { version = "4", features = ["derive"] }
   thiserror = "2"
   ```

2. Implement the following in `src/main.rs`:

   > **Hints:**
   > - Define an `AppError` enum with `#[derive(Error, Debug)]` and at least two variants: `Io(#[from] io::Error)` (the `#[from]` auto-generates the `From` impl so `?` propagates) and a second variant like `BadPath(String)`.
   > - Define a `Cli` struct with `#[derive(Parser, Debug)]` and a `#[command(...)]` attribute: an `input: String` field (default `"-"` for stdin) and a `top: usize` field (short/long flags, default `10`).
   > - Write `fn read_input(src: &str) -> Result<String, AppError>`: if `src == "-"`, read stdin via `io::stdin().read_to_string(...)`; otherwise `fs::read_to_string(src)`. Use `?` to propagate `io::Error` into `AppError`.
   > - Write `fn run() -> Result<(), AppError>`: parse `Cli`, read input, count words with a `HashMap` (`entry().or_insert(0)`), sort entries by count descending, and print the top `N` as `count  word`.
   > - Write `fn main()` that calls `run()` and on `Err` prints `eprintln!("error: {e}")` then `exit(1)`.
3. `cargo run -- --help` — should show usage.
4. `echo "a b a c a b" | cargo run -- -i - --top 2`.
5. Provoke errors: `cargo run -- -i /nonexistent`, observe the `BadPath`/`Io` output.

**Definition of Done (DoD):**

- [ ] `cargo run -- --help` shows generated help.
- [ ] `AppError` with `#[from]` for `io::Error`, at least 2 variants.
- [ ] `?` propagates errors from `read_to_string` automatically.
- [ ] A wrong path ends with `error: io: ...` and exit code 1 (checkable with `echo $?`).
- [ ] Stdin mode (`-`) works with `echo ... |`.
- [ ] Commit: `git commit -m "day5: error handling and cli with clap"`.

**Extension (optional):** Add `anyhow` as an alternative (`anyhow::Result` as return type) and compare ergonomically — when to use `thiserror`, when `anyhow`.
