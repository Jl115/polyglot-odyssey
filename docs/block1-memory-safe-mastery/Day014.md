---

## 📖 Theory

### Module systems in TS

- **CommonJS (CJS):** `require()` / `module.exports`. Synchronous, for Node.
- **ES Modules (ESM):** `import`/`export`. Standard, statically analyzable, Browser+Node+Deno.

In `tsconfig.json` use `"module": "NodeNext"` or `"ESNext"` + `"moduleResolution": "Bundler"`/`"NodeNext"`. Since Node 12+ ESM works natively; `.mts`/`.cts` for unambiguous file modes.

```ts
// ESM
export function add(a: number, b: number) { return a + b; }
import { add } from "./math.js";   // .js even in TS source
```

### Declaration merging — same-name declarations add up

TS allows multiple `interface` declarations with the same name — they merge:

```ts
interface Window { myProp: string }   // extends the lib.dom.d.ts Window
interface Window { other: number }
// Window now has both fields
```

The same applies to `namespace` and to `function` + `namespace` (for static properties on functions).

### Ambient declarations — types for untyped JS code

```ts
// legacy.d.ts
declare module "legacy-lib" {
  export function doThing(x: number): string;
  export const version: string;
}
```

`.d.ts` files contain *only types* (no runtime code). The compiler uses them to make untyped JS APIs type-safe.

### `declare global` — global extensions

```ts
// polyfill.d.ts
declare global {
  interface String {
    reverse(): string;
  }
}
// String.prototype.reverse must exist at runtime
```

### Triple-slash directives (legacy)

```ts
/// <reference types="node" />
/// <reference path="./other.d.ts" />
```

In modern projects handled via `tsconfig.json` `types`/`include`; triple-slash only for legacy configuration.

### `import type` — type-only imports

```ts
import type { Result } from "./types";   // removed during transpilation
import { isOk } from "./types";           // stays as a runtime import
```

Important for ESM + isolated modules (e.g. `esbuild`, `swc`, `vite`), because these compilers transpile each file in isolation and cannot see whether a name is a type or a value.

### Why this matters

In Block 3 (AI-Native) you will work with many JS libraries, some of them untyped. `.d.ts` authoring is the bridge; module configuration determines whether things run in Node, Bun, Browser, Deno. Wrong module settings are the most common build errors.

### Pitfalls

- CJS/ESM interop: `import x = require("y")` is TS-specific; `import x from "y"` with `esModuleInterop` default-wraps. Missing `esModuleInterop`, `import fs from "fs"` breaks.
- `declare module "*.svg"` — wildcard module declarations for asset imports in bundlers.
- Declaration merging does *not* work for `type` aliases (only `interface`/`namespace`).
- Ambient types can go stale — if the JS API changes, the TS code compiles but fails at runtime.

## 🛠️ Practice

**Task:** Write a `.d.ts` for a fictional untyped JS library `legacyMath`, extend `Array<T>` with `shuffle()` via declaration merging, and use it all from typed TS code.

**Step by step:**

1. Setup like Day 12.
2. Write `src/legacy.d.ts` (ambient declarations only — no runtime code):

   > **Hints:**
   > - Use `declare module "legacyMath"` to give types for an untyped JS library: export `fib(n: number): number` and `const version: string`.
   > - Extend `Array<T>` via declaration merging: add an `interface Array<T> { shuffle(): T[]; }` declaration so `.shuffle()` becomes typed across the project.
3. Write `src/runtime.js` (the actual JS implementation the `.d.ts` describes):

   > **Hints:**
   > - Export `fib(n)` via `module.exports.fib` — an iterative Fibonacci loop swapping two variables (`a`, `b`).
   > - Export `version = "0.0.1"`.
   > - Install `Array.prototype.shuffle` with a Fisher–Yates loop from the end down to index 1, swapping each element with a random earlier index (`Math.floor(Math.random() * (i + 1))`). Return `this`.
4. Write `src/index.ts` (typed consumer of the above):

   > **Hints:**
   > - `import { fib, version } from "legacyMath"` — the import is typed by your `.d.ts`.
   > - `require("./runtime")` to load the side effects that install `Array.prototype.shuffle`.
   > - Build a `number[]`, call `.shuffle()` (now typed via declaration merging), and `console.log(version, fib(10), shuffled)`. You should not need any `any`.
5. `npx tsc --noEmit && node --loader ts-node/esm src/index.ts` (or via `esbuild-register`).

**Definition of Done (DoD):**

- [ ] `npx tsc --noEmit` without errors.
- [ ] `legacyMath` is typed via `.d.ts` (no `any` in the public API).
- [ ] `Array<T>.shuffle()` is typed and callable from TS code.
- [ ] `import type` applied correctly where only types are needed.
- [ ] Commit: `git commit -m "day14: declaration merging and modules"`.

**Extension (optional):** Write an ambient module declaration for `*.png` imports (for Vite/Webpack) and a `declare global` for `process.env.MY_VAR`.
