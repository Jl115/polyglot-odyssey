## 📖 Theory

### Narrowing — how TS refines types

TypeScript "narrows" a broad type (`string | number`) within a block, based on checks the compiler understands:

```ts
function f(x: string | number) {
  if (typeof x === "string") {
    x.toUpperCase();           // here x: string
  } else {
    x.toFixed(2);              // here x: number
  }
}
```

Mechanisms: `typeof`, `instanceof`, `in` (property check), truthiness (`if (x)`), equality (`=== null`), discriminated unions (`x.kind === "a"`).

### User-defined type guards

A function with return type `x is T` becomes a type-check function:

```ts
interface Cat { meow(): void }
interface Dog { bark(): void }

function isCat(a: Cat | Dog): a is Cat {
  return typeof (a as any).meow === "function";
}

const pet: Cat | Dog = /* ... */;
if (isCat(pet)) pet.meow(); else pet.bark();
```

### Discriminated unions — the TS counterpart to Rust's enums

```ts
type Shape =
  | { kind: "circle";   radius: number }
  | { kind: "square";   side:   number }
  | { kind: "rect";     w: number; h: number };

function area(s: Shape): number {
  switch (s.kind) {                 // narrowing via literal discriminator
    case "circle": return Math.PI * s.radius ** 2;
    case "square": return s.side ** 2;
    case "rect":   return s.w * s.h;
  }
}
```

The `kind` field is the *discriminator*. TS narrows to the correct variant in each `case`. `switch (true)` patterns with an exhaustiveness check via `never`:

```ts
function assertNever(x: never): never { throw new Error(`unhandled: ${JSON.stringify(x)}`); }
function area(s: Shape): number {
  switch (s.kind) {
    case "circle": return Math.PI * s.radius ** 2;
    case "square": return s.side ** 2;
    case "rect":   return s.w * s.h;
    default: return assertNever(s);   // compile error if a variant is missing
  }
}
```

### `satisfies` operator (TS 4.9+)

```ts
const config = { port: 8080 } satisfies Record<string, number>;
```

`satisfies` checks conformance without widening the type — you keep the narrowest literal types, but get the compile-time check.

### Why this matters

Type guards are the TS equivalent of Rust's `match`. They make API responses, JSON payloads, and union-based domains type-safe. In Block 3 (AI) you will model LLM responses via discriminated unions (Success | Error | ToolCall).

### Pitfalls

- `typeof` only knows `"string" | "number" | "boolean" | "symbol" | "bigint" | "undefined" | "object" | "function"`. Arrays are `object` — use `Array.isArray()` instead of `typeof`.
- Type guards with `any` are unsafe — `x is T` does NOT lie, the compiler trusts you. Always actually check.
- TS narrowing is *not* flow-sensitive across mutations. If you reassign `x` inside a closure, narrowing can be lost ("assigned within closure").
- `as` is an assertion, not a guard — it forces the type without a check.

## 🛠️ Practice

**Task:** Define a `Result<T, E>` discriminated union with `kind: "ok" | "err"`, a type guard `isOk`, and a `safeParse<T>(schema, input)` function that type-safely parses JSON.

**Step by step:**

1. Initialize the project:

   ```bash
   mkdir day12 && cd day12 && npm init -y && npm i -D typescript@5 @types/node && npx tsc --init
   ```

2. Implement the following in `src/index.ts`:

   > **Hints:**
   > - Define `Result<T, E>` as a discriminated union with `kind: "ok" | "err"` and a `value` / `error` payload field.
   > - Write `isOk<T, E>(r)` with the user-defined type-guard return type `r is { kind: "ok"; value: T }` — the body just checks `r.kind === "ok"`.
   > - Write `assertNever(x: never): never` that throws on any unhandled variant, so a `switch` missing a case becomes a compile error.
   > - Write `safeParse(input: unknown): Result<Schema, string>` for a `Schema = { port: number; host: string }`. Narrow with `typeof` and null checks before trusting each field — only construct the `{ kind: "ok" }` value after every field is validated, so no `as` cast escapes without a guard.
   > - In a `require.main === module` block, call `safeParse(JSON.parse(...))`, branch on `isOk`, and print the result or error.
3. `npx tsc --noEmit && node dist/index.js` (or `ts-node`).
4. Provoke exhaustiveness: add `{ kind: "pending" }` to the `Result` union without updating all switches — `assertNever` catches it.

**Definition of Done (DoD):**

- [ ] `isOk` is an `x is T` type guard.
