# Day 2: Lifetimes & Structs

**Block:** Block 1: Memory-Safe Mastery · Rust Fundamentals

> **Goal of the day:** You define your own structs with correct lifetime parameters, understand the elision rules, and can explain why the compiler sometimes demands explicit lifetimes.

---

## 📖 Theory

### Structs — user-defined data types

A `struct` bundles named fields. Three variants: named (C-struct), tuple-struct, unit-struct.

```rust
struct User {              // named
    name: String,
    age: u32,
}
struct Point(i32, i32);    // tuple-struct
struct Marker;             // unit-struct (zero-sized, often used as a type-level marker)
```

### Lifetimes — the question "how long does this reference live?"

A **lifetime** is a compile-time label for the scope in which a reference is valid. It prevents **dangling references**: no reference may outlive the data it points to.

```rust
// 'a tells the compiler: the returned &str lives at least as long as `s`
fn first_word<'a>(s: &'a str) -> &'a str {
    let bytes = s.as_bytes();
    for (i, &b) in bytes.iter().enumerate() {
        if b == b' ' { return &s[..i]; }
    }
    s
}
```

### Lifetime elision — when you don't have to write lifetimes

The compiler inserts lifetimes automatically following three rules ("elision"):

1. Every `&` parameter gets its own lifetime.
2. If there is exactly _one_ input lifetime parameter, all outputs get that lifetime.
3. For methods (`&self`/`&mut self`), outputs get the lifetime of `self`.

That is why `fn len(s: &str) -> usize` compiles without `'a` — the output is `usize` (owned, no `&`). But as soon as you return a `&` and have _multiple_ input lifetimes, you must annotate.

### Structs with references — the classic stumbling block

A struct that holds references MUST carry a lifetime — otherwise the compiler doesn't know how long the struct is allowed to live.

```rust
struct Excerpt<'a> {
    part: &'a str,   // part must not outlive its source
}

impl<'a> Excerpt<'a> {
    fn longest(&self, other: &'a str) -> &'a str {
        if self.part.len() > other.len() { self.part } else { other }
    }
}

let novel = String::from("Call me Ishmael. Some years ago...");
let ex = Excerpt { part: &novel[..16] };   // ex must not outlive novel
// drop(novel); // ❌ novel borrowed by ex
```

### `'static` — the lifetime of the entire program

`'static` means: the reference lives for the entire program runtime. String literals (`"hi"`) are `&'static str` — they live in the binary image. Do **not** abuse it as a "fix for lifetime problems" — `'static` is a strong promise.

### Why this matters

Lifetimes are the formal language in which Rust expresses borrowing. Without them, references in structs and signatures would be ambiguous. They are also the prerequisite for `Cow`, iterators, and anything that returns references.

### Pitfalls

- **Too many lifetimes** often signal that you should use _owned_ data (`String` instead of `&str`) instead.
- `'static` bounds in trait bounds (`T: 'static`) do not mean "lives forever", but "contains no non-`'static` references" — `String` satisfies this, `&'a str` does not.
- Lifetimes are **only** compile-time annotations — they cost _no_ runtime.

## 🛠️ Practice

**Task:** Build an `Excerpt<'a>` struct that holds an `&'a str`, plus a method `longest` that compares its own field with an external `&'a str` and returns the longer reference.

**Step by step:**

1. `cargo new day2 --bin` (or use the existing project).
2. Implement the following in `src/main.rs`:

   > **Hints:**
   > - Define `struct Excerpt<'a>` with a single field `part: &'a str` — the lifetime ties the struct to its source string.
   > - In `impl<'a> Excerpt<'a>`, write `fn longest(&self, other: &'a str) -> &'a str` that returns `self.part` or `other` (whichever is longer). Both inputs share `'a` so the returned reference is valid for that whole lifetime.
   > - Add `fn announce(&self, prefix: &str) -> String` returning `format!("{prefix}: {self.part}")` — this relies on **lifetime elision** (owned return, no explicit `'a` needed).
   > - In `main`, create a `String` (`novel`), slice out a fragment, build an `Excerpt`, then call `longest` and `announce` and print the results.

3. Build with `cargo build`.
4. Provoke an error: create `ex`, then `let dangling = ex.part;`, drop the source `novel` _before_ using `dangling` — observe the lifetime error message.
5. Replace `longest` with a version without `'a` annotation (`fn longest(&self, other: &str) -> &str`) — observe that the compiler asks you for explicit lifetimes.

**Definition of Done (DoD):**

- [ ] `cargo build` without warnings.
- [ ] The `Excerpt` struct carries an `'a` parameter and `part: &'a str`.
- [ ] `longest` returns `&'a str` and uses both inputs.
- [ ] `announce` uses elision (no explicit `'a` in the return).
- [ ] You can prove with a test that `novel` must not be dropped while `ex` is alive (e.g. deliberately produce a compile error and explain it).
- [ ] Commit: `git commit -m "day2: lifetimes and structs"`.

**Extension (optional):** Implement `Iterator` for a `Words<'a>` that iterates over an `&'a str` and yields each word as an `&'a str`. Here `'a` is essential because every yield is a reference into the source.
