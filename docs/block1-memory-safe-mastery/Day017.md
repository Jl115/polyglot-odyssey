## 📖 Theory

### Tauri architecture

Tauri is a desktop app framework:

- **Frontend** = web view (WebView2/WebKit/GTK, depending on platform) — HTML/CSS/JS via any framework (React, Svelte, Vue, vanilla).
- **Backend** = native Rust process.
- **IPC** = `invoke` from the frontend → Rust commands; `emit`/`listen` for Rust → frontend events.

The Rust process starts the webview server and registers commands. No Node runtime, no Electron-Chromium bloat — Tauri apps are typically 5–20MB instead of 100MB+.

### `#[tauri::command]` — a Rust function for the frontend

```rust
#[tauri::command]
fn greet(name: &str) -> String {
    format!("Hello, {name}!")
}

fn main() {
    tauri::Builder::default()
        .invoke_handler(tauri::generate_handler![greet])
        .run(tauri::generate_context!())
        .expect("error while running tauri application");
}
```

Frontend (TS):

```ts
import { invoke } from "@tauri-apps/api/core";
const msg = await invoke<string>("greet", { name: "World" });
```

### Serialization

Arguments and returns are serialized via `serde` (JSON-like). Rust types must derive `Serialize`+`Deserialize`. Errors via `Result<T, E>` where `E: Serialize` — an `Err` becomes a promise rejection in the frontend.

### Events (Rust → frontend)

```rust
window.emit("progress", 42)?;
```

```ts
import { listen } from "@tauri-apps/api/event";
await listen<number>("progress", e => console.log(e.payload));
```

### Security

Tauri uses a capability system (`tauri.conf.json`): the frontend only gets rights that are explicitly granted (file system, shell, HTTP). Default = *nothing*. That is a significant security win over Electron.

### Why this matters

Tauri is the path to "Fullstack Memory-Safe App deployed" (the Block 1 outcome): a Rust backend (safe, fast) + a web frontend (familiar UI). It combines everything from Day 1–16.

### Pitfalls

- The web view is *not* Chrome — some modern CSS/JS features are missing on older Windows (WebView2 is based on Edge/Chromium, macOS WebKit on Safari). Check compatibility.
- Commands are referenced as a string in the frontend — refactor tools do not help here. Tip: `specta`+`tauri-specta` generate TS types from Rust commands.
- `invoke` is async — always `await`.
- In dev mode the web view process is relatively open by default; for production set capabilities strictly.

## 🛠️ Practice

**Task:** Build a Tauri app with a vanilla TS frontend that calls a Rust function `word_count(text: String) -> usize` and displays the result.

**Step by step:**

1. Setup (Tauri CLI):

   ```bash
   cargo install tauri-cli --version "^2.0"
   npm create tauri-app@latest -- day17 --template vanilla-ts
   cd day17
   ```

2. Implement the Rust command in `src-tauri/src/lib.rs`:

   > **Hints:**
   > - Annotate `word_count(text: String) -> usize` with `#[tauri::command]`; count via `text.split_whitespace().count()`.
   > - In `pub fn run()` (the entry point), build a `tauri::Builder::default()` and register the command with `.invoke_handler(tauri::generate_handler![word_count])`, then `.run(tauri::generate_context!())`.
   > - Keep the `#[cfg_attr(mobile, tauri::mobile_entry_point)]` attribute on `run` so it works on mobile too.
3. Implement the frontend in `src/main.ts`:

   > **Hints:**
   > - `import { invoke } from "@tauri-apps/api/core"`.
   > - Grab the three DOM elements by id (`#text`, `#count`, `#out`) using `document.querySelector<HTML...Element>(...)!`.
   > - On the button click, `await invoke<number>("word_count", { text: input.value })` and write `Words: ${n}` into the output element. Remember `invoke` is async — always `await` it.
4. Add to HTML (`index.html`): `<textarea id="text"></textarea><button id="count">Count</button><p id="out"></p>`.
5. Run: `npm install && npm run tauri dev`.
6. Type text, click "Count", see the result.

**Definition of Done (DoD):**

- [ ] `npm run tauri dev` starts a window without errors.
- [ ] Text in the textarea → click → word count appears.
- [ ] Rust command registered via `generate_handler![word_count]`.
- [ ] Frontend uses `invoke<number>(...)` typed.
- [ ] You can explain why Tauri apps are smaller than Electron apps (no bundled Chromium).
- [ ] Commit: `git commit -m "day17: tauri desktop app with rust backend"`.

**Extension (optional):** Add a Rust event `progress` that is emitted during a long task, and show a progress bar in the frontend. Use `window.emit` + `listen`.
