## 📖 Theory

### The `typescript` compiler API

The `typescript` npm package is not just the compiler — it is a programmatic API you can use to analyze and generate source code. Core objects:

- **`SourceFile`** — AST root for a file.
- **`Node`** — every AST node. Has `kind: SyntaxKind`, `parent`, `getChildren()`.
- **`Checker`/`TypeChecker`** — resolves types (like `Type<T>` from an identifier).
- **`TransformationContext`** — for custom transformers.

```ts
import * as ts from "typescript";

const src = `export function add(a: number, b: number) { return a + b; }`;
const sf = ts.createSourceFile("mod.ts", src, ts.ScriptTarget.Latest, true);
sf.forEachChild(node => {
  if (ts.isFunctionDeclaration(node) && node.modifiers?.some(m => m.kind === ts.SyntaxKind.ExportKeyword)) {
    console.log("export:", node.name?.text);
  }
});
```

### AST nodes — SyntaxKind

Every node has a `kind` from the `ts.SyntaxKind` enum. Most important: `FunctionDeclaration`, `InterfaceDeclaration`, `PropertySignature`, `Identifier`, `NumericLiteral`, `ExportKeyword`.

Type guards like `ts.isFunctionDeclaration(node)` narrow `node` to the correct subtype (analogous to Day 12 type guards).

### Visitor pattern — `forEachChild`

```ts
function visit(node: ts.Node) {
  if (ts.isInterfaceDeclaration(node)) {
    console.log("interface:", node.name.text);
    node.members.forEach(m => {
      if (ts.isPropertySignature(m)) console.log("  .", m.name.getText(sf), ":", (m.type as any)?.getText?.());
    });
  }
  ts.forEachChild(node, visit);
}
visit(sf);
```

### Transformers — source-to-source rewriting

```ts
const transformer: ts.TransformerFactory<ts.SourceFile> = context => sf => {
  function visit(node: ts.Node): ts.Node {
    if (ts.isFunctionDeclaration(node) && node.name?.text === "add") {
      return ts.factory.updateFunctionDeclaration(
        node, node.modifiers, node.asteriskToken, ts.factory.createIdentifier("addRenamed"),
        node.typeParameters, node.parameters, node.type, node.body
      );
    }
    return ts.visitEachChild(node, visit, context);
  }
  return ts.visitNode(sf, visit) as ts.SourceFile;
};

const result = ts.transform(sf, [transformer]);
const printer = ts.createPrinter();
console.log(printer.printFile(result.transformed[0]));
```

`ts.factory.createX(...)` is the idiomatic AST constructor (replaces the deprecated `ts.createX`). `ts.visitEachChild` recurses the visitor over all children.

### Why this matters

The compiler API is the foundation for: code generators (OpenAPI→TS), linters (eslint-typed-rules), codemods, build tools (vite/esbuild have their own, but the TS API for type-aware work). In Block 3 you will build agents that read and produce code — the compiler API is the bridge from "string" to "structured program".

### Pitfalls

- AST nodes are *immutable* — `updateX` creates new ones, does not mutate in place.
- `node.getText()` needs the source file context for correct spans; without a SourceFile it can fall back incorrectly.
- The `TypeChecker` is expensive — create it once per program, not per node.
- `ts.factory` is the current API; old examples online use `ts.createX`, which is deprecated.

## 🛠️ Practice

**Task:** Write a tool that parses a TS file, lists all `export function`s with their parameters, and a transformer that prefixes every function name with `public_`.

**Step by step:**

1. `npm i typescript`.
2. Implement the following in `src/index.ts`:

   > **Hints:**
   > - `import * as ts from "typescript"` and read the target file with `fs.readFileSync` (path from `process.argv[2]`, defaulting to `src/sample.ts`).
   > - Parse with `ts.createSourceFile(path, src, ts.ScriptTarget.Latest, true)`.
   > - For the listing: write a recursive `visit(node)` using `ts.forEachChild`. Narrow with `ts.isFunctionDeclaration(node)` and check `node.modifiers` for an `ExportKeyword` (`ts.SyntaxKind.ExportKeyword`). Print the function name and each parameter as `name: type` via `p.name.getText(sf)` and `p.type?.getText(sf)`.
   > - For the transformer: build a `ts.TransformerFactory<ts.SourceFile>` that returns `ts.visitNode(file, visit)`. Inside `visit`, when `ts.isFunctionDeclaration(node) && node.name`, use `ts.factory.updateFunctionDeclaration(...)` with a new identifier `"public_" + node.name.text`; otherwise `ts.visitEachChild(node, visit, ctx)`.
   > - Run the transform with `ts.transform(sf, [transformer])`, print the result with `ts.createPrinter().printFile(result.transformed[0])`.
   > - Remember nodes are immutable — `updateX` returns a new node, it does not mutate in place.
3. Create `src/sample.ts` as test input for your tool:

   > **Hints:**
   > - Include at least one exported function (`export function add(a: number, b: number) { ... }`), one exported const, and one **non-exported** function (`function internal() {}`).
   > - The tool must list only the exported one, and the transformer must prefix only function names (leaving `internal` untouched).
4. `npx tsc --noEmit && node dist/index.js src/sample.ts` (or via `tsx`).

**Definition of Done (DoD):**

- [ ] `npx tsc --noEmit` without errors in the tool.
- [ ] The tool lists only exported functions with parameters (no internal ones).
- [ ] The transformer renames `add` → `public_add`, leaves `internal` untouched.
- [ ] The output is valid TS (parseable by `ts.createSourceFile`).
- [ ] Commit: `git commit -m "day15: compiler api and ast manipulation"`.

**Extension (optional):** Use the `TypeChecker` to print the *resolved* type for each function parameter (instead of just source text). For that you must create a `Program` instead of only `createSourceFile`.
