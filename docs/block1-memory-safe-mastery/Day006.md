## 📖 Theory

### Traits — Rust's answer to interfaces

A trait declares methods that a type *can* implement. Unlike Java interfaces, traits can have default methods and can be implemented after the fact (subject to the "orphan rule": either the trait or the type must be in your crate).

```rust
trait Greet {
    fn say(&self) -> String;
    fn loud(&self) -> String { format!("{}!!", self.say().to_uppercase()) } // default
}
```

### Generics with bounds

```rust
// T must implement Greet — compile-time monomorphization
fn print_all<T: Greet>(items: &[T]) {
    for x in items { println!("{}", x.loud()); }
}
```

The compiler generates a separate function for each concrete `T` — **static dispatch**, zero overhead. In the disassembly you see `print_all_User`, `print_all_Bot`, etc.

### `impl Trait` — anonymous parameters/returns

```rust
fn make_iter() -> impl Iterator<Item = u32> { 0..10 }
fn take(x: impl Greet) { println!("{}", x.say()); }
```

Equivalent to generics with a bound, but shorter and great for "I return *some* iterator".

### `dyn Trait` — dynamic dispatch

```rust
fn print_mixed(items: &[Box<dyn Greet>]) {  // trait object
    for x in items { println!("{}", x.loud()); }   // vtable call
}
```

Here the concrete type info is *erased* — a vtable pointer calls the method indirectly. Slightly slower (indirect call, cache miss), but allows heterogeneous collections (`Box<dyn Animal>` with `Cat`, `Dog`, `Lizard`).

### Trait objects & object safety

A trait can only be used as `dyn Trait` if it is **object safe**: no `Self` return, no generic methods. For example, `Clone` is *not* object safe (`fn clone(&self) -> Self`).

### Associated types vs. generics

```rust
trait Iterator { type Item; fn next(&mut self) -> Option<Self::Item>; }
```

Associated types: a type has *exactly one* `Item`. Generic trait: a type can be `Iterator<Item=u32>` AND `Iterator<Item=String>` — that would be forbidden with associated types.

### Why this matters

Traits + generics are the tool for reuse. In Block 2 (memory pool) you will build traits like `Allocator`, in Block 4 (crypto) `Hash`, `Cipher`. Without trait bounds, all functions would be pinned to concrete types.

### Pitfalls

- **Orphan rule:** you cannot implement `Display` for `Vec<T>` — either the trait or the type must be in your crate. Workaround: the newtype pattern (`struct MyVec(Vec<u8>)`).
- `Box<dyn Trait>` is **not** `Clone` by default — trait objects are tricky in generic code.
- `?Sized` bound for traits with `Self: Sized` — for advanced patterns.
- Trait bounds can explode (`T: A + B + C, U: A + Clone`) — a `where` clause makes it readable.

## 🛠️ Practice

**Task:** Define a trait `Summable`, implement it for `Vec<i64>` and `HashMap<String, i64>`, and write a generic `total<T: Summable>(x: T) -> i64` with static dispatch. Compare performance against a `dyn Summable` version.

**Step by step:**

1. Implement the following in `src/main.rs`:

   > **Hints:**
   > - Define `trait Summable { fn sum_all(&self) -> i64; }` and implement it for `Vec<i64>` (iterate + `copied` + `sum`) and for `HashMap<String, i64>` (`values()` + `copied` + `sum`).
   > - Write `fn total<T: Summable>(x: T) -> i64` — a generic function with a trait bound (static dispatch / monomorphization).
   > - Write `fn total_dyn(x: &dyn Summable) -> i64` — a function taking a trait object (dynamic dispatch via vtable).
   > - In `main`, build a `Vec<i64>` and a `HashMap<String, i64>` of 1..=100, call `total` on each, then build a `Vec<Box<dyn Summable>>` and call `total_dyn` on one element to exercise dynamic dispatch.
2. `cargo build`.
3. Prove monomorphization: `cargo rustc -- --emit asm` and grep for `total` — there should be `total_*` variants (mangled).

**Definition of Done (DoD):**

- [ ] `cargo build` without warnings.
- [ ] `Summable` trait with a default method OR at least 2 implementations.
- [ ] `total<T: Summable>` with static dispatch (proof via ASM output).
- [ ] `total_dyn(&dyn Summable)` works with a `Box<dyn>` collection.
- [ ] An explainable answer to: "Why is `Clone` not object safe?"
- [ ] Commit: `git commit -m "day6: traits and generics"`.
