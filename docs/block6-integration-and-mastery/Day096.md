# Day 96: Personal Brand & Content

**Block:** Block 6: Integration & Mastery · Career

> **Goal of the day:** You have a public content presence with at least one published piece of substance content (blog post or tech-talk script) that links to your capstone project — and a 90-day content plan that is not "post more", but a concrete topic grid.

---

## 📖 Theory

"Personal brand" is a commercialized term. The usable reduction: **a traceable, public trail of your work** that enables strangers to verify your competence *themselves* — without you having to claim it. The capstone repo + one content article pointing at it is the atomic building block of that.

### Concept 1: Substance content vs. performance content

- **Substance content:** deep, technical, linked to code/artifacts/measurements. Half-life = months to years. Example: "How I built a PQC envelope with ML-KEM-768 in Rust — including benchmarks". Target audience: engineers solving the same problem.
- **Performance content:** shallow, reaction-driven, opinions. Half-life = hours. Example: "Rust vs Go hot take 🔥". Target audience: the algorithm feed.

Substance content is the career multiplier, performance content is algorithm sugar. Mix 4:1 in favor of substance. A company that hires you will read your substance articles; your performance content is irrelevant there.

### Concept 2: The 3-asset base

Three public assets, no more, as initial brand infrastructure:

1. **GitHub profile (pinned):** capstone + 2-3 side-project repos. README is the landing page. Pinned repos are your business card.
2. **One content channel:** blog (own site, e.g. Hugo/Astro on GitHub Pages) OR Dev.to/Medium OR LinkedIn long-form. One platform. No multi-platform friction at the start.
3. **An "About" page:** 5 sentences — who, what, currently learning, currently building, contact. This page is the most underestimated conversion point.

### Concept 3: The 90-day content plan as a topic grid

Instead of "I should post more", a grid with columns that explicitly links concrete topics from the curriculum to a content tag:

```
| Week | Curriculum reference     | Content format        | Status |
|------|--------------------------|-----------------------|--------|
| 1    | Block 4 — PQC envelope   | Blog post (1500 w)    | draft  |
| 2    | Block 3 — Agent loop     | Thread/X (8 tweets)   | idea   |
| 3    | Capstone release         | Show-HN post          | TODO   |
| 4    | Block 2 — Zig vs Rust    | Comparison blog post  | idea   |
| 5    | Block 1 — Ownership      | "Bug-of-the-week"     | idea   |
| 6    | Block 5 — Cross-compile  | Twitter thread        | idea   |
...
```

One substance unit per week. Six weeks = 6 articles/threads. No "daily posting" — that is burnout planning.

### Concept 4: Show-HN & landing page conversion

The capstone release is a Show-HN-suitable moment. Show-HN posts work when the post:

- Names a concrete problem (1 sentence).
- Links to the repo WITH an installable binary.
- Has a *concrete* demo guide ("run `pqc-agent init` then `pqc-agent run 'read /tmp/x'`").
- No marketing language.

Conversion: an engineer reads the article → clicks About → sees the capstone link → stars the repo. Three jumps, each reducing possible readers by ~80%. Therefore: every page in the chain must enable the next jump within 10 seconds.

### Why this matters

This ability — to translate technical work into a traceable public trail — is the narrowest career bottleneck. Engineers who only code are replaceable. Engineers with a *verifiable trail* of their work get found and are 2-3x less visible on the regular job market (because recruiters come inbound). This is not a marketing course, it is a career-engineering skill.

### Pitfalls

- "I'll post when it's perfect" — perfect never comes. Publish the first article with an honest "Draft v1" or "Notes" header. Iteration > perfection.
- Multi-platform distribution at the start → every channel under-maintained. One well > three half.
- Performance content overweight → algorithm-rewarded, but recruiters ignore it. You win likes, you lose career signal.
- No About page → readers land on the article, have no next jump → lost.

## 🛠️ Practice

**Task:** Publish 1 piece of substance content that links to your capstone. Create a 90-day content plan as a markdown table. About page live.

**Step by step:**

1. **Choose a platform (one):** e.g. Hugo site on GitHub Pages:

   ```bash
   hugo new site personal-site
   cd personal-site
   git init && git remote add origin <your-fork>
   # Theme: PaperMod or pure HTML/CSS — no theme spiral
   ```

2. **About page:** `content/about.md`, the 5 sentences, see concept 2. Must be reachable live (`<user>.github.io/about`).
3. **Substance article draft:** `content/posts/pqc-envelope-rust.md`:

   > **Hints:**
   > - **Problem** (2 sentences): PQC migration, what breaks, why hybrid.
   > - **Approach:** ML-KEM-768 encapsulates a DEK (XChaCha20-Poly1305); Ed25519 signs the envelope; include one 5–15 line code snippet from day 92 (not a whole file).
   > - **Results:** a table with the real latency/throughput numbers from your day-94 bench (no placeholder numbers).
   > - **Code:** repo link + install command. **Lessons:** what surprised you + what you'd do differently.
4. **Publish** — `git push`, deploy via GitHub Pages Action.
5. **90-day plan** in `docs/content/PLAN_90.md` as a table (see concept 3). At least 6 weeks filled in.
6. **Show-HN draft (posting not mandatory):** write the post text in `docs/content/show_hn_draft.md`, max 8 lines, see concept 4.

**Definition of Done (DoD):**

- [ ] One platform (blog/Dev.to/LinkedIn) is live and reachable from outside (URL noted in `docs/content/PLAN_90.md`).
- [ ] About page exists, has 5 sentences, mentions the capstone project with a link.
- [ ] One substance article is published and links concretely to the capstone repo.
- [ ] The article has at least 3 concrete numbers (bench, LoC, time spent) — no unquantified claims.
- [ ] `docs/content/PLAN_90.md` has ≥ 6 weeks filled in with curriculum reference + format.
- [ ] Show-HN draft file exists (posting optional, writing not).
- [ ] Commit: `git commit -m "day96: published 1 substantive article + 90d content plan"`.

**Extension (optional):** Set up Plausible/GoatCounter as privacy-first analytics. Track 1 metric: unique visitors per substance article over 30 days. That is the only number that counts for career purposes — not likes, not followers.
