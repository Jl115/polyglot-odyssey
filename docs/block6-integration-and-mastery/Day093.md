---

## 📖 Theory

Day 92 built the shell (secrets + crypto + build). Day 93 builds the **moving parts**: the agent loop and the tool interface. The risk here is making the loop too complex — one tool is enough, two is luxury, three is scope creep.

### Concept 1: Minimal tool-use loop

An agent loop without framework bloat has four states:

```
[USER PROMPT] -> [LLM CALL] -> [TOOL DECISION]
        ^                          |
        |                          v
   [FINAL ANSWER] <----- [TOOL EXECUTE] -> [OBSERVATION] -> (LLM CALL)
```

Implemented as a finite state machine, not as recursion (prevents infinite loops via max iterations):

```rust
enum LoopState { LlmCall, ToolCall(String), ToolResult(String), Done(String), Stop }

fn agent_loop(prompt: &str, store: &SecretsStore, llm: &dyn Llm, max_iter: usize) -> Result<String> {
    let mut msg = prompt.to_string();
    for _ in 0..max_iter {
        match llm.decide(&msg)? {
            Decision::Tool(name) => {
                let out = execute_tool(&name, store)?;
                msg = format!("Tool {name} returned: {out}");
            }
            Decision::Final(ans) => return Ok(ans),
            Decision::Stop => return Ok("stopped".into()),
        }
    }
    bail!("agent_loop: max iterations exceeded")
}
```

`max_iter` is a **safety anchor**, not an optimization parameter. Default = 5. Beyond that is a bug, not a feature.

### Concept 2: LLM trait — mock first

The production LLM call (network, API key, latency, cost) must **not** be the default development path. Define a trait and deliver a deterministic mock:

```rust
trait Llm { fn decide(&self, msg: &str) -> Result<Decision>; }

enum Decision { Tool(String), Final(String), Stop }

struct MockLlm;
impl Llm for MockLlm {
    fn decide(&self, msg: &str) -> Result<Decision> {
        if msg.contains("read") { Ok(Decision::Tool("read_file".into())) }
        else { Ok(Decision::Final(format!("echo: {msg}"))) }
    }
}
```

The real backend (`LlamaCppLlm` via FFI or `OpenAiLlm` via HTTP) is switched via `--llm mock|llamacpp|openai`. Tests run against `MockLlm` — deterministic, offline, free. This is exactly the inversion that day 38 (Observability) and day 41 (K8s) prepared.

### Concept 3: Signed audit log

Every agent action is logged — and the log is **Ed25519-signed at the end of the session** and appended to the secrets store. This is the block-4 connection in action: not only secrets are signed, but the *usage* of the secrets is retroactively verifiable. That is the difference between "I used crypto" and "crypto is part of the proof".

```rust
struct AuditLog { entries: Vec<AuditEntry>, }
impl AuditLog {
    fn finalize_signed(&self, sk: &SigningKey) -> Result<Vec<u8>> {
        let bytes = bincode::serialize(&self.entries)?;
        let sig = sk.sign(&bytes).to_bytes();
        Ok(bytes.into_iter().chain(sig).collect())
    }
}
```

### Why this matters

This day proves the ability to build complex systems as *small composable traits*, instead of as monolithic framework configuration. This architectural discipline — trait boundaries, mock first, max-iteration-bounded loops — transfers directly to any future agent job. This is exactly where "agent hype" separates from "agent engineering".

### Pitfalls

- Recursive loops without `max_iter` → infinite loop in production (and in tests).
- LLM directly without a trait → untestable, every test needs network/API key.
- Log file grows unboundedly → rotate by size or session, sign per session.
- Tool output returned to the LLM unfiltered → prompt injection vector. Mark tool output as "system: tool_result", separate from the user channel.

**Task:** Implement (1) `Llm` trait + `MockLlm`, (2) a `read_file` tool, (3) `agent_loop` with `max_iter`, (4) audit log with signature, (5) CLI subcommand `run`. Real LLM optional behind a flag.

**Step by step:**

1. Create `src/llm.rs`, `src/tool.rs`, `src/agent.rs` — modular, not one 600-line file.
2. `src/llm.rs`:

   > **Hints:**
   > - Define `pub trait Llm` with `fn decide(&self, msg: &str, ctx: &ToolRegistry) -> Result<Decision>` and a `pub enum Decision { Tool(String), Final(String), Stop }`.
   > - Implement `MockLlm` (deterministic, offline) — base it on the Theory example above, but adapt the `decide` signature to take the `ToolRegistry`.

   > **Hints:**
   > - Define `pub trait Tool { fn name(&self) -> &str; fn run(&self, args: &str) -> Result<String>; }`.

   > - Store tools in a `ToolRegistry` (e.g. `HashMap<&str, Box<dyn Tool>>`) so the agent can look up tools by name.
4. `src/agent.rs` — `agent_loop` as in the theory example, with a `ToolRegistry` (HashMap<&str, Box<dyn Tool>>).
