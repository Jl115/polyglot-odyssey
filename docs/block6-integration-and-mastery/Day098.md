# Day 98: Interview & Hiring Prep

**Block:** Block 6: Integration & Mastery · Career

> **Goal of the day:** You have 2 system-design sketches (on paper/digital) for typical questions in systems/security/AI roles, a STAR-formatted behavioral repertoire (5 stories), and a salary negotiation plan that fixes your walk-away point *before* the first call.

---

## 📖 Theory

Engineers don't fail interviews on knowledge, they fail on **format**. A wrong answer structure makes competent engineers appear incompetent. The three interview types each have a different success key — and none of them is "code well".

### Concept 1: System design — the framework

Systems roles (backend, infra, security) have system-design questions with a 45-60 minute slot. The standard framework that works in 90% of cases:

1. **Clarify (5 min):** ask requirements explicitly, don't assume. "Who are the users? Read-heavy or write-heavy? Latency SLO? Consistency vs availability tradeoff?"
2. **High-level architecture (10 min):** 3-5 boxes. Client → LB → Service → Storage. Draw *before* you speak, otherwise you lose the thread.
3. **Deep-dive (20 min):** one component in detail. This is where specialization scores (Rust ownership, PQC, agent loops).
4. **Bottlenecks & scale (10 min):** "What breaks at 10x load? At 100x?" Single point of failure, cache invalidation, partition tolerance.
5. **Tradeoffs (5 min):** justify every choice with an alternative. "Postgres vs DynamoDB, because X, with tradeoff Y."

For your profile, two concrete practice questions are realistic:

- **"Design a PQC Migration Service"** (security + scale): migration orchestration, rollback, key management, audit log, SBOM integration.
- **"Design an AI Agent Orchestrator"** (AI-native): tool registry, max-iter, rate limiting, audit log, multi-tenant secrets store.

### Concept 2: Coding interview — the 4-phase pattern

Coding questions (45 min) always follow the same loop. A mistake in phase 1 = a mistake in 4:

1. **Restate + examples (5 min):** restate the task in your own words, invent 2 examples including an edge case. *Do not* start coding before examples exist.
2. **Approach (10 min):** algorithm as prose/pseudocode, not as a `fn`. Name the complexity (O(·) for time & space). Say out loud what you are doing.
3. **Implement (20 min):** idiomatic code. In Rust: no `unwrap()` in solutions, `?` operator. In TS: explicit types. Readable variable names.
4. **Test (10 min):** run the examples from phase 1 through the code (think out loud), find the bug, fix it.

Anti-patterns: coding immediately without examples, typing silently, done without a test phase. The interviewer evaluates *process*, not result.

### Concept 3: Behavioral — the STAR format

Behavioral questions ("Tell me about a time when…") have a standard format that makes the answer structurable:

- **S (Situation):** context, 1-2 sentences.
- **T (Task):** your concrete responsibility, 1 sentence.
- **A (Action):** what *you* did, with concrete decisions (not "we"). 3-4 sentences.
- **R (Result):** quantified outcome, 1-2 sentences. Numbers, not opinions.

Example from your capstone:
> "S: Building a PQC CLI for the 100-day curriculum, I needed encrypted secret storage without external dependencies. T: I had to design the envelope cryptography. A: I chose a hybrid ML-KEM-768 + XChaCha20-Poly1305 envelope with Ed25519 audit-log signatures, validating via tamper-detection tests. R: Roundtrip tests pass in 1.2ms; tamper-detection covers 100% of byte modifications; the v0.1.0 release shipped with SBOM and signatures."

Prepare **5 stories** that cover different facets: (1) ownership/lead, (2) conflict resolution, (3) failure + learning, (4) technical depth, (5) cross-functional collaboration. One story can be re-tailored for multiple questions — the 5-story repertoire is sufficient for 90% of all behavioral questions.

### Concept 4: Salary negotiation — the walk-away point

The most important preparation happens **before** the first recruiter call:

1. **Research market value:** Glassdoor, levels.fyi, local comparison. A band for role + seniority + region.
2. **Fix the walk-away point:** the amount below which you definitely decline. Write it down before the call, not negotiable.
3. **Anchor high:** when asked about expectations, give a range with the upper end = your target, lower end = your walk-away point + 5%. Never name a number first if you can push back ("I'd like to learn about the full comp package first").
4. **Total comp, not base:** equity, bonus, sign-on, remote allowance, learning budget. Base is only one dimension.

The only power you have in negotiation is the ability to walk away. Without a walk-away point you negotiate from fear, not from position.

### Why this matters

Interview competence is a *separate* skill, orthogonal to engineering competence. Excellent engineers without interview-format training fall an average of 1-2 levels in outcome. This preparation is the bottleneck for the "full-time engineer role" career option (the alternative to day 97's consulting). The skill transfers to every role change of the next 30 years.

### Pitfalls

- Diving into details immediately in system design → loses the big picture. Always 5 min clarify first.
- Coding silence → the interviewer cannot evaluate your thought process, default = lower rating. *Think out loud*, even if it feels unfamiliar.
- Behavioral without quantification → "we improved performance" is worthless; "we reduced p95 latency from 200ms to 60ms" is gold.
- Fixing the walk-away point only during the call → emotional negotiation, you accept too low.

## 🛠️ Practice

**Task:** 2 system-design sketches (PQC Migration Service + AI Agent Orchestrator), 5 STAR stories, 1 salary plan with a walk-away point.

**Step by step:**

1. Create `docs/career/interview_prep/`.
2. **System design sketch 1** — `pqc_migration_service.md`, following the 5-phase framework:

   > **Hints:**
   > - **Clarify:** users (regulated-industry security teams), workload (write-light/read-heavy), SLOs (migration throughput + audit-query p95), consistency-vs-availability tradeoff.
   > - **High-Level Architecture:** an ASCII diagram with API Gateway → Migration Orchestrator → HSM-backed Key Store → append-only signed Audit Log → per-migration SBOM Generator.
   > - **Deep-Dive:** the Migration Orchestrator — bounded worker pool, reversible-delta rollback, HSM key management (PKCS#11, keys never leave HSM).
   > - **Bottlenecks:** HSM throughput, audit-log growth — name a mitigation for each.
   > - **Tradeoffs:** storage choice (e.g. Postgres vs DynamoDB) and sync vs async orchestration, each with a justification.
3. **System design sketch 2** — `ai_agent_orchestrator.md`, same structure, focus on tool registry, max-iter, rate limiting, multi-tenant secrets (compare your capstone).
4. **STAR repertoire** — `star_stories.md` with 5 stories, each in STAR format (see concept 3). One *must* come from the capstone, one from a conflict, one from a failure.
5. **Salary plan** — `salary_plan.md`:

   > **Hints:**
   > - Include: target role + region, market range (from levels.fyi/Glassdoor), a fixed **walk-away point** as a concrete number, an anchor range for when asked, negotiable extras, and the total-comp dimensions (base/equity/bonus/sign-on/benefits).
   > - The walk-away point must be a real number fixed *before* the first call — not "TBD".
6. **Practice (not optional):** run the PQC sketch once in 45 minutes straight through, speaking out loud, with a timer. Note where you get stuck.

**Definition of Done (DoD):**

- [ ] `pqc_migration_service.md` has all 5 phases (Clarify / High-Level / Deep-Dive / Bottlenecks / Tradeoffs).
- [ ] `ai_agent_orchestrator.md` has the same 5 phases, with an ASCII diagram in High-Level.
- [ ] `star_stories.md` has 5 stories, each a complete STAR structure (S/T/A/R explicitly labeled).
- [ ] At least 1 STAR story is quantified (number in the R part).
- [ ] `salary_plan.md` has a walk-away point as a concrete number (not "TBD").
- [ ] One 45-min system-design exercise run through (timer recording or note with duration + stumbling points).
- [ ] Commit: `git commit -m "day98: 2 system design sketches + 5 STAR stories + salary plan"`.

**Extension (optional):** Do a mock interview with an engineer friend (60 min): 20 min system design, 20 min coding, 20 min behavioral. Have them check the STAR stories for quantification and the sketch for a clarify phase. Note feedback, iterate the repertoire.
