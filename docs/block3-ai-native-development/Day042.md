## 📖 Theory

**vLLM** is a high-throughput inference server for LLMs. Its core innovation is **PagedAttention**: the *KV-cache* is managed in fixed pages like virtual memory in an OS, so (a) fragmentation disappears, (b) multiple requests share the cache, and (c) continuous batching becomes possible.

### Why PagedAttention multiplies throughput

Classically each request reserves a contiguous GPU block for the maximum possible tokens → memory wasted. PagedAttention allocates dynamically in 16-token pages → 2–4× higher throughput at the same VRAM.

### OpenAI-compatible API

vLLM exposes `/v1/chat/completions` and `/v1/models` — code that works with OpenAI runs unchanged against vLLM. That makes it a drop-in for self-hosting.

```bash
# GPU (e.g. 24 GB): Qwen2.5-7B
vllm serve Qwen/Qwen2.5-7B-Instruct --port 8000

# CPU fallback (no GPU): llama.cpp instead of vLLM
# brew install llama.cpp
llama-server -m ~/.cache/huggingface/Qwen2.5-1.5B-Instruct-Q4_K_M.gguf \
  --port 8080 --n-gpu-layers 0
```

Model download for the CPU fallback:
```bash
huggingface-cli download Qwen/Qwen2.5-1.5B-Instruct \
  --local-dir ./models/qwen-1.5b --quiet
# gguf via bartowski quant:
# wget https://huggingface.co/bartowski/Qwen2.5-1.5B-Instruct-GGUF/resolve/main/Qwen2.5-1.5B-Instruct-Q4_K_M.gguf
```

### Client call

```python
from openai import OpenAI
client = OpenAI(base_url="http://localhost:8000/v1", api_key="dummy")
resp = client.chat.completions.create(
    model="Qwen/Qwen2.5-7B-Instruct",
    messages=[{"role":"user","content":"Explain PagedAttention in 2 sentences."}],
    max_tokens=80, temperature=0.2)
print(resp.choices[0].message.content)
print(f"tokens: in={resp.usage.prompt_tokens} out={resp.usage.completion_tokens}")
```

### Important parameters

| Flag | Purpose | AI-dev relevance |
|---|---|---|
| `--max-model-len 4096` | context limit | long source code: raise it, VRAM grows |
| `--quantization awq` | 4-bit quantization | 2× less VRAM, ~5% quality loss |
| `--gpu-memory-utilization 0.9` | VRAM share for KV-cache | too high → OOM on load spikes |
| `--enable-prefix-caching` | cache identical prefixes | prompt templates → massive speedup |

### Why this matters

The block outcome "AI Dev Tool with GitHub integration" needs a running LLM that analyzes PRs in the background. Cloud APIs are easy but expensive at high volume and raise data-privacy concerns (source code). Self-hosted vLLM (or llama.cpp) is the *realistic* production variant.

### Pitfalls

- **First-load latency:** the model loads in ~30s–5min depending on size. Liveness probes too aggressive → pod restart loop.
- **VRAM > model weight:** a 7B model in bf16 = ~14 GB weight + 2–4 GB KV-cache + overhead. A 16 GB GPU can OOM on long contexts.
- **Tokenizer discrepancy:** if the client tokenizer doesn't match the server model, prompts get merged wrongly. Always keep the `model` name exact.
- **CPU vLLM is practically unusable** (>30× slower). CPU → llama.cpp, GPU → vLLM. Be honest about it in code comments.

## 🛠️ Practice

**Task:** Start a local LLM server (vLLM with GPU or llama.cpp without) and answer 3 requests of varying complexity with token logging.

**Step by step:**

1. Hardware check:
   ```bash
   # GPU present?
   nvidia-smi   # shows VRAM; if 0 or absent → CPU path
   ```
2. **GPU path** (recommended for ≥ 8 GB VRAM):
   ```bash
   pip install vllm
   vllm serve Qwen/Qwen2.5-1.5B-Instruct --port 8000 --max-model-len 2048
   ```
3. **CPU path** (fallback):
   ```bash
   brew install llama.cpp
   # download GGUF (see above)
   llama-server -m ./models/qwen-1.5b.gguf --port 8080 --ctx-size 2048
   ```
4. Healthcheck: `curl localhost:8000/v1/models | jq '.data[0].id'` (adjust port).
5. Client script `ask.py` (snippet above).
6. Test requests:
   - Easy: "What is 2+2?"
   - Medium: "Explain ownership in Rust."
   - Long: "Write a function that reads a file asynchronously." + token tracking.
7. Test prefix caching: same system prompt across 3 requests → second/third should have equal `prompt_tokens` but differing `completion_tokens`; latency should drop.

**Definition of Done (DoD):**

- [ ] `curl <server>/v1/models` returns JSON with a model id, HTTP 200.
- [ ] `python ask.py` produces an answer with ≤ 200 tokens and logs `prompt_tokens` + `completion_tokens`.
- [ ] A second identical request (with prefix caching) has noticeably lower latency, or equal latency with a clear comment why.
- [ ] On an overly long request (> context limit) a clear HTTP error comes back instead of hanging.
- [ ] You can explain PagedAttention in 3 sentences.
- [ ] Commit: `git commit -m "day42: local llm serving via vllm/llama.cpp"`.

**Extension (optional):** Build a load test with `python -c "import asyncio,openai; ..."` — 10 parallel requests measure p50/p95 latency and tokens/s. Compare with sequential.
