---

## 📖 Theory

**Fine-tuning** adapts the weights of a pre-trained model to a specific task. Full-parameter fine-tuning is expensive (all weights update). **LoRA (Low-Rank Adaptation)** freezes the original weights and learns only two small rank-`r` matrices `A` and `B` per weight matrix, whose product approximates the update: `W' = W + B·A`. Trainable parameters drop from billions to millions — 10–100× less VRAM.

### LoRA math

For a weight matrix `W ∈ R^(d×k)`:

- Full FT: learn `ΔW ∈ R^(d×k)` → `d·k` parameters.
- LoRA: `ΔW = B @ A`, `A ∈ R^(r×k)`, `B ∈ R^(d×r)`, `r << min(d,k)` → `r·(d+k)` parameters.
- With `d=k=4096`, `r=8`: Full = 16.8M params, LoRA = 65k params (~256× reduction).

### Hugging Face PEFT library

`peft` is the standard for LoRA in PyTorch/HF. With `transformers` and `trl` (SFTTrainer):

```python
from peft import LoraConfig, get_peft_model
from transformers import AutoModelForCausalLM, AutoTokenizer, TrainingArguments
from trl import SFTTrainer, SFTConfig

model = AutoModelForCausalLM.from_pretrained(
    "Qwen/Qwen2.5-0.5B", torch_dtype="auto")
tok = AutoTokenizer.from_pretrained("Qwen/Qwen2.5-0.5B")

lora_cfg = LoraConfig(
    r=8, lora_alpha=16, lora_dropout=0.05,
    target_modules=["q_proj","k_proj","v_proj","o_proj"],
    task_type="CAUSAL_LM")

model = get_peft_model(model, lora_cfg)
model.print_trainable_parameters()   # → "trainable: 0.5% of all"

trainer = SFTTrainer(
    model=model, tokenizer=tok,
    train_dataset=ds,                # HuggingFace dataset
    args=SFTConfig(
        output_dir="./out", per_device_train_batch_size=2,
        gradient_accumulation_steps=4, num_train_epochs=3,
        learning_rate=2e-4, logging_steps=10, save_strategy="epoch"),
)
trainer.train()
```

### Instruction dataset format

```json
{"instruction":"Explain ownership in 1 sentence.","output":"Every value has an owner; at scope end it is dropped."}
{"instruction":"What is a move?","output":"Ownership transfer; the old name is invalid."}
```

### Hardware reality (honest)

- **GPU path:** 4 GB+ VRAM (T4, 3060, etc.) is enough for Qwen2.5-0.5B with LoRA, batch 2, seq 512.
- **CPU path:** trainable, but ~10–30× slower; for 0.5B and 500 samples, realistically 30–60 min.
- **Colab free:** T4 GPU free, ~12 GB VRAM, ideal for this day. Recommended default.
- **No ML hardware → fake path:** use a *small* task (e.g. 50 examples, 1 epoch) just to validate the pipeline. Qualitatively useless, but the learning goal "I can start the code" is met.

### Why this matters

An AI dev tool that should understand "in-house" code style (e.g. your repos) benefits massively from LoRA fine-tuning on your code dataset — at a fraction of the cost of a cloud fine-tune. LoRA is today the standard approach for resource-conscious customization.

### Pitfalls

- **Wrong `target_modules`:** adapting only `q_proj` is weak; usually all 4 attention projections + optionally MLP modules.
- **`lora_alpha` too high:** `alpha=16` at `r=8` is a good default; too high → instability, divergence.
- **Tokenizer pad token:** Qwen2 has a default pad, but some models don't; set `tokenizer.pad_token = tokenizer.eos_token`.
- **Catastrophic forgetting:** 3+ epochs on a narrow dataset overwrite pre-trained knowledge. LoRA mitigates this, but run eval on out-of-domain prompts too.
- **Missing eval:** without a holdout set the loss value is meaningless. Hold out 10% of the data for validation.

## 🛠️ Practice

**Task:** Build an instruction dataset (≥ 100 examples), LoRA fine-tune Qwen2.5-0.5B (or 1.5B), log train/val loss, save the adapter weights.

**Step by step:**

1. Setup:

   ```bash
   pip install "transformers>=4.45" "trl>=0.11" peft datasets accelerate
   ```

2. Build the dataset: 100+ `{instruction, output}` pairs (e.g. Rust/TS facts
   from Block 1/2; or your Day001–Day020). Save as `data.jsonl`, then load and
   split it:

   > **Hints:**
   > - Use `load_dataset("json", data_files="data.jsonl")["train"]` from the `datasets` library.
   > - Call `.train_test_split(test_size=0.1)` to hold out 10% for validation.
3. Format per example: `f"### Instruction:\n{instruction}\n\n### Response:\n{output}"`.
4. Training script `train.py` with the snippets above; GPU/CPU/Colab depending on hardware.
5. Check logging: `tensorboard --logdir ./out`; loss curve should fall monotonically.
6. Save the adapter: `model.save_pretrained("./lora_adapter")` — only ~5–20 MB.
7. Test inference by loading the LoRA adapter onto the base model and
   generating a response:

   > **Hints:**
   > - Load the base model with `AutoModelForCausalLM.from_pretrained("Qwen/Qwen2.5-0.5B")`.
   > - Wrap it with `PeftModel.from_pretrained(base_model, "./lora_adapter")` to apply the adapter weights.
   > - Tokenize a prompt in the same `### Instruction: … ### Response:` format, then call `.generate(..., max_new_tokens=50)`.
   > - Pass `return_tensors="pt"` to the tokenizer for PyTorch tensors.

**Definition of Done (DoD):**

- [ ] `model.print_trainable_parameters()` shows `< 1%` trainable.
- [ ] Train loss falls across epochs; `eval_loss` documented in `trainer_state.json`.
- [ ] `./lora_adapter/adapter_config.json` exists and contains `"peft_type":"LORA"`.
- [ ] Inference with the loaded adapter produces sensible text in the training domain (no longer base behavior).
- [ ] You note in `notes.md`: hardware path (GPU/CPU/Colab), training time, final `eval_loss`.
- [ ] Commit: `git commit -m "day46: lora finetune qwen-0.5b on rust faqs"`.

**Extension (optional):** Merge LoRA into the base model (`model.merge_and_unload()`) and export as `onnx` or `gguf` for vLLM/llama.cpp serving. Compare inference quality before/after merge.
