# Day 50: Mini-Capstone: ML Pipeline

**Block:** Block 3: AI-Native Development · Mini-Capstone

> **Goal of the day:** You build a reproducible end-to-end ML pipeline (data → train → eval → quant → register) that runs with a single command (`make pipeline`) and delivers an artifact-tracked result.

---

## 📖 Theory

Third mini-capstone: integration of the ML building blocks (Days 46–49) into a *pipeline* that is reproducible — i.e. the same inputs yield the same result, with versioned stands of all artifacts.

### Pipeline stages

```
data/                ──┐
   curate.py            │
   ↓                    │
   train.jsonl          │  → train.py (LoRA)
                         │       ↓
                         │   lora_adapter/  → eval.py
                         │                         ↓
                         │                  quant.py → q4km.gguf
                         │                                    ↓
                         │                       register.py (HF Hub / local registry)
                         ▼
                    metrics.json (all stages)
```

### Makefile as orchestrator

```makefile
PIPELINE_VER ?= $(shell git rev-parse --short HEAD)
MODEL ?= Qwen/Qwen2.5-0.5B

data/train.jsonl data/val.jsonl: curate.py raw.jsonl
	python curate.py --out data --raw raw.jsonl

lora_adapter:
	python train.py --model $(MODEL) --data data --out lora_adapter

metrics.json: lora_adapter
	python eval.py --base $(MODEL) --adapter lora_adapter --eval data/val.jsonl --out metrics.json

q4km.gguf: lora_adapter
	python quant.py --base $(MODEL) --adapter lora_adapter --out q4km.gguf

pipeline: data lora_adapter metrics.json q4km.gguf
	@echo "Pipeline $(PIPELINE_VER) done"
```

### Artifact versioning

Each stage writes into a `manifest.json`:

```json
{
  "git_sha": "abc1234",
  "base_model": "Qwen/Qwen2.5-0.5B",
  "data_sha": "sha256:...",
  "adapter_sha": "sha256:...",
  "metrics": {"bleu_base": 12.3, "bleu_ft": 18.1},
  "quant": {"format": "q4_k_m", "size_mb": 1024, "quality_loss_pct": 4.2}
}
```

### Caching: what changes, what doesn't

- Data hash → changes → train must rerun.
- Base model pin → static → cache.
- LoRA hyperparameters → part of the train key → invalidate cache.

### Why this matters

In production (capstone Day 55, CI/CD Day 51) the pipeline is re-triggered on every dataset commit — and must be *reproducible*. "It worked yesterday, not today" is classic pipeline chaos. This capstone forces you to build every stage *deterministically* and *versioned*.

### Pitfalls

- **Non-determinism:** `seed` not set in `train.py`, `eval.py`, sampling → run-to-run variance. Set `torch.manual_seed`, `random.seed`, `numpy.random.seed`; `model.generation_config.do_sample=False` for eval.
- **Stale cache:** Makefile targets without correct dependencies (`lora_adapter: train.py` missing) → no rebuild on code changes. List every `.py` as a dependency or force `make -B`.
- **Model download costs:** every run downloads the base model → set `HF_HOME=~/.cache/huggingface` and cache.
- **Partial pipeline break:** `eval.py` fails, `make pipeline` aborts → quant.py never runs. Use `make -k` for continue-on-error or run in stages and collect logs.

## 🛠️ Practice

**Task:** Build the 5-stage pipeline with a Makefile, run it with `make pipeline`, produce `manifest.json` with all SHAs and metrics.

**Step by step:**

1. Project structure:
   ```
   day50/
   ├── Makefile
   ├── curate.py, train.py, eval.py, quant.py, register.py
   ├── raw.jsonl
   └── data/ lora_adapter/ q4km.gguf metrics.json manifest.json (output)
   ```
2. Reuse code from Days 47–49; put each stage in its own script with `argparse`.
3. Adapt the Makefile (above); check `make -n pipeline` (dry-run).
4. First run:
   ```bash
   make pipeline
   ```
5. Test reproducibility: run the pipeline twice → `manifest.json` identical (same SHAs, ≤ 1% metrics deviation).
6. Artifact registry: `register.py` pushes `metrics.json` and `q4km.gguf` to HF Hub (private repo `you/dev-hint-model`).
7. Partial-failure demo: inject a bug in `eval.py`, `make -k pipeline` → train + quant run, eval skipped → clear report.

**Definition of Done (DoD):**

- [ ] `make pipeline` runs end-to-end without error (or with a clearly documented partial fail on `make -k`).
- [ ] `manifest.json` contains `git_sha`, `data_sha`, `adapter_sha`, `metrics`, `quant`.
- [ ] A second run on unchanged input yields ≤ 1% deviating metrics (reproducibility).
- [ ] When `raw.jsonl` changes, `make pipeline` triggers a re-train (data dependency works).
- [ ] On a bug in `eval.py`, `make pipeline` aborts (does not silently skip).
- [ ] `register.py` successfully pushed the quant + adapter to HF Hub (or a local `models/` registry folder).
- [ ] Commit: `git commit -m "day50: mini-capstone reproducible ml pipeline"`.

**Extension (optional):** Integrate DVC or MLflow — `dvc.yaml` as a pipeline DAG instead of a Makefile; `dvc push` for artifact storage in S3/GCS. Compare trade-offs with the Makefile approach.
