# Day 40: Mini-Capstone: Agent Pipeline

**Block:** Block 3: AI-Native Development · Mini-Capstone

> **Goal of the day:** You build an end-to-end agent pipeline that takes a request, researches (RAG), generates a code suggestion, and self-evaluates the result — all in a traced LangGraph workflow.

---

## 📖 Theory

A **capstone** forces you to assemble the building blocks so far (Days 36–39) into a coherent system. The learning goal is not something new but *integration*: keep interfaces clean, the state schema consistent, tracing active, and run the pipeline under realistic conditions.

### Mini-capstone specification

**Name:** `dev-hint-agent` — a CLI tool that, given a programming question, (a) looks things up, (b) generates a code suggestion, (c) self-evaluates whether the suggestion looks compilable, and optionally performs a revision.

**Pipeline (5 nodes):**

```
START → classify → research(RAG) → generate → self_review → END
                              ↑                    │
                              └── rewrite ─────────┘   (max 2x)
```

- `classify`: simple keyword routing: `code` vs `concept` vs `unknown`.
- `research`: calls Qdrant (Day 38) for relevant chunks.
- `generate`: LLM call that produces a code suggestion from question + chunks.
- `self_review`: a second LLM call evaluates `"Compilable? Yes/No + reason"`. If "No" and iterations < 2 → back to `generate` (with the critique as context), otherwise `END`.

### State schema

```python
class CapstoneState(TypedDict):
    question: str
    kind: str                       # code|concept|unknown
    context: Annotated[list[str], add]
    draft: str
    critique: str
    iterations: int
    final: str
```

### Why this matters

This mini-capstone is the "little sister" of the block capstone (Day 55): it isolates *only* the agent logic (no GitHub API, no K8s deploy). When it runs, you have the confidence that the larger version is feasible. If it *doesn't* run, the trace (Day 39) shows exactly which node fails.

### Pitfalls

- **Self-evaluation is weak:** LLMs tend to judge their own output positively. Force a structured output schema (`{"compilable": bool, "reason": str}`) via tool-calling or JSON mode, not free text.
- **Context evaporation:** if `generate` doesn't *read* `critique` on retry, it repeats the same mistake. Always merge the critique into the prompt.
- **Loop without bounded iterations:** the `self_review → generate` cycle needs a hard `iterations >= 2` limit, otherwise infinite.
- **Tracing cost:** 5 nodes × 2 iterations × ~2 LLM calls = 10+ spans per run. Rate-limit on the LangSmith free tier.

## 🛠️ Practice

**Task:** Implement the 5-node pipeline with Qdrant RAG, LLM generation, and a self-review loop (max 2 iterations). CLI interface: `python agent.py "How do I implement a channel API in Rust?"`.

**Step by step:**

1. Setup: `cp -r day37 day40 && cd day40`, Qdrant from Day 38 running, `pip install langchain langchain-anthropic langgraph qdrant-client sentence-transformers`.
2. `agent.py`:
   - State schema (above).
   - Nodes: `classify`, `research` (with `qd.search`), `generate`, `self_review` (force JSON output).
   - Conditional edges:
     - `classify → research` (code/concept), `classify → END` (unknown → "I can't help").
     - `self_review → generate` (on "No" & iterations<2), otherwise `END`.
3. Write the self-review prompt so the evaluator LLM returns **structured JSON**
   (`{"compilable": <bool>, "reason": "<short>"}`), then parse it safely:

   > **Hints:**
   > - Build an f-string prompt that includes `state['draft']` (the suggestion) and the last item from `state['context']` (or `"none"` if empty).
   > - Ask the model to answer as JSON with two keys: `compilable` (bool) and `reason` (string).
   > - Parse the response with `json.loads(...)`; wrap it in a `try/except` and fall back to `compilable=False` on any parse error.
   > - Return `"generate"` (to retry) when `compilable` is false and `iterations < 2`, otherwise proceed to `END`.
4. Add a CLI wrapper so the tool can be invoked as
   `python agent.py "How do I implement a channel API in Rust?"`:

   > **Hints:**
   > - Read the question from `sys.argv[1]` under `if __name__ == "__main__":`.
   > - Call `app.invoke({...})` with the initial state — every `CapstoneState` field must be present (`question`, `iterations: 0`, empty strings/lists for the rest).
   > - Print `result["draft"]` (or `result["final"]`) as the final output.
5. Tracing active (LANGSMITH_TRACING=true), run once.
6. Document test cases: (a) a clear Rust question, (b) a vague question, (c) "write Python" (classify should route correctly).

**Definition of Done (DoD):**

- [ ] `python agent.py "What is ownership in Rust?"` outputs a code suggestion with source citations.
- [ ] On a flawed first draft, `self_review` runs back to `generate` at least once (visible in the trace).
- [ ] After max 2 iterations the pipeline terminates guaranteed.
- [ ] LangSmith trace shows all 5 nodes as spans with token and cost info.
- [ ] `metrics.json` per run: `iterations`, `total_cost_usd`, `latency_ms`.
- [ ] Commit: `git commit -m "day40: mini-capstone dev-hint-agent pipeline"`.

**Extension (optional):** Add tool-calling — `generate` may call `bash` (to compile the suggestion); `self_review` evaluates based on compiler output instead of LLM opinion. That makes the evaluation deterministic.
