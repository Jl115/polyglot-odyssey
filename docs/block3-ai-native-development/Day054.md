## 📖 Theory

Ethics in ML is *not* a philosophy seminar but engineering practice: bias tests in CI, model cards as artifacts, audit trails for regulators. In the EU region parts of this are *legally* binding (EU AI Act, in force since August 2024, fully applicable from 2026).

### EU AI Act — risk classes

| Class | Examples | Duties |
|---|---|---|
| **Unacceptable** (prohibited) | social scoring, manipulative AI | ban |
| **High-risk** | HR, biometrics, justice, medical | conformity assessment, risk management, data governance, logging, humans-in-the-loop, model card |
| **Limited risk** | chatbots, deepfakes | transparency duty ("you are talking to an AI") |
| **Minimal risk** | spam filter, recommendations | none |

An "AI dev tool" that evaluates code PRs and possibly rejects them → high-risk-like (can have job relevance). Transparency, audit logs, HITL are good practice even for minimal risk.

### Fairness metrics

Given: model predictions `ŷ`, true labels `y`, sensitive group `A` (e.g. language of the PR author, experience level).

| Metric | Definition | Fair when |
|---|---|---|
| **Demographic Parity** | `P(ŷ=1|A=0) == P(ŷ=1|A=1)` | ~equal |
| **Equal Opportunity** | `P(ŷ=1|y=1,A=0) == P(ŷ=1|y=1,A=1)` | true-positive rate equal per group |
| **Equalized Odds** | TPR and FPR equal per group | stricter |
| **Disparate Impact** | `min(P(ŷ=1|A)) / max(P(ŷ=1|A))` | ≥ 0.8 (4/5 rule) |

```python
import pandas as pd
def disparate_impact(df, pred_col, group_col):
    rates = df.groupby(group_col)[pred_col].mean()
    return rates.min() / rates.max()

# DI < 0.8 → alert; > 1.0 → reverse bias
```

### Bias test pipeline in CI

```python
# tests/test_fairness.py
def test_disparate_impact():
    df = pd.read_csv("eval_results.csv")  # y_pred, y_true, group
    di = disparate_impact(df, "y_pred", "language")
    assert di >= 0.8, f"DI={di:.3f} < 0.8 → possible discrimination"
```

### Model Cards (Mitchell et al., 2019)

A model card is a standardized document summarizing *what the model can do*, *where it fails*, *which data*, *which ethics risks*. Mandatory for HF Hub.

```markdown
# Dev-Hint-Model v0.3

## Intended Use
Code hints for Rust/TS developers.

## Out-of-Scope
No legal, medical, or financial advice.

## Eval
- BLEU: 18.1 (in-domain), 9.2 (OOD Python)
- LLM-Judge-Score: 4.1/5
- Fairness DI (language): 0.87

## Risks
- Hallucination on unknown APIs (rate: ~12%)
- Bias in favor of English questions (DI=0.91)

## Data
- 200 curated Rust FAQ examples (self-created)
- 30 gold eval examples, kept secret
```

### Why this matters

- **Legally:** the EU AI Act has fines up to 7% of global revenue. Ignorance is no defense.
- **Engineering quality:** bias tests in CI are *tests* — they catch regressions before users experience them.
- **Trust:** a dev tool that rejects PRs *must* be traceable and contestable. Without an audit trail it is a black box.
- **Professional ethics:** as an engineer you carry responsibility for what you ship. "The model said so" is not a defense.

### Pitfalls

- **"We have no sensitive attributes"** — language, experience, PR size, repo language are *all* potentially sensitive. Do sensitive-attribute analysis *upfront*.
- **DI threshold hardened:** 0.8 is a rule of thumb, not law. Calibrate by context; stricter for high-stakes.
- **Bias tests forgotten after deployment:** drift (Day 52) can *create* bias. Repeat bias tests regularly, not once.
- **Model card lies:** sugar-coating metrics → liability-relevant. Document honest limits.
- **"AI tool as HR score"** — a PR-reviewer agent that decides "mergeable y/n" is effectively HR-adjacent. Transparency and HITL mandatory.
- **LLM-specific:** LLM-based tools inherit bias *from the base model*. Your own fine-tuning doesn't automatically mitigate it — must be measured explicitly.

**Task:** Write (1) a fairness test for your Day 46 model on language/domain, (2) a model card for the model, (3) an EU AI Act classification of your capstone dev tool.

**Step by step:**

1. Extend the eval set (Day 48) with a group column: e.g. `language: rust|python|general`, 10 examples each.
2. Inference for all 30 → predictions; `eval_results.csv` with `y_pred`, `y_true`, `language`.
3. Fairness script `fairness.py`:

   > **Hints:**
   > - Load `eval_results.csv` with pandas and binarize predictions (`score >= 4` → `y_pred_bin`) so disparate impact is computable.
   > - Compute disparate impact across the `language` group with your `disparate_impact` helper (ratio of group success rates); print `DI(language) = X.XXX`.
   > - Emit an `ALERT: possible discrimination` line when DI < 0.8 — the CI test (step 6) will fail on this same threshold.
4. Write a model card `MODEL_CARD.md` (template above), honestly — including *Risks* and *Out-of-Scope*.
5. EU AI Act classification: in writing in `ethics.md`:
   - Which risk class does your capstone dev tool fall under?
   - Which duties apply? (logging, HITL, transparency, audit trail)
   - 3 concrete measures you implement in the capstone.
6. Bias test in CI (Day 51): in `tests/test_fairness.py` as a `pytest` that runs in GH Actions.
