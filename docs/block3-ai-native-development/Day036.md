## 📖 Theory

LangGraph (from LangChain) models LLM workflows as **directed graphs**: each node is a function that reads and writes a shared **State**; each edge decides which node runs next. This solves three problems of classic prompt chains:

1. **Cycles & retry:** a graph can jump back to an earlier node (e.g. "rewrite → retry" on tool failure) — a chain cannot.
2. **Conditional routing:** `conditional_edges` choose the next node based on state, not blindly by order.
3. **Persistence:** checkpointers store state per `thread_id`, so long-running agents can be paused/resumed or interrupted via human-in-the-loop.

### State: the shared memory

The state is a `TypedDict` class. Each node returns a **partial** of the state — LangGraph merges it automatically. For reducers (e.g. append to a list instead of overwriting) use `Annotated[list, operator.add]`.

```python
from typing import TypedDict, Annotated
from operator import add

class AgentState(TypedDict):
    question: str
    research: Annotated[list[str], add]   # append, not overwrite
    draft: str
    iterations: int
```

### Nodes and edges

A node is a function `state -> partial_state`. Edges can be fixed (`add_edge(A, B)`) or conditional (`add_conditional_edges(A, router_fn, {"yes": B, "no": C})`).

```python
from langgraph.graph import StateGraph, START, END

def research(state: AgentState) -> dict:
    q = state["question"]
    return {"research": [f"Fact about: {q}"]}   # append via add reducer

def draft(state: AgentState) -> dict:
    facts = "\n".join(state["research"])
    return {"draft": f"Answer based on:\n{facts}", "iterations": state["iterations"] + 1}

def quality_gate(state: AgentState) -> str:
    return "ok" if len(state["draft"]) > 20 else "rewrite"

g = StateGraph(AgentState)
g.add_node("research", research)
g.add_node("draft",   draft)
g.add_edge(START, "research")
g.add_edge("research", "draft")
g.add_conditional_edges("draft", quality_gate, {"ok": END, "rewrite": "research"})
app = g.compile()
```

### Why this matters

The block outcome is an *AI Dev Tool with GitHub integration* — i.e. an agent that reads code, analyzes it, comments on PRs, and iterates as needed. Pure chains fail the moment a step needs to "try again". LangGraph is the de-facto standard for such agent loops in Python (ReAct, Plan-Execute, Reflexion are built on it).

### Pitfalls

- State fields without a reducer are **overwritten**, not merged — lists vanish if you forget `Annotated[..., add]`.
- `app.invoke(...)` is synchronous and blocks; for streaming/HITL use `app.astream(...)` or `app.astream_events(...)`.
- Every node **must** be able to produce a value for every state key it reads — otherwise a KeyError on the first run.
- `compile(interrupt_before=["draft"])` pauses *before* the node — useful for human-in-the-loop, but forgetting it means the agent stops for no apparent reason.

## 🛠️ Practice

**Task:** Build the 3-node workflow *research → analysis → answer* with a conditional edge that jumps back to research when the answer is insufficient (max 2 iterations).

**Step by step:**

1. Create the project:

   ```bash
   mkdir day36 && cd day36
   python -m venv .venv && source .venv/bin/activate
   pip install "langgraph>=0.2" langchain-anthropic python-dotenv
   echo "ANTHROPIC_API_KEY=sk-..." > .env   # or OpenAI
   ```

2. Create `graph.py` with the state, the three nodes, and the `quality_gate` edge (snippets above).
3. For the LLM-backed nodes, wire a `ChatAnthropic` (or `ChatOpenAI`) client
   into each node so the research and analysis steps produce real model output
   instead of hardcoded strings:

   > **Hints:**
   > - Instantiate `ChatAnthropic(model="claude-3-5-haiku-latest")` (or `ChatOpenAI`) once at module level.
   > - Inside each node, call `llm.invoke(prompt_string).content` to get the model's text response.
   > - Each node still returns a **partial state dict** (e.g. `{"research": [msg]}`) — the graph merges it via the reducer.
   > - Remember the `Annotated[list, add]` reducer so research facts **append**, not overwrite.
4. Add an iteration limit: in `quality_gate` check `if state["iterations"] >= 2: return "ok"` — otherwise infinite loop.
5. Run it:

   ```bash
   python -c "from graph import app; print(app.invoke({'question':'What is io_uring?','iterations':0}))"
   ```

6. Enable persistence: `from langgraph.checkpoint.memory import MemorySaver; app = g.compile(checkpointer=MemorySaver())`, then call with `config={"configurable":{"thread_id":"t1"}}` — the state survives interpreter restarts within the same thread.

**Definition of Done (DoD):**

- [ ] `python graph.py` runs without ImportError.
- [ ] `app.invoke({...})` terminates (no infinite loop) and contains `draft` in the output state.
- [ ] The conditional edge is visible in the graph: `print(app.get_graph().draw_mermaid())` shows `draft -->|rewrite| research`.
- [ ] With `iterations >= 2` the loop breaks cleanly ("ok" branch).
- [ ] Checkpointer works: a second `invoke` with the same `thread_id` sees the previous state.
- [ ] Commit: `git commit -m "day36: langgraph state machine with retry loop"`.

**Extension (optional):** Visualize the graph with `app.get_graph().draw_mermaid_png("graph.png")` and add the image to the repo.
