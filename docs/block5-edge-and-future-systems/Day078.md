---

## 📖 Theory

An ML compiler must run the *same* model on dozens of backends (x86 AVX, ARM Neon, RISC-V V, CUDA, edge NPUs). Classical compilers (LLVM) are optimized for generic languages (C/C++), not for tensor graphs. **MLIR** and **TVM** close this gap.

### MLIR — Multi-Level Intermediate Representation

MLIR (from LLVM, initiated by Google/Chris Lattner) is a **framework for dialects**. Instead of a fixed IR, you define dialects (`linalg` for linear algebra, `tensor`, `affine`, `gpu`, `rvv` for RISC-V Vector...) and **passes** that lower between dialects ("progressive lowering").

```
high-level:  linalg.matmul + tensor
    ↓  --convert-linalg-to-affine
mid:         affine loops + memref
    ↓  --convert-affine-to-cf
low:         LLVM dialect
    ↓  --convert-to-llvmir
LLVM IR → Asm → Machine Code
```

A model can be lowered step by step from the conceptual (tensor graph) down to the machine — every step *verifiable*, every dialect *typed*.

### Apache TVM — the end-to-end ML compiler

TVM (Apache) takes models from TF/PyTorch/ONNX and generates optimized code for **dozens of targets**:

```
[ ONNX/TF/PyTorch ]
    ↓  Relay Frontend
[ Relay IR (functional tensor graph) ]
    ↓  AutoTVM / Ansor (auto-tuning of loop schedules)
[ Lowered Tensor IR ]
    ↓  Build
[ Target: CUDA / LLVM (x86, ARM, RISC-V) / C / WASM ]
```

**AutoTVM/Ansor** automatically searches for the best loop schedules (tiling, unroll, vectorization) for the respective target — that is the "auto-tuner" core.

### In practice: ONNX → TVM → C

```python
import onnx
import tvm
from tvm import relay

model = onnx.load("model.onnx")
mod, params = relay.frontend.from_onnx(model)

target = tvm.target.Target("llvm -mtriple=riscv64-unknown-linux-gnu -mattr=+v")

with tvm.transform.PassContext(opt_level=3):
    lib = relay.build(mod, target=target, params=params)

# Generate C source instead of a binary (portable for edge)
lib.export_library("model.c", tvm.contrib.csource.create_csource_executor)
```

### Why this matters

Every edge device has a different accelerator architecture — hand-tuning for every target is uneconomical. MLIR/TVM automate lowering + tuning and make models portable. Anyone shipping ML at the edge today mostly uses Relay/TVM (or MLIR-based tools like IREE). Block 5 builds the edge-to-cloud pipeline; this is the *compiler layer* in between.

### Pitfalls

- **AutoTVM is slow:** a tuning run can take hours. For initial experiments disable tuning; it only pays off for the final version.
- **Check the target triple:** `"llvm -mtriple=..."` must match the TVM build (TVM must have been compiled with `LLVM` support and possibly a RISC-V backend — `pip install apache-tvm` usually only covers x86).
- **Relay ≠ Relay VM:** there is the graph executor (`relay.build`) and the newer Relay VM (`relay.vm.compile`) — the VM is more flexible (also dynamic shapes), the graph executor faster for static shapes.
- **Memory:** edge C code often needs a static workspace; TVM allocates by default — for bare-metal use `tvm.contrib.csource` with `--system-lib`.

## 🛠️ Practice

**Task:** Take a small ONNX model (e.g. a `MobileNetV2` or your own `linear` layer), compile it with TVM to **C code**, and compile the generated C code standalone.

**Step by step:**

1. Install TVM (recommended via pip, only for x86/LLVM C codegen):

   ```bash
   pip install apache-tvm onnx
   ```

2. Load a test model (e.g. from the `onnx` model zoo) or create one yourself:

   > **Hints:**
   > - Define a minimal `torch.nn.Module` (e.g. a single `nn.Linear` layer) and export it with `torch.onnx.export` — pass a dummy `torch.randn` input and name the inputs/outputs.
   > - Alternatively, download a small model from the ONNX Model Zoo.

3. Compile with TVM and generate C source:

   > **Hints:**
   > - Load the ONNX model and parse it with `relay.frontend.from_onnx` to get the Relay module + params.
   > - Use `tvm.transform.PassContext(opt_level=3)` and `relay.build` with `target="c"` to get a graph executor library.
   > - Export to a `.c` file via `lib.export_library("model.c", tvm.contrib.csource.create_csource_executor)`.
4. Inspect `model.c`: `wc -l model.c` — you see generated C functions (`__tvmgen__*`).
5. Build a minimal C harness that fills the input tensor, calls `run`, and prints the output.
6. Compile: `gcc model.c harness.c -o model -I.` — run it.

**Definition of Done (DoD):**

- [ ] `model.c` is generated and contains TVM-generated C functions (proof: `grep -c '__tvmgen__' model.c` ≥ 1).
- [ ] Your C harness runs and reproduces the ONNX reference output (compare with `onnxruntime` on the same input) to 2 decimal places.
- [ ] You can name the lowering path: ONNX → Relay IR → (TIR) → C code.
- [ ] You tried `target="llvm"` instead of `"c"` once and can explain why `c` is more portable for edge/bare-metal.
- [ ] Commit: `git commit -m "day78: tvm onnx->c compilation"`.

**Extension (optional):** Enable AutoTVM for a Conv2D model (`tvm.autotvm.tune`), measure runtime before/after tuning — the difference is the value of the autotuner.
