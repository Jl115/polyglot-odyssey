---

## 📖 Theory

"The best language" does not exist — there is only *the best language for a context*. A Language Choice Matrix is a **structured decision framework** that replaces subjective preference with measurable criteria.

### The five axes

| Axis | What it measures | Metric |
|-------|--------------|-----------|
| Performance | compute throughput, latency | bench (Day 88): RPS, ns/op, p99 |
| Memory safety | compile-time guarantees | CVE history, ownership model |
| Ecosystem | libraries, tooling | `crates.io` count, package quality |
| Latency profile | p99, tail, determinism | `criterion` p99, `hyperfine` stddev |
| Productivity | iteration speed, onboarding | LOC/feature, build time, hot reload |

|---------|------------|--------------|----------|-----------|-------------|----------|

### Decision path patterns

1. **Performance-critical core** → Rust (safety + speed). C/Zig only with an existing C codebase.
2. **Distributed service** → Go (concurrency model, build speed, binaries).
3. **User-facing UI** → TypeScript (web) or Dart (cross-platform desktop/mobile).
4. **ML training/notebook** → Python (ecosystem, not performance).
5. **Edge inference** → Rust + WASM (Day 79) or C/C++ + TinyML (Day 76).
6. **Legacy system / kernel** → C; new kernel modules: Rust (Day 83).

### Tradeoff triangles

No language is top everywhere. Three fundamental tradeoffs:

```
        Performance
           /\
          /  \
         /    \
  Safety ------ Productivity
```

- Rust optimizes performance + safety, sacrifices productivity.
- Go optimizes productivity + safety, sacrifices performance.
- C optimizes performance + ecosystem, sacrifices safety.

Choosing a language means choosing *which side of the triangle to sacrifice*.

### Why this matters

Polyglot engineering means choosing the right language for every subsystem — and *justifying* it. This matrix is the tool you will use in architecture reviews, hiring interviews, and vendor evaluations. Day 90 (Multi-Language System) is the practical application of the matrix.

### Pitfalls

- **Outdated numbers** — languages evolve; Go's generics (1.18), Python's `uvloop`, Rust's async-gen2 have shifted the landscape. Update the matrix yearly.
- **"Ecosystem" is not "GitHub stars"** — quality > quantity. Rust has fewer crates than Python packages, but often higher quality per crate (`cargo` tooling).
- **Team capability** — the best language is useless if nobody knows it. Multiply by a team-skill factor.
- **Vendor lock-in** — Go binaries are portable; Python needs a runtime + packages. Deployment complexity is a hidden cost.
- **Latency vs. throughput** — Go has high throughput, but p99 latency can be 10× higher than Rust due to GC pauses. For real-time: Rust/Zig.
