## 📖 Theory

**Lock-free** means: at least one thread always makes progress — regardless of the scheduler. No thread can block the progress of all others (as a `Mutex` can when the holder is preempted). The foundation is **atomic operations** with well-defined memory orderings.

### Atomics & memory ordering

Rust's `std::sync::atomic` provides `AtomicUsize`, `AtomicBool`, …:

```rust
use std::sync::atomic::{AtomicUsize, Ordering};
let x = AtomicUsize::new(0);
x.store(1, Ordering::Relaxed);            // no synchronization promise
x.fetch_add(1, Ordering::SeqCst);         // globally consistent order
let prev = x.compare_exchange(
    1,                      // expected
    2,                      // new
    Ordering::Acquire,      // success
    Ordering::Relaxed       // failure
).is_ok();                  // true if x was 1 before → now 2
```

| Ordering | What it promises | When to use |
|----------|------------------|-----------|
| `Relaxed` | atomicity only | counters, no cross-var sync |
| `Acquire`/`Release` | release-acquire synchronization | locks, producer-consumer |
| `SeqCst` | global total order | rarely needed, expensive |

### The MS-queue (Michael-Scott)

Classic lock-free FIFO queue: a linked list of CAS-linked nodes.

```rust
use std::sync::atomic::{AtomicUsize, AtomicPtr, Ordering};
use std::ptr;

struct Node<T> { data: T, next: AtomicPtr<Node<T>> }

pub struct MsQueue<T> {
    head: AtomicPtr<Node<T>>,
    tail: AtomicPtr<Node<T>>,
}

impl<T> MsQueue<T> {
    pub fn new() -> Self {
        let stub = Box::into_raw(Box::new(NodeStub));
        Self { head: AtomicPtr::new(stub), tail: AtomicPtr::new(stub) }
    }

    pub fn push(&self, v: T) {
        let node = Box::into_raw(Box::new(Node { data: v, next: AtomicPtr::new(ptr::null_mut()) }));
        let tail = self.tail.load(Ordering::Acquire);
        unsafe { (*tail).next.store(node, Ordering::Release); }
        self.tail.store(node, Ordering::Release);   // (simplified: without CAS-hazard, see sources)
    }
}
```

Fully correct, the MS-queue is a few dozen lines — the above is the core; the *CAS-retry* and the *helping* when the tail lags are missing (see practice step & sources). `unsafe` is necessary because you atomically move raw pointers and the compiler cannot prove the lifetime.

### Why not just `Mutex`?

`Mutex<VecDeque>` is correct and often fast enough — but:

- Under high contention (8+ threads) the contended mutex path gets expensive (syscall `futex`/`ulock`).
- Latency tail: a thread holding the mutex and getting preempted blocks all others → p99 explodes.
- Real-time/kernel paths must not sleep → `Mutex` is off-limits.

### The ABA problem

Lock-free algorithms have a subtle enemy: **ABA**. Thread A reads value `A`, wants to CAS to `B`. Meanwhile `A → B → A` happens (via other threads). The CAS from A to `B` "succeeds" even though state changed. Solution: `AtomicUsize` with a version tag (`AtomicU64` as ptr+version) or hazard pointers / epoch-based reclamation (crossbeam-epoch).

### Why this matters

Lock-free structures are the performance core of the high-performance server (Day 85) and the polyglot runtime (Day 90). They avoid scheduler dependence and are the basis for io_uring completion queues and kernel circular buffers.

### Pitfalls

- **`unsafe` is not optional** — correct lock-free structures in Rust need raw pointers.
- **Memory reclamation is the real problem** — not the CAS, but "when can the old node be freed?". Use `crossbeam-epoch` or `crossbeam_skiplist`.
- **Wrong ordering = UB** — `Relaxed` for cross-var sync is a bug that only shows up under load (and only there).
- **Don't bench with 1 thread** — lock-free overhead is *higher* than a mutex at 1 thread; the win only comes under contention.

**Step by step:**

1. `cargo new day82 --bin`, `cargo add crossbeam-queue rayon criterion`.
2. In `src/main.rs`, implement two benchmark functions:

   > **Hints:**
   > - Write `bench_lockfree()` that creates a `SegQueue`, spawns 8 threads via `thread::scope`, and each thread pushes + pops `OPS/8` items. Time with `Instant::now()` / `elapsed().as_millis()`.
   > - Write `bench_mutex()` doing the same with a `Mutex<VecDeque>` — `push_back` then `pop_front`.

5. Vary thread count: 1, 2, 4, 8, 16 — record in a table.
