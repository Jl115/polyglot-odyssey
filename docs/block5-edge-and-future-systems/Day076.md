## 📖 Theory

**TinyML** is ML inference on microcontrollers with kilobytes of RAM and a milliwatt power budget — no Python runtime, no operating system, often no floating-point unit. This forces **quantization** (int8 instead of float32) and **pruning**.

### The TinyML stack

```
[ Training (PC/GPU) ]
        ↓  export
[ TensorFlow SavedModel / ONNX ]
        ↓  quantize (int8)
[ TFLite .tflite ]
        ↓  TFLite Micro (C++ static lib, no allocator)
[ Firmware for ESP32 / RP2040 / Cortex-M ]
```

Three layers reduce the footprint:

1. **Architecture choice:** small networks (MobileNetV2-0.35, EfficientNet-Lite, DS-CNN).
2. **Post-training quantization:** float32 → int8 (~4× smaller, 2-4× faster on Cortex-M with DSP).
3. **TFLite Micro interpreter:** static tensor-arena buffer, no `malloc` at runtime.

### Quantization in practice

```python
# Conversion + int8 quantization (full integer)
import tensorflow as tf

converter = tf.lite.TFLiteConverter.from_saved_model("saved_model/")
converter.optimizations = [tf.lite.Optimize.DEFAULT]

# Representative data for activation quantization
def rep_data():
    for x in train_ds.take(100):
        yield [x[0].numpy().astype('float32')]
converter.representative_dataset = rep_data

# Force int8-only (no float fallback)
converter.target_spec.supported_ops = [tf.lite.OpsSet.TFLITE_BUILTINS_INT8]
converter.inference_input_type = tf.int8
converter.inference_output_type = tf.int8

tflite_int8 = converter.convert()
open("model_int8.tflite", "wb").write(tflite_int8)
```

### Inference in C++ (TFLite Micro)

```cpp
#include "tensorflow/lite/micro/micro_interpreter.h"
#include "tensorflow/lite/micro/micro_mutable_op_resolver.h"
#include "model_int8.h"  // xxd -i model_int8.tflite > model_int8.h

constexpr int kTensorArenaSize = 64 * 1024;  // 64 KB static buffer
uint8_t tensor_arena[kTensorArenaSize];

int main() {
  const tflite::Model* model = tflite::GetModel(model_int8_tflite);
  tflite::MicroMutableOpResolver<10> resolver;
  resolver.AddConv2D();
  resolver.AddFullyConnected();
  // ... further ops from the model

  tflite::MicroInterpreter interpreter(model, resolver, tensor_arena);
  interpreter.AllocateTensors();

  TfLiteTensor* input = interpreter.input(0);
  // ... fill input (int8 quantized)
  interpreter.Invoke();
  TfLiteTensor* output = interpreter.output(0);
  // read output
}
```

### Why this matters

Edge devices produce data at the source (sensor, camera) — round-trips to the cloud cost latency, bandwidth, and privacy. TinyML makes inference *on-device* possible and is the typical Block 5 building block for the edge-to-cloud pipeline: the edge filters, the cloud aggregates.

### Pitfalls

- **int8 quantization can cost accuracy** — always use a representative dataset (≥100 real samples), otherwise activation scales get miscalibrated.
- **TFLite Micro without `malloc`** — the tensor arena must be large enough at compile time; `interpreter.AllocateTensors()` fails at runtime otherwise.
- **Not every op is supported by Micro** — check `MicroMutableOpResolver`; if an op is missing → linker error.
- **ESP32 has no int8 DSP** — NPU vector instructions are Cortex-M55/M85-specific; on an ESP32, int8 is often *not* faster than float.

## 🛠️ Practice

**Task:** Take a pretrained `MobileNetV2` (ImageNet or a small keyword-spotting model), quantize it to int8, and measure inference time in C++.

**Step by step:**

1. **Host path (no hardware):** Install the toolchain:

   ```bash
   pip install tflite-runtime tensorflow
   ```

2. Download a pretrained model (e.g. `mobilenet_v2_1.0_224` from TF Hub) and run the conversion script above.
3. Compare sizes: `ls -l model_int8.tflite` vs. the float32 original (~3-4× smaller expected).
4. **Inference test on the host** with `tflite-runtime`:

   > **Hints:**
   > - Create a `tflite.Interpreter` from `model_int8.tflite` and call `allocate_tensors()`.
   > - Use `get_input_details()` to learn the input tensor's index and shape; fill it with `set_tensor` (remember the dtype is `int8`).
   > - Warm up with ~10 `invoke()` calls, then time 100 iterations with `time.perf_counter()` and print the average ms/inference.
5. Optional **edge path:** If you have an RP2040/ESP32, build the TFLite Micro C++ code from the example and flash it; measure with `micros()` around the `Invoke()`.

**Definition of Done (DoD):**

- [ ] `model_int8.tflite` exists and is **≥ 3× smaller** than the float32 model (proof via `ls -l`).
- [ ] The host benchmark script runs and prints a concrete `ms/inference` number.
- [ ] You can explain in 2 sentences why int8 is faster on a Cortex-M4 with DSP, but not necessarily on an ESP32.
- [ ] You know your model's memory footprint (tensor-arena size in KB) and can read it via `tflite::MicroInterpreter::arena_used_kb()`.
- [ ] Commit: `git commit -m "day76: tinyml int8 quantization + host bench"`.

**Extension (optional):** Train a small keyword-spotting model yourself (e.g. on the Speech Commands dataset), quantize it, and reach < 20 KB `.tflite` — deployable on an RP2040.
