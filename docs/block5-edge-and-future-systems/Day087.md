# Day 87: Dart + Rust Desktop App

**Block:** Block 5: Edge & Future Systems · Cross-Platform Desktop

> **Goal of the day:** You build a Flutter desktop app that binds a Rust shared library via `dart:ffi` — a native function (e.g. image decode or crypto hash) is called from Dart.

---

## 📖 Theory

**Flutter** is Google's cross-platform UI toolkit (Dart language, its own rendering engine). For performance-critical parts (crypto, ML, codecs) Flutter uses **`dart:ffi`** — direct bindings to C-ABI shared libraries, the same mechanism as Day 86.

### Architecture

```
[ Flutter UI (Dart) ]
        ↓  dart:ffi  (DynamicLibrary.open)
[ Rust cdylib (.so/.dll/.dylib) ]
        ↓  extern "C"
[ Performance code: crypto / codec / ML ]
```

Advantages:

- **One UI codebase** for Linux/macOS/Windows/iOS/Android/Web.
- **Performance code in Rust** instead of C/C++ — memory-safe.
- **Direct FFI** without JSON-marshalling overhead (unlike platform channels).

### Minimal Dart FFI example

```dart
// lib/main.dart
import 'dart:ffi';
import 'dart:io' show Platform;
import 'package:ffi/ffi.dart';

typedef AddFunc = Int64 Function(Int64 a, Int64 b);
typedef AddFuncDart = int Function(int a, int b);

void main() {
  final libPath = Platform.isLinux
      ? './libday87.so'
      : Platform.isMacOS
          ? './libday87.dylib'
          : './day87.dll';
  final dylib = DynamicLibrary.open(libPath);

  final add = dylib.lookupFunction<AddFunc, AddFuncDart>('add');
  print('3 + 4 = ${add(3, 4)}');   // 7
}
```

### Rust side (same as Day 86)

```rust
// src/lib.rs
#[no_mangle]
pub extern "C" fn add(a: i64, b: i64) -> i64 { a + b }
```

### Strings across FFI: `Utf8` pointer

```dart
// Dart side: String → Pointer<Utf8>, don't forget to free
final greet = dylib.lookupFunction<GreetFunc, GreetFuncDart>('greet');
final namePtr = 'World'.toNativeUtf8();
final resultPtr = greet(namePtr);
print(resultPtr.toDartString());
malloc.free(namePtr);
// resultPtr must be freed by a Rust free function
```

### Enabling Flutter desktop

```bash
flutter config --enable-macos-desktop --enable-linux-desktop --enable-windows-desktop
flutter create app87
cd app87
flutter run -d macos   # or -d linux / -d windows
```

### Why this matters

Polyglot desktop today means: UI in Dart/Flutter, performance code in Rust. That is exactly the architecture used by e.g. 1Password, Bitwarden mobile, Rive, and parts of the Flutter engine itself. Day 90 (Multi-Language System) builds on exactly this pattern.

### Pitfalls

- **`DynamicLibrary` path** — Flutter runs from different working dirs; relative paths break. Use `Platform.resolvedExecutable` + `path.join` or bundle the lib into the `assets/` directory.
- **Keep memory ownership clear** — Dart's GC does not know about Rust memory. Every `lookup` function that allocates needs a `free_*` counterpart.
- **Isolates** — Dart is single-threaded with isolates; FFI calls are synchronous and block the UI isolate. For long-running calls: wrap in `Isolate.run` or async Rust via callback.
- **Hot reload breaks FFI** — the Rust shared lib must be reloaded manually; hot reload caches the `DynamicLibrary`.
- **Threading** — Rust code that spawns threads must consider the Flutter isolate lifetime: runtime drop = isolate end.

## 🛠️ Practice

**Task:** Build a Flutter desktop app with a text field that passes input to Rust and gets back a SHA-256 hash (Rust `sha2` crate) and displays it.

**Step by step:**

1. **Rust lib:** `cargo new --lib day87lib`, `cargo add sha2 hex`, `crate-type = ["cdylib"]`. Implement the FFI functions yourself:

   > **Hints:**
   > - `hash_sha256(input: *const i8) -> *mut i8`: convert the raw pointer to a Rust string via `CStr::from_ptr` (in an `unsafe` block), compute SHA-256 with `Sha256::new()` / `.update()` / `.finalize()`, hex-encode the digest, and return it as a `CString::new(out).unwrap().into_raw()` (caller must free).
   > - `free_rust_string(p: *mut i8)`: reclaim the `CString` with `CString::from_raw(p)` so Rust can drop it.
   > - Mark both functions `#[no_mangle] pub extern "C"`.
   > - Add `crate-type = ["cdylib"]` to `Cargo.toml`.
2. `cargo build --release`.
3. **Flutter app:** `flutter create app87`, then `flutter pub add ffi`.
4. In `lib/main.dart` a simple UI (TextField + ElevatedButton + Text for output) that loads the Rust lib, calls `hash_sha256`, shows the result, and calls `free_rust_string`.
5. Copy `libday87lib.dylib` next to the Flutter binary or adjust the path.
6. `flutter run -d macos` → type "hello", click the button → see the SHA-256.
7. Verify: `echo -n hello | shasum -a 256` in the shell should yield the same hash.

**Definition of Done (DoD):**

- [ ] Rust `cdylib` compiles and `nm libday87lib.dylib | grep hash_sha256` shows the export.
- [ ] Flutter desktop app runs (macOS or Linux/Windows) and shows a TextField+Button UI.
- [ ] Input "hello" → SHA-256 output `2cf24dba5fb0a30e26e83b2ac5b9e29e1b161e5c1fa7425e73043362938b9824` (or analogous).
- [ ] `free_rust_string` is called after every display (proof: app runs memory-stable over 1000 clicks).
- [ ] You can explain in 2 sentences why `dart:ffi` is faster than Flutter platform channels (no JSON marshalling, direct call).
- [ ] Commit: `git commit -m "day87: flutter desktop + dart:ffi + rust sha256"`.

**Extension (optional):** Use `flutter_rust_bridge` (a code generator that auto-generates Dart bindings from Rust) instead of hand-written FFI — compare comfort and overhead. Alternative: asynchronous call via `Isolate.run` for long inputs.
