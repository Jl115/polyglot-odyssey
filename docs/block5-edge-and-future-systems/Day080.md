# Day 80: Mini-Capstone: Edge-to-Cloud

**Block:** Block 5: Edge & Future Systems · Capstone

> **Goal of the day:** You build a minimal pipeline: an edge module (WASM) reads sensor data, aggregates it, and sends it to a cloud endpoint; the cloud part persists it. You prove end-to-end function with real data.

---

## 📖 Theory

The **edge-to-cloud pipeline** is the recurring architecture pattern of Block 5: edge devices filter / aggregate / run inferences *on-device* (low latency, privacy, bandwidth), and send only the condensed data to the cloud. The cloud does long-term storage, batch training, and global aggregation.

### The three layers

```
[ Edge (Device) ]                [ Gateway ]                 [ Cloud ]
  Sensor/ML-inference   --mqtt/http-->  Aggregator    --http-->  Store & Dashboard
  WASM sandbox             (K8s edge / bare)             (Postgres + API)
```

Three design decisions shape the pipeline:

1. **What runs at the edge vs. cloud?** Heuristic: what is *time-critical* (filtering, anomaly detection) at the edge; what is *data-rich* (training, history) in the cloud.
2. **Which protocol?** MQTT for sporadic low-bandwidth sensors, HTTP/gRPC for deterministic calls, QUIC for unstable links.
3. **Which data format?** JSON for debugging/interop, Protobuf/FlatBuffers for performance, Arrow for analytics.

### Edge module (Rust + WASI)

```rust
use std::fs;
fn main() {
    let raw = fs::read_to_string("/data/sensor.txt").unwrap();
    let temps: Vec<f64> = raw.lines()
        .filter_map(|l| l.parse().ok())
        .collect();
    let avg = temps.iter().sum::<f64>() / temps.len() as f64;
    let payload = format!("{{\"avg\":{:.2},\"n\":{}}}", avg, temps.len());
    // POST via wasi-http (capability-gated)
    println!("{}", payload);  // for the capstone stdout → cloud endpoint reads it
}
```

### Cloud endpoint (Rust + Axum)

```rust
use axum::{routing::post, Router, extract::State};
use std::sync::Arc;

#[derive(Clone)] struct Db(Arc<tokio::sync::Mutex<Vec<String>>>);

async fn ingest(State(db): State<Db>, body: String) -> &'static str {
    db.0.lock().await.push(body);
    "ok"
}

#[tokio::main]
async fn main() {
    let db = Db(Arc::new(tokio::sync::Mutex::new(vec![])));
    let app = Router::new().route("/ingest", post(ingest)).with_state(db);
    let listener = tokio::net::TcpListener::bind("127.0.0.1:8080").await.unwrap();
    axum::serve(listener, app).await.unwrap();
}
```

### Why this matters

This is the miniature version of exactly the outcome the block promises (`edge-to-cloud pipeline`). You connect Day 76–79 (TinyML/RISC-V/TVM/WASM) with the cloud part from Block 3 (K8s/HTTP services) — and make explicit the architecture decisions a polyglot engineer must make.

### Pitfalls

- **No real sensors needed:** simulate sensor data via a file or environment variable. Hardware integration is an extension.
- **Test order:** the edge module *must* be tested against a running cloud endpoint — otherwise the HTTP call fails silently.
- **WASM HTTP is host-provided:** pure `std::net` is not available in `wasm32-wasip1`. Use the `wasi-http` component interface or let the edge app write to stdout and pipe it to `curl`.
- **Timezones/timestamps:** edge devices often have no RTC — use cloud time in the payload or add NTP.

## 🛠️ Practice

**Task:** Build the edge-to-cloud pipeline from two parts: (1) a WASM edge module aggregates sensor values; (2) an Axum cloud endpoint persists them. Prove end-to-end with 3 real values.

**Step by step:**

1. **Cloud part:** `cargo new cloud --bin`, `cargo add axum tokio -F tokio/full`. Code from the example above. Start: `cargo run --bin cloud` → listens on `:8080/ingest`.
2. Test manually: `curl -d '{"avg":23.4,"n":10}' http://localhost:8080/ingest` → `ok`.
3. **Edge part:** `cargo new edge --bin`. Code reads `/data/sensor.txt`, computes avg, prints JSON to stdout. Build `cargo build --release --target wasm32-wasip1`.
4. Generate sensor data: `printf "23.1\n23.3\n23.0\n" > /tmp/sensor.txt`.
5. **Wiring** (piped variant without wasi-http, simple & robust):
   ```bash
   wasmtime --dir=/tmp::/data target/wasm32-wasip1/release/edge.wasm \
     | xargs -I{} curl -d {} http://localhost:8080/ingest
   ```
6. Verify: after 3 runs, check in the cloud part that 3 records are stored (log or endpoint `/dump`).

**Definition of Done (DoD):**

- [ ] Cloud endpoint runs on `127.0.0.1:8080` and answers `ok` to POST `/ingest`.
- [ ] Edge module compiles to `wasm32-wasip1` and outputs valid JSON `{"avg":..,"n":..}`.
- [ ] End-to-end: 3 sensor values yield one stored record with the correct avg after a pipeline run.
- [ ] You can justify every architecture decision in 1 sentence (why edge aggregation, why HTTP, why JSON).
- [ ] You provoked a failure pipeline (edge without cloud → HTTP error) and documented the behavior.
- [ ] Commit: `git commit -m "day80: edge-to-cloud capstone (wasm edge + axum cloud)"`.

**Extension (optional):** Replace stdout piping with real `wasi-http` outbound calls via the Wasmtime component model. Alternative: edge writes to an MQTT broker (`rumqttc` crate native, no WASM).
