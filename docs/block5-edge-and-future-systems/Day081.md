## 📖 Theory

`async fn` in Rust creates **no** thread and **starts nothing**. It returns a `Future` — a state-machine value that is only *pollable*. Only an **executor** (Tokio, async-std, smol) polls the future and drives it forward until it returns `Poll::Ready`.

### The Future trait

```rust
trait Future {
    type Output;
    fn poll(self: std::pin::Pin<&mut Self>, cx: &mut Context<'_>) -> Poll<Self::Output>;
}

enum Poll<T> { Ready(T), Pending }
```

When a future returns `Poll::Pending`, it must signal the executor once progress is possible — via the **Waker** (`cx.waker().wake()`). That is the "wait state" mechanism.

### async/await = state machine

```rust
async fn fetch() -> u32 {
    let a = step1().await;   // await point 1
    let b = step2(a).await;  // await point 2
    a + b
}
```

Compiles (simplified) to:

```rust
enum FetchFut { Start, AwaitingStep1(Step1Fut), AwaitingStep2(u32, Step2Fut), Done }
impl Future for FetchFut { ... match on state ... }
```

Every `await` point is a potential **suspension point** — the task yields control to the executor, which polls another task. No OS thread switch, no locks.

### The Tokio runtime

Tokio consists of (1) a **scheduler** (work-stealing across worker threads), (2) an **I/O driver** (epoll/io_uring/kqueue → `mio`), (3) a **timer driver**.

```rust
#[tokio::main]                      // creates a multi-thread runtime
async fn main() {
    let h = tokio::spawn(async {     // task on the scheduler
        tokio::time::sleep(Duration::from_millis(50)).await;
        42
    });
    let v = h.await.unwrap();
    println!("{v}");
}
```

`tokio::spawn` is cheap (~100 bytes per task) — so a Tokio routine can carry **millions of tasks**, while OS threads are limited to thousands.

### Select / Join — concurrent futures

```rust
use tokio::time::{timeout, Duration};
let r = timeout(Duration::from_millis(100), slow_call()).await;
match r {
    Ok(v) => println!("got {v}"),
    Err(_) => println!("timed out"),
}
```

### Why this matters

The high-performance server (Day 85) and the edge-to-cloud pipeline (Day 80) need async — otherwise they don't scale. Async is also the basis for lock-free patterns (Day 82). Anyone using Rust seriously for servers/edge cannot avoid Tokio.

### Pitfalls

- **`.await` only in `async` context** — from synchronous code you need `block_on` or a runtime blocker.
- **`std::thread::sleep` in async blocks the worker thread** — use `tokio::time::sleep`.
- **`Send` bounds:** tasks moved between worker threads must be `Send` — `Rc`/`RefCell` in tasks break that.
- **`spawn_blocking` for CPU-bound/C-FFI** — blocking calls (e.g. `std::fs::read`) must not block the worker thread.
- **Runtime flavors:** `current_thread` (single-thread) vs. `multi_thread` — default is multi, for embeds often single.
- **Cancellation:** dropping the future = cancellation at the next await point. Cleanup must be idempotent.

## 🛠️ Practice

**Task:** Build a minimal TCP echo server with Tokio that handles every connection in a task. Benchmark with 10 000 concurrent connections via a `tokio` test harness or `hey`.

**Step by step:**

1. `cargo new day81 --bin`, `cargo add tokio -F full`.
2. In `src/main.rs`, implement the echo server:

   > **Hints:**
   > - Bind a `TcpListener` to `127.0.0.1:9000` inside `#[tokio::main] async fn main`.
   > - In a loop, `accept().await` each connection and `tokio::spawn` a task per socket (`async move`).
   > - Inside each task, loop reading into a fixed buffer (`AsyncReadExt::read`) — `Ok(0)` means EOF, so return; on success, echo back with `AsyncWriteExt::write_all`.
   > - Handle errors by simply returning from the task.
3. `cargo run`. Test in a 2nd terminal: `nc 127.0.0.1 9000` → type, gets echoed.
4. Benchmark: install `hey` (`go install github.com/rakyll/hey@latest`) or use a `tokio` test:

   ```bash
   hey -z 10s -q 1000 -c 100 http://127.0.0.1:9000/
   # or simply: for i in $(seq 1 1000); do (echo hi | nc -q1 127.0.0.1 9000 &); done
   ```

5. Measure active tasks: insert `tokio::task::yield_now` and count.
6. Variant: `#[tokio::main(flavor = "current_thread")]` — compare performance in the benchmark.

**Definition of Done (DoD):**

- [ ] Server runs on `127.0.0.1:9000` and echoes.
- [ ] 100 concurrent connections (via `nc &` loop) are all served — no deadlock.
- [ ] You can explain `Poll::Ready` vs `Poll::Pending` in one sentence and say who calls `wake()`.
- [ ] You can justify why `std::thread::sleep` in async freezes the server (reproduce it: let the server freeze, observe).
- [ ] Commit: `git commit -m "day81: tokio echo server + 1k connections"`.

**Extension (optional):** Extend with `select!` between TCP data and a 10-second idle timeout — the task terminates on inactivity. Benchmark p99 latency via `hey -t 10 -c 1000`.
