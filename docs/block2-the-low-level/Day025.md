**Block:** Block 2: The Low Level · Modern C++

---

## 📖 Theory

C++20 was the biggest expansion since C++11. The most important features for low-level engineering:

### Concepts — typed constraints instead of SFINAE

Before C++20: `template <typename T, typename = std::enable_if_t<...>>`. With concepts, readable:

```cpp
#include <concepts>

template <typename T>
concept Numeric = std::integral<T> || std::floating_point<T>;

template <Numeric T>
T square(T x) { return x * x; }
// square(std::string{}) → compile error with clear message "constraints not satisfied"
```

### Ranges — composable views

```cpp
#include <ranges>
#include <vector>
#include <algorithm>

std::vector<int> v = {1, 2, 3, 4, 5, 6};
auto result = v
    | std::views::filter([](int x){ return x % 2 == 0; })    // {2, 4, 6}
    | std::views::transform([](int x){ return x * x; })      // {4, 16, 36}
    | std::views::take(2);                                   // {4, 16}
// Lazy: views are only computed on iteration → 0 allocation.
```

### `std::format` — type-safe formatting

```cpp
#include <format>
std::string s = std::format("x={}, y={:.2f}", 42, 3.14159);   // "x=42, y=3.14"
std::cout << std::format("{:>10}\n", "hi");                    // right-aligned
```

Replaces the UB-prone `printf` (format-string type mismatch = UB). Rust's `format!` is the direct model.

### Coroutines (`co_await`/`co_yield`)

```cpp
#include <coroutine>
generator<int> naturals() {
    for (int i = 1;; ++i) co_yield i;
}
for (int x : naturals() | std::views::take(5)) std::cout << x << ' ';   // 1 2 3 4 5
```

Lazy generators like Python/JavaScript. `co_await` for asynchronous workflows — relevant for Day 81 (Async Rust Deep Dive) as a contrast.

### Why this matters

C++20/23 retrofits modern ergonomics: concepts (Rust-trait-like), ranges (iterator adapters as in Rust), `format` (Rust's `format!`), coroutines (async). Anyone learning here sees how languages influence each other — and where C++ makes compromises (compatibility with C++98 legacy) that Zig/Rust drop.

### Pitfalls

- **Range views are lazy** — they do not store. Iterating twice over the same view → performance problem; `std::ranges::to<std::vector>()` (C++23) materializes.
- **Concepts vs. SFINAE:** concepts deliver better error messages, but specialization (`template<> class Stack<bool>`) still exists — mixing is possible.
- **`std::format` only since C++20**, `<format>` header; older compilers (`gcc < 13`) support it partially. Use fmtlib as a fallback.
- **Coroutines need library support** — `generator<T>` arrives in C++23 (`<generator>`), manual implementation is complex.
- **Modules** (`export module foo;`) solve the header problem — but build systems (CMake) need updates; currently rarely in use.

## 🛠️ Practice

**Task:** Write a C++20 program that (a) builds a pipeline of filter + transform + take over a vector, (b) defines its own concept `Hashable`, and (c) uses `std::format`.

**Step by step:**

1. `day25/main.cpp`:

   > **Hints:**
   > - Define a concept `Hashable` with a `requires` clause: `{ std::hash<T>{}(t) } -> std::convertible_to<std::size_t>;`.
   > - A `template <Hashable T>` function returning `std::hash<T>{}(t)`.
   > - Build a lazy pipeline: `v | std::views::filter(...) | std::views::transform(...) | std::views::take(3)`.
   > - Use `std::format("...{}", x)` for output instead of `printf`.

2. Build: `g++ -std=c++20 -Wall -Wextra -O2 -o day25 day25/main.cpp` (gcc ≥ 13 or clang ≥ 16).
3. Sanitize: `g++ -std=c++20 -fsanitize=address,undefined -g -o day25_asan day25/main.cpp && ./day25_asan`.
4. Provoke a constraint violation: call `my_hash(std::vector<int>{})` — compile error "constraints not satisfied".

**Definition of Done (DoD):**

- [ ] `g++ -std=c++20 -Wall -Wextra` compiles without warnings (recent compiler needed).
- [ ] Pipeline output: `even-squared: 4\neven-squared: 16\neven-squared: 36`.
- [ ] `Hashable` concept accepts `int` and `std::string`, rejects `std::vector<int>`.
- [ ] `std::format` formats `int`, `double` (`{:.2f}`), string.
- [ ] You can compare: C++20 ranges ↔ Rust `Iterator::filter().map().take()`.
- [ ] Commit: `git commit -m "day25: concepts, ranges, std::format (c++20)"`.

**Extension (optional):** Implement a coroutine `generator<int> naturals()` with `co_yield` and iterate via `std::views::take`. (C++23: `<generator>` header.)
