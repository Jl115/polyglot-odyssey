**Block:** Block 2: The Low Level · Zig

---

## 📖 Theory

Zig is an alternative to C: the same low-level control, but **better defaults** (no hidden control flow, no hidden memory allocation, explicit allocators) and a powerful metaprogramming model: `comptime`.

### `comptime` — code generation through reflection

Every Zig value can be `comptime` — the compiler evaluates it at compile time. Generic functions are simply function parameters marked `comptime`:

```zig
fn max(comptime T: type, a: T, b: T) T {
    return if (a > b) a else b;
}
const m = max(i32, 3, 7);            // comptime T, no template syntax
```

Zig's `@typeInfo` provides static reflection (like a `concept`/`trait`):

```zig
const std = @import("std");
fn isNumeric(comptime T: type) bool {
    return switch (@typeInfo(T)) {
        .int, .float => true,
        else => false,
    };
}
```

### Error unions — explicit error handling without exceptions

Zig has no exceptions. Functions that can fail have the return type `T!E` (value OR error). You must propagate the error with `try` or handle it with `catch` — like Rust's `Result<T,E>`, but syntactically lighter.

```zig
const std = @import("std");
const ParseError = error{ Empty, Invalid };

fn parse_int(s: []const u8) ParseError!i32 {
    if (s.len == 0) return error.Empty;
    return std.fmt.parseInt(i32, s, 10) catch return error.Invalid;
}

pub fn main() !void {
    const v = try parse_int("42");          // propagates error upward
    std.debug.print("{d}\n", .{v});
    const fallback = parse_int("x") catch 0;  // catches locally
    std.debug.print("{d}\n", .{fallback});
}
```

`try` propagates, `catch` handles, `err: |e|` binds the error value. `anyerror` is the universal error set.

### Language philosophy: no hidden control flow

- No operator overloading, no exceptions, no hidden copy, no hidden alloc.
- `for`/`while` without `break`/`continue` tricks.
- Pointer types: `*T`, `[*]T`, `[]T` (slice), `[N]T` (array) — all syntactically distinguishable.

### Why this matters

Zig is a C-replacement candidate in kernels/embedded/build systems. Its design decisions (`comptime`, error unions, explicit allocators) are the clean synthesis of C++ templates and Rust `Result`. Block 2 ends with the comparison on Day 32 — where exactly this is weighed against Rust.

### Pitfalls

- `try` in `pub fn main() !void` propagates to the OS exit code — runtime crash instead of exception.
- `comptime` code cannot do everything: no heap alloc at compile time, no I/O.
- Error sets are `anyerror` (large) or an explicit set (efficient, but all errors must be declared).
- Zig is still pre-1.0 — API changes are frequent (e.g. 0.11 → 0.12 build system switch).
- `@import("std")` is *not* a namespace import like in Rust — it is a compile-time module.
