## 📖 Theory

### Templates: compile-time code generation

Templates are **hygienic macros** with type parameters. The compiler generates separate code for each instantiation (`Stack<int>`, `Stack<double>`) — monomorphization like in Rust/Zig, but *type-checking per instantiation* (two-phase lookup is more complex).

```cpp
template <typename T>
class Stack {
    std::vector<T> data_;
public:
    void push(T v)      { data_.push_back(std::move(v)); }
    T pop()             { T v = std::move(data_.back()); data_.pop_back(); return v; }
    bool empty() const  { return data_.empty(); }
};
```

Template code must live in headers (unless with `extern template` or C++20 modules) — in contrast to Rust generics, which may be private in the `crate`.

### STL: containers, iterators, algorithms

The STL is the standard library with three pillars: **containers** (`vector`, `map`, `unordered_map`, `string`), **iterators** (`begin()/end()`, ranges), and **algorithms** (`sort`, `find`, `transform`, `accumulate`).

```cpp
std::vector<int> v = {5, 2, 8, 1};
std::sort(v.begin(), v.end());                       // {1,2,5,8}
std::sort(v.begin(), v.end(), std::greater<>{});     // {8,5,2,1} (lambda-less)
auto it = std::find(v.begin(), v.end(), 5);          // iterator to 5
```

C++20 **ranges** make algorithms composable:

```cpp
#include <ranges>
auto evens_squared = v
    | std::views::filter([](int x){ return x % 2 == 0; })
    | std::views::transform([](int x){ return x * x; });
for (int x : evens_squared) std::cout << x << ' ';
```

### Iterators as abstraction

An iterator is a generalized pointer: `++it`, `*it`, `it == end()`. Container-agnostic code:

```cpp
template <typename It>
auto sum(It first, It last) {
    typename std::iterator_traits<It>::value_type s{};
    for (; first != last; ++first) s += *first;
    return s;
}
```

### Why this matters

Templates are C++'s answer to C `void*` generics (Day 21/22): type-safe, with no runtime cost. Anyone who knows Rust generics or Zig comptime grasps the concept immediately — but C++ templates are more powerful (SFINAE, concepts, variadic) and more error-prone (endless error messages). Block 2 compares exactly these tradeoffs between languages.

### Pitfalls

- **Template code in `.cpp` without explicit instantiation** → linker error. Fix: header-only or `template class Stack<int>;` in the cpp.
- **`std::vector<bool>`** is a specialization with bit-packing → no real `T&` reference. Avoid for pointer/reference semantics.
- **Iterator invalidation:** `for (auto& x : v) { if (x==2) v.push_back(0); }` → UB. Rust catches this via the borrow checker.
- **SFINAE / concepts:** error messages are long. C++20 `requires`-clauses (concepts) make readability significantly better.

**Task:** Implement a template `Stack<T>` with `push`/`pop`/`empty`/`size`, and use STL algorithms (`std::sort`, `std::find_if`, `std::accumulate`) on a `std::vector<T>` with lambda comparators.

**Step by step:**

1. `day24/stack.hpp`:

   > **Hints:**
   > - A `template <typename T> class Stack` wrapping `std::vector<T> data_`.
   > - `push` does `data_.push_back(std::move(v))`; `pop` moves out `data_.back()` then `pop_back`; add `empty()` and `size()` (`noexcept`).

2. `day24/main.cpp`:

   > **Hints:**
   > - Push a few ints into a `Stack<int>`, then pop them all into a `std::vector<int>`.
   > - Sort descending with `std::sort` + a lambda comparator `[](int a, int b){ return a > b; }`.
   > - Use `std::find_if` (lambda) to locate the first even, and `std::accumulate` to sum the vector.

3. Build: `g++ -std=c++17 -Wall -Wextra -O2 -o day24 day24/main.cpp`.
4. Sanitize: `g++ -std=c++17 -fsanitize=address,undefined -g -o day24_asan day24/main.cpp && ./day24_asan`.
5. Provoke iterator invalidation: after `v.push_back(0)` in the loop → ASan catches the UB.
