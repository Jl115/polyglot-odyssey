# Day 28: Zig: Build System & FFI

**Block:** Block 2: The Low Level · Zig

> **Goal of the day:** You define a `build.zig`, integrate a C source via `addCSourceFile`, export a Zig function to C via `export fn` — and prove that a C program can link and call your Zig library.

---

## 📖 Theory

### `build.zig` — build system as code

Zig has **no Makefile, no CMake**. The build system is itself a Zig program (`build.zig`) that uses the `std.Build` API. This is the same `comptime` approach as for language features — builds are debuggable, typed, composable.

```zig
const std = @import("std");
pub fn build(b: *std.Build) void {
    const target = b.standardTargetOptions(.{});
    const optimize = b.standardOptimizeOption(.{});

    const exe = b.addExecutable(.{
        .name = "app",
        .root_source_file = b.path("src/main.zig"),
        .target = target,
        .optimize = optimize,
    });
    b.installArtifact(exe);

    const run = b.addRunArtifact(exe);
    b.step("run", "Run app").dependOn(&run.step);
}
```

`zig build` → builds. `zig build run` → builds + runs. `zig build -Dtarget=aarch64-linux-gnu` → cross-compile.

### C interoperability: Zig as a drop-in C compiler

Zig can **compile and link C code directly** — `@cImport` binds C headers at compile time. This is the fastest FFI bridge that exists (no bindgen step).

```zig
const c = @cImport({
    @cInclude("stdio.h");
});
pub fn main() void {
    _ = c.printf("hello from C's printf, called by Zig\n");
}
```

`zig cc` is a full drop-in for `cc` — a project can set `CC="zig cc"` and immediately benefits from Zig's cross-compile capability.

### `export fn` — Zig functions callable from C

A function with `export` is exported with the C ABI, without name mangling. It looks like a C function to the linker.

```zig
export fn zig_add(a: c_int, b: c_int) c_int {
    return a + b;
}
```

A Zig library (.a/.so/.dll) with this function can be linked from C/C++/Rust/Python.

### Cross-compile without a toolchain matrix

`zig build -Dtarget=x86_64-windows-gnu` compiles for Windows — without MinGW installed, a single Zig compiler covers *all* targets. This is central for CI/CD and the capstone (Day 34).

### Why this matters

Zig's build system is simultaneously a build tool and a C compiler — unique. Anyone cross-compiling C/C++ projects can use Zig as a "better GCC." And FFI becomes trivial: Zig functions directly callable from Rust/C (Day 31 goes deeper), which the capstone (Day 34 polyglot pool) exploits.

### Pitfalls

- The `build.zig` API changed across 0.11 → 0.12 → 0.13 → 0.14 (paths, `b.addExecutable` signature) — keep the version current.
- `@cInclude` needs include paths via `addIncludePath` in build.zig or `zig cc -I...`.
- `export fn` may only return C-ABI-compatible types (`c_int`, `[*c]u8`, `bool`) — Zig slices are *not* C types (pointer + length pair).
- C strings `[*c]const u8` are not `[]const u8` — length is missing. Convert via `std.mem.span`.
- Build step dependencies: `b.step("test").dependOn(&run_test.step)` — if you forget `dependOn`, the step runs empty.

## 🛠️ Practice

**Task:** Build a Zig library with `export fn zig_double(c_int) c_int`, compile it as a static lib, and call it from a C program — all through a single `build.zig`.

**Step by step:**

1. `day28/build.zig`:

   > **Hints:**
   > - Add a static library `zigmath` from `src/math.zig` with `linkLibC()`.
   > - Add an executable `app` from `src/main.c` via `addCSourceFile`, then `linkLibrary(lib)`.
   > - Wire a `run` step depending on `addRunArtifact(exe)`.

2. `day28/src/math.zig`:

   > **Hints:**
   > - `export fn zig_double(x: c_int) c_int` returning `x * 2` — C-ABI, no name mangling.

3. `day28/src/main.c`:

   > **Hints:**
   > - `#include <stdio.h>`, declare `extern int zig_double(int x);`, call it and `printf` the result.

4. Build & run: `cd day28 && zig build run` → output: `zig_double(21) = 42`.
5. Cross-compile test: `zig build -Dtarget=x86_64-windows-gnu` → produces `zig-out/bin/app.exe` (without a Windows toolchain).

**Definition of Done (DoD):**

- [ ] `zig build run` prints `zig_double(21) = 42`.
- [ ] `zig-out/lib/libzigmath.a` exists (static library).
- [ ] C source calls the Zig function via `extern` successfully.
- [ ] Cross-compile to Windows produces `app.exe` without an installed Windows toolchain.
- [ ] You can explain: why is `export fn` a C-ABI function (name not mangled, `c_int` instead of `i32`).
- [ ] Commit: `git commit -m "day28: zig build system + export fn to C"`.

**Extension (optional):** Export a function `zig_alloc(size_t) -> void*` that uses a `GeneralPurposeAllocator` — demonstrate that C code can trigger Zig allocators.
