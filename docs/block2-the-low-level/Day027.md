## 📖 Theory

### The rule: no hidden allocation

In C/C++, `new`/`malloc` calls the global heap allocation. In Zig **there is no default heap function** — every function that needs memory takes an `std.mem.Allocator` as a parameter. That makes memory visible, testable, and swappable.

```zig
fn build_string(alloc: std.mem.Allocator, n: usize) ![]u8 {
    const buf = try alloc.alloc(u8, n);
    @memset(buf, 'A');
    return buf;
}
```

### The three central allocators

| Allocator | Purpose | Properties |
| --- | --- | --- |
| `GeneralPurposeAllocator` (GPA) | default heap, with diagnostics | detects leaks/use-after-free; **not** speed-optimized |
| `ArenaAllocator` | bulk allocation for short lifetimes | one `free` cleans everything; ideal for parsers/request handlers |
| `FixedBufferAllocator` | in-place allocation from a stack array | no syscall, deterministic; for embedded/tests |

```zig
// GPA — diagnostic allocator
var gpa = std.heap.GeneralPurposeAllocator(.{}){};
defer _ = gpa.deinit();                       // checks leaks on shutdown
const alloc = gpa.allocator();

// Arena — bulk
var arena = std.heap.ArenaAllocator.init(alloc);
defer arena.deinit();                          // one free for everything
const aalloc = arena.allocator();

// FixedBuffer — stack-backed
var buf: [1024]u8 = undefined;
var fba = std.heap.FixedBufferAllocator.init(&buf);
defer _ = fba.reset();
```

### `defer` — deterministic cleanup

`defer` runs an expression at end of scope — like Rust's drop, but written explicitly (no RAII destructor magic).

```zig
{
    const buf = try alloc.alloc(u8, 100);
    defer alloc.free(buf);                    // always called at block end
    // ... use buf
}   // here free(buf)
```

### Memory categories: stack, heap, static

- **Stack:** local `var x: i32 = 0;` — automatically freed.
- **Heap:** via allocator — you call `free`.
- **Static/const:** embedded in the binary, immutable (e.g. string literals `[]const u8`).

### Why this matters

Explicit allocators are perhaps Zig's most important design decision: they allow *sandboxing* (FixedBuffer in tests), *embedded* (no malloc syscall), and *custom pools* without code changes — just by passing a different allocator. Rust does the same via the `Global` trait, but less radically. The Block 2 capstone (Day 34) builds exactly such a swappable pool.

### Pitfalls

- **GPA without `deinit()`** → leak detection never runs → leaks undetected.
- **Arena never `deinit`** → all allocations leak.
- **FixedBuffer overflow** → allocator returns `error.OutOfMemory` (clean behavior, no UB like a C buffer overflow).
- **Unclear slice ownership:** a function returning `[]u8` should document who must free (caller vs. callee). Zig has no borrow-checker documentation system like Rust.
- **`defer alloc.free(buf)` *after* `return` values**: `defer` runs before the return — beware if you return the buffer (use-after-free!).

## 🛠️ Practice

**Task:** Implement a function `reverse_in_place` that runs with three different allocators — and prove that GPA reports **0 leaks** at the end.

**Step by step:**

1. `day27/src/main.zig`:

   > **Hints:**
   > - `reverse_copy(alloc, src)`: `try alloc.alloc(u8, src.len)`, fill it in reverse order, return the slice.
   > - GPA block: init `GeneralPurposeAllocator(.{}){}`, `defer _ = gpa.deinit()`, then alloc + `defer alloc.free(rev)`.
   > - Arena block: wrap the GPA allocator in `ArenaAllocator.init(...)`, `defer arena.deinit()` — no per-slice free needed.
   > - FixedBuffer block: `var buf: [256]u8 = undefined;` + `FixedBufferAllocator.init(&buf)` — no free needed; reset reclaims.

2. Build & run: `cd day27 && zig build run`.
3. Provoke a leak: comment out `defer alloc.free(rev);` in the GPA block → GPA deinit must warn about a leak at program end (stderr: "memory leak").
4. Provoke overflow: reduce `buf: [256]u8` to `[3]u8` → FBA returns `error.OutOfMemory`, a clean error instead of a crash.

**Definition of Done (DoD):**

- [ ] `zig build` compiles without warnings.
- [ ] All three allocators produce the identical result "olleh".
- [ ] GPA with leak provocation: stderr shows `memory leak` on exit.
- [ ] FBA with buffer-too-small: clean `error.OutOfMemory` (no crash/UB).
- [ ] You can explain: why is `Allocator` as a parameter better than a global `malloc`?
- [ ] Commit: `git commit -m "day27: zig allocators (gpa leak-detect, arena, fixed-buffer)"`.

**Extension (optional):** Write your own `BumpAllocator` (linear allocator: one pointer, `alloc` advances, `reset()` at the end) and measure the speedup vs. GPA over 100k allocations.
