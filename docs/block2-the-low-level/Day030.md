## 📖 Theory

### The `Allocator` interface

`std.mem.Allocator` is a vtable-based interface: a `ptr` + `vtable` pointer. Every implementation provides `alloc`, `resize`, `free`. The user only calls `alloc.alloc(T, n)` / `alloc.free(slice)` — never the vtable directly.

```zig
pub const Allocator = struct {
    ptr: *anyopaque,
    vtable: *const VTable,
    pub const VTable = struct {
        alloc: *const fn(...) anyerror!?[*]u8,
        resize: *const fn(...) bool,
        free: *const fn(...) void,
    };
    pub fn alloc(self: Allocator, comptime T: type, n: usize) ... { ... }
};
```

### The `bump` pattern: linear allocator

Bump allocation is the fastest strategy: a cursor (`offset`) advances on every `alloc`. **No freelist, no coalescing, no lookup**. Trade-off: you cannot free individual blocks — only a `reset()` cleans everything. Perfect for phases like request handling, AST building, game frames.

```zig
const BumpAllocator = struct {
    buffer: []u8,
    offset: usize = 0,
    const Self = @This();

    fn init(buf: []u8) Self { return .{ .buffer = buf }; }
    fn reset(self: *Self) void { self.offset = 0; }

    fn alloc(ctx: *anyopaque, len: usize, alignment: u8, _: usize)
        anyerror!?[*]u8
    {
        const self: *Self = @ptrCast(@alignCast(ctx));
        const fwd = std.mem.alignForward(usize, self.offset, alignment);
        const end = fwd + len;
        if (end > self.buffer.len) return null;
        self.offset = end;
        return @ptrCast(&self.buffer[fwd]);
    }
    fn resize(_: *anyopaque, _: usize, _: u8, _: usize, _: usize) bool { return false; }
    fn free(_: *anyopaque, _: []u8, _: u8, _: usize) void {}

    pub fn allocator(self: *Self) std.mem.Allocator {
        return .{ .ptr = @ptrCast(self), .vtable = &.{ .alloc = alloc, .resize = resize, .free = free } };
    }
};
```

### Safety switches: `@setRuntimeSafety`

Zig has **runtime safety** for out-of-bounds, integer overflow, null deref — but they cost cycles. In hot loops you disable them per block:

```zig
pub fn hot_loop(buf: []u8) void {
    @setRuntimeSafety(false);
    // no bounds check here → maximum speed, but UB on a bug
    for (buf) |*b| b.* +%= 1;
}
```

`@intCast`, `@floatFromInt` etc. are implicitly unchecked in ReleaseFast; in Debug/ReleaseSafe they check. Anyone who knows C understands: Zig makes *controlled* what is standard in C (no checks).

### Allocator choice as an architecture decision

| Pattern | When | Lifetime |
| --- | --- | --- |
| GPA | default, debug | per allocation |
| Arena | request handler, parser | per phase |
| Bump | game frame, AST | per frame |
| FixedBuffer | embedded, test | never free (reuse) |
| Pool (fixed-size) | many equal-sized objects | per block |

### Why this matters

Anyone performance-optimizing C/C++ code builds pools/arenas by hand (or uses `tcmalloc`/`jemalloc`). Zig makes this part of the language. The Block 2 capstone (Day 34) is exactly such a polyglot pool; Day 32 compares with Rust's `bumpalo` crate. Performance-critical code lives or dies by allocator choice — this is the heart of "The Low Level".

### Pitfalls

- **BumpAllocator with individual `free`:** impossible — `free` is a noop. Memory is only released on `reset()`.
- **Forgetting alignment:** use `alignForward` instead of `offset + len` — otherwise UB on typed pointers.
- **`@setRuntimeSafety(false)` globally:** UB in ReleaseFast *crashes non-deterministically* — only Debug catches it. Always test with `Debug`/`ReleaseSafe`.
- **Vtable indirection costs:** BumpAllocator via vtable costs an indirect call; in an inlining-hostile hot loop → call `alloc_inline` manually.
- **Slice `free` with the wrong allocator:** `arena.free(buf)` is a noop — memory leaks until `arena.deinit`. Document ownership.

**Task:** Implement a `BumpAllocator`, measure the speedup against `GeneralPurposeAllocator` over 100k small allocations, and selectively disable safety to measure the further speedup.

**Step by step:**

1. `day30/src/main.zig`:

   > **Hints:**
   > - `BumpAllocator` struct with `buffer: []u8` and `offset: usize`; `alloc` aligns forward via `std.mem.alignForward`, advances `offset`, returns `null` when it would exceed `buffer.len`.
   > - `resize` returns `false`; `free` is a noop (bump strategy — only `reset()` reclaims memory).
   > - Expose an `std.mem.Allocator` via `.{ .ptr = @ptrCast(self), .vtable = &.{ .alloc = ..., .resize = ..., .free = ... } }`.
   > - A `workload` allocating N small buffers, and `main` timing Bump vs GPA with `std.time.nanoTimestamp()`.

2. Build: `cd day30 && zig build run`.
3. Compare: GPA should be 5–50× slower than Bump (depending on platform).
4. Safety comparison: build with `zig build -Doptimize=ReleaseFast` and again with `ReleaseSafe` — measure the speedup difference.
