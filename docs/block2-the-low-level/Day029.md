## 📖 Theory

### Zig's async: colorless functions

In most languages there are two function colors: **sync** (`fn foo()`) and **async** (`async fn foo()`) — and async can only be called from async (the color problem, Bob Nystrom's famous blog post). Zig does it differently: **any function can suspend**, the compiler automatically generates a coroutine frame. Callers do not have to be "async".

```zig
fn simple_async() void {
    suspend {}                     // here the caller can call resume
    // ... after resume
}
```

The compiler generates a state machine (like Rust's `async {}` desugaring to `Future`), but without an `async` keyword.

> **Status note:** Zig 0.11/0.12/0.13 partially rolled back the `async`/`await` keywords; in 0.13 there is `nosuspend` and the async features are in flux. Async in Zig is currently pre-1.0 and unstable. Use Tokio (Day 10) for production; Zig async is a research topic.

### `freestanding` target: without an OS

`os = .freestanding` means: no libc, no syscalls, no main in the standard sense. This is the basis for kernels/bootloaders/firmware.

```zig
// build.zig
const exe = b.addExecutable(.{
    .name = "kernel",
    .root_source_file = b.path("src/kernel.zig"),
    .target = b.resolveTargetQuery(.{ .cpu_arch = .x86_64, .os_tag = .freestanding }),
});
exe.code_model = .kernel;
```

```zig
// kernel.zig
export fn _start() callconv(.C) noreturn {
    while (true) {}                 // typical kernel loop
}
```

No `pub fn main` — the entry point is called `_start` (or defined via a linker script).

### `comptime` metaprogramming for device trees

Kernels/embedded benefit massively from `comptime`: register definitions, memory-mapped IO, peripheral layouts are generated at compile time from tables.

```zig
const Register = struct { addr: usize, width: u8 };
const registers = [_]Register{
    .{ .addr = 0x1000, .width = 32 },
    .{ .addr = 0x1004, .width = 8 },
};
fn write_reg(comptime r: Register, val: u32) void {
    const ptr: *volatile u32 = @ptrFromInt(r.addr);
    ptr.* = val;
}
```

### Why this matters

Zig is a serious option for kernel development and firmware (Windows libraries already use Zig code as a C compiler). Colorless async is unique and the counter-design to Rust's Tokio model (Day 10/81). Block 5 (Edge & Future) will reuse this for bare-metal RISC-V.

### Pitfalls

- **Async API instability:** 0.11 → 0.13 broke the ABI; use Tokio (Day 10) in production.
- **Freestanding without a linker script:** memory layout undefined, a linker script (`linker.ld`) with a `_start` address is required.
- **`volatile`** is a pointer qualifier in Zig (`*volatile T`), not a type modifier like in C.
- **Panic handler:** in `freestanding` you must define your own `pub fn panic` (the default assumes libc).
- **Cross-compile CPU features:** `resolveTargetQuery` with `.cpu_arch=.x86_64` is not always enough; features like `+sse2` influence the ABI.

## 🛠️ Practice

**Task:** (a) Write an `async`-style function with `suspend`/`resume` (or a `nosuspend` wrapper, if on 0.13), and (b) build a minimal `freestanding` binary for x86_64 that just has `_start` in an infinite loop.

**Step by step:**

1. `day29/build.zig`:

   > **Hints:**
   > - Add a hosted executable `async_demo` from `src/async_demo.zig` with a `run-demo` step.
   > - Add a `kernel.bin` executable targeting `b.resolveTargetQuery(.{ .cpu_arch = .x86_64, .os_tag = .freestanding })` with `code_model = .kernel`.

2. `day29/src/async_demo.zig` (Zig 0.13-compatible with `nosuspend`):

   > **Hints:**
   > - A function containing `suspend {}` and a `pub fn main() void` that prints before/after (Zig 0.13 async is unstable — a `nosuspend`/placeholder demo is acceptable).

3. `day29/src/kernel.zig`:

   > **Hints:**
   > - Define a custom `pub fn panic(...) noreturn` that loops forever (freestanding has no default panic).
   > - `export fn _start() callconv(.C) noreturn`: write a message, then `while (true) {}`.

4. Build: `cd day29 && zig build`.
5. Inspect the binary: `file zig-out/bin/kernel.bin` — should show "freestanding" or an ELF without OS-specific sections.
6. Cross-compile experiment: change `cpu_arch = .riscv64` → produces a RISC-V binary without a RISC-V toolchain installed.

**Definition of Done (DoD):**

- [ ] `zig build` compiles both binaries without errors.
- [ ] `file zig-out/bin/kernel.bin` shows an ELF without an OS tag (freestanding).
- [ ] `zig build run-demo` runs and prints "before suspend / after".
- [ ] Cross-compile to RISC-V produces a binary (without an installed RISC-V toolchain).
- [ ] You can explain: why does `freestanding` need its own panic handler?
- [ ] Commit: `git commit -m "day29: zig async + freestanding kernel stub"`.

**Extension (optional):** Write a linker script `linker.ld` with ENTRY(_start) and sections, link `kernel.o` via `zig cc -T linker.ld -nostdlib -o kernel.elf kernel.o` and boot in QEMU (`qemu-system-x86_64 -kernel kernel.elf`).
