## 📖 Theory

C has no ownership model and no borrow checker. The programmer is solely responsible for *who* owns a memory block and *when* it is freed. That is exactly the freedom that Rust (Block 1) restricts — and the source of the top-3 memory bugs:

| Bug | Symptom in C | What Rust does |
| --- | --- | --- |
| Use-after-free | `free(p); p->x` → heap read after release | Compile error (move/borrow) |
| Double-free | `free(p); free(p)` → heap corruption | Compile error |
| Leak | `malloc` without `free` → memory hole | Drop at end of scope |

That is why we study the *original* mechanics here — so that later in Rust you can consciously decide when you need `unsafe` and write `unsafe { }` blocks correctly.

### Stack vs. heap in C

- **Stack:** automatic storage duration. Local variables; `int x = 5;`. Lifetime = scope. Fast, no `free` needed.
- **Heap:** dynamic storage duration via `malloc`/`calloc`/`realloc`. Lifetime = until you explicitly call `free(p)`.

```c
int stack_val = 42;            // stack, automatically freed
int *heap_val = malloc(sizeof(int));
*heap_val = 42;                // heap, you must call free(heap_val)
free(heap_val);
// *heap_val                  // ❌ use-after-free (UB), no compiler error
```

### Pointer arithmetic

Pointers are addresses; `p + 1` does not jump 1 byte, but `sizeof(*p)` bytes. This is the basis for array iteration.

```c
int v[] = {10, 20, 30};
int *p = v;                    // == &v[0]
printf("%d\n", *(p + 2));      // 30 — v[2]
printf("%ld\n", (char*)p + 1 - (char*)p);   // 1 byte difference in char arithmetic
```

### Struct memory layout: padding & alignment

Every type has an **alignment** (`_Alignof(T)`) — an address must be a multiple of it. The compiler inserts **padding** bytes to align members. This explains why structs are often larger than the sum of their members.

```c
#include <stddef.h>
#include <stdio.h>
struct S {
    char  c;   // 1 byte
    // 3 bytes padding → so int is aligned
    int   i;   // 4 bytes
    char  d;   // 1 byte
    // 3 bytes tail padding → struct alignment == 4
};
printf("%zu %zu\n", sizeof(struct S), _Alignof(struct S));   // 12 4
```

`offsetof(struct S, i)` returns the offset of a member from the start of the struct — useful for making padding *visible*.

### Why this matters

Anyone reading C (kernels, libraries, FFI bindings) must understand padding and alignment blindfolded — otherwise UB arises in `memcpy`-based serialization and in `unsafe` Rust FFI code. Block 1 showed *that* Rust prevents unsafe memory bugs; here you see *how* these bugs look in C — the template that Rust pushes back against.

### Pitfalls

- `void*` loses type information: `memcpy(dst, src, size)` with a wrong `size` is UB, not a compile error. Casts to `void*` should be deliberate.
- `sizeof(ptr) != sizeof(array)`: `int *p = arr; sizeof(p)` returns the pointer size (8), not the array size. Arrays decay to pointers on function calls.
- Signed overflow, shifts by ≥ bit width, uninitialized reads — all UB. Compilers may "optimize away" UB.
- Pointer subtraction is only defined within the same array (`p - q` across two mallocs = UB).

## 🛠️ Practice

**Task:** Write a C program that (a) analyzes a struct for padding/alignment and (b) implements a **generic `swap`** that swaps two values of any type — and prove afterwards that ASan/Valgrind are clean.

**Step by step:**

1. Create `day21/main.c`:

   > **Hints:**
   > - Define `struct Mixed` with members `char c; int i; char d;` — the layout analyzed in the Theory section.
   > - Use `sizeof`, `_Alignof`, and `offsetof(struct Mixed, member)` (from `<stddef.h>`) to print the struct size, alignment, and per-member offsets.
   > - `swap(void *a, void *b, size_t size)`: use a temporary byte buffer (a small VLA `unsigned char tmp[size]`) and three `memcpy` calls (`<string.h>`).
   > - In `main`, call `swap` on two `int`s and two `double`s passing `sizeof(T)` each time; print before/after to confirm.

2. Build: `cc -std=c11 -Wall -Wextra -o day21 day21/main.c`.
3. Check with AddressSanitizer: `cc -fsanitize=address,undefined -g -o day21_asan day21/main.c && ./day21_asan`.
4. Check with Valgrind: `valgrind --leak-check=full --error-exitcode=1 ./day21`.
5. Provoke a bug: comment out `free` after a `malloc` → ASan/Valgrind must report it.

**Definition of Done (DoD):**

- [ ] `cc -std=c11 -Wall -Wextra` compiles without warnings.
- [ ] `sizeof(struct Mixed)` is **12**, `_Alignof` is **4** — you explain where the 3+3 padding bytes come from.
- [ ] `swap` correctly swaps `int` and `double` (output matches).
- [ ] `./day21_asan` runs **clean** (exit 0, no leak report).
- [ ] `valgrind --leak-check=full ./day21` reports **0 errors / 0 leaks**.
- [ ] Commit: `git commit -m "day21: C pointers, layout, generic swap (asan/valgrind clean)"`.

**Extension (optional):** Replace the VLA `unsigned char tmp[size]` with `malloc`/`free` to support large structs — and document why the VLA version risks **stack overflow** for `size` in the MB range.
