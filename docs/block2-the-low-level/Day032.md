# Day 32: Zig vs Rust: Tradeoffs

**Block:** Block 2: The Low Level · Polyglot

> **Goal of the day:** You implement the same mini-task (a simple linked list with `push`/`pop`) in Rust and Zig, compare compile time, binary size, safety guarantees, and produce a reasoned "when which language" decision.

---

## 📖 Theory

Block 1 covered Rust, Block 2 the first 6 days Zig. Now the direct comparison. Both languages replace C, but with **different design points**:

| Dimension | Rust | Zig |
| --- | --- | --- |
| Safety model | compile-time borrow checker (aliasing + lifetime) | runtime checks (runtime safety), `@setRuntimeSafety(false)` for speed |
| Metaprogramming | generics + traits + macros | `comptime` + reflection |
| Error handling | `Result<T,E>` + `?`, no exceptions | `T!E` error union + `try`/`catch`, no exceptions |
| Memory | default `Box`/`Vec`, custom via `Global` trait | explicit `Allocator` parameter, no defaults |
| Build system | `cargo`, stable, rich ecosystem | `build.zig`, compact, drop-in C compiler |
| C interoperability | `bindgen` + `extern "C"`, separate tool | native, `@cImport` + `export fn` |
| Async | Tokio/async-std, color (`async fn`) | colorless functions (unstable pre-1.0) |
| Maturity | 1.0 since 2015, stable, ABI-free | pre-1.0, API breaks frequent |
| Ecosystem | huge (crates.io, 100k+ crates) | small, growing fast |

### Safety philosophy

**Rust** moves safety into the compiler: a compiling program is guaranteed memory-safe (modulo `unsafe`). Price: steep learning curve, sometimes fights with the borrow checker.

**Zig** moves safety into runtime: in Debug/ReleaseSafe, out-of-bounds, overflow, null deref are checked and panic cleanly. In ReleaseFast the checks are gone → C-like speed, but C-like UB risk. The programmer decides per block via `@setRuntimeSafety`.

```rust
// Rust: compiler forbids UB
let mut v = vec![1, 2, 3];
let r = &v[0];
v.push(4);                  // ❌ compile error: v borrowed mutably
println!("{r}");
```

```zig
// Zig: runtime check (Debug) or UB (ReleaseFast)
var buf = [_]u8{ 1, 2, 3 };
const x = buf[5];           // Debug: panic; ReleaseFast: UB
```

### Metaprogramming: traits vs comptime

Rust's **traits** are type classes: typed interfaces resolved at compile time (static dispatch via monomorphization, dynamic via `&dyn`). Constraints are declarative (`where T: Hash`).

Zig's **`comptime`** is reflection: you write generic functions as normal functions with a `comptime T: type` parameter, check via `@typeInfo` manually. More flexible, but less declarative — it is more C++ templates than Rust traits.

### FFI: drop-in C compiler vs bindgen

Rust C interop needs three steps: header parser (`bindgen`), wrapper crate, `unsafe extern "C"`. Zig is a drop-in C compiler (`zig cc`) + native `@cImport`. Anyone mixing C libraries saves considerable time with Zig build tooling.

### Ecosystem & maturity

Rust has crates.io, stable Rust 1.0, large corporate use (Linux kernel parts, Cloudflare, AWS, Microsoft). Zig is pre-1.0, ABI unstable, smaller ecosystem — but actively used in C circles (e.g. Bun runtime, Tigerbeetle).

### Why this matters

Anyone working polyglot must choose *with reasons* — not by hype. The Block 2 capstone (Day 34) uses both languages for the same memory pool. Day 89 (Language Choice Matrix) will consolidate this table for productive decisions.

### Pitfalls

- **Rust for quick prototypes:** borrow-checker troubleshooting delays the first version. Zig lets the "first draft" come together faster (UB risk in ReleaseFast).
- **Zig for production:** ABI breaks between 0.11/0.12/0.13/0.14 — library pinning needed.
- **Rust + C library:** bindgen pain point with complex macros/inline functions.
- **Zig + Rust** directly (without a C bridge): only possible via C ABI, no direct Zig-Rust FFI.
- **Async color:** Rust + Tokio forces async through the call stack; Zig solves it (unstable), but in production today Tokio wins.

## 🛠️ Practice

**Task:** Implement a linked list `IntList` with `push_front`/`pop_front` in **Rust** and in **Zig**. Compare: LOC, binary size, compile time, safety guarantee.

**Step by step:**

1. Rust variant `day32/rust/src/main.rs`:

   > **Hints:**
   > - `Node { value: i32, next: Option<Box<Node>> }` and `List { head: Option<Box<Node>> }`.
   > - `push_front`: `Box::new` a node taking `self.head.take()` as its `next`, then assign it to `self.head`.
   > - `pop_front`: `self.head.take().map(|n| { self.head = n.next; n.value })` — no `unsafe`.

2. Zig variant `day32/zig/src/main.zig`:

   > **Hints:**
   > - `Node = struct { value: i32, next: ?*Node }`; `List` holds `head: ?*Node` and an `alloc: std.mem.Allocator`.
   > - `pushFront`: `try self.alloc.create(Node)`, set `.next = self.head`, reassign head.
   > - `popFront`: unwrap head, save the value, advance head, `self.alloc.destroy(n)`; use a GPA with `defer _ = gpa.deinit()`.

3. Build & compare (each with `time` and `ls -l`):

   ```sh
   cd day32/rust && time cargo build --release && ls -l target/release/day32_rust
   cd day32/zig  && time zig build -Doptimize=ReleaseFast && ls -l zig-out/bin/day32_zig
   ```

4. ASan comparison: build both with a sanitizer and test the edge case (pop from empty) — Rust: `None`, Zig: `null` (clean) or in ReleaseFast without a check: UB.

**Definition of Done (DoD):**

- [ ] Both versions compile and run, output identical (4 3 2 1 0).
- [ ] Rust variant: no `unsafe` blocks, compiler refuses use-after-free (prove it by trying).
- [ ] Zig variant: `gpa.deinit()` shows 0 leaks at the end.
- [ ] Measurement table produced: LOC, binary size (KB), compile time, safety guarantee.
- [ ] You can justify: when would you choose Rust, when Zig? (e.g. Rust: security-critical userspace; Zig: build system, C replacement, embedded with drop-in C).
- [ ] Commit: `git commit -m "day32: rust vs zig linkedlist benchmark"`.

**Extension (optional):** Additionally compare the compile time for 10 000 generated lines each (Rust macro vs Zig comptime code generation) — a typical pain point of large codebases.
