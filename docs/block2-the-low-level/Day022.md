## 📖 Theory

### Function pointers

A function pointer stores the address of a function — the basis for callbacks, qsort comparators, and vtables.

```c
int (*cmp)(const void *, const void *);          // type: pointer to function
cmp = &my_compare;                               // address of the function
int r = cmp(a, b);                               // call
```

`qsort` from the C standard library is the classic example of generic code via callbacks — without templates, only via `void*` and a comparator:

```c
#include <stdlib.h>
int cmp_int(const void *a, const void *b) {
    int x = *(const int *)a, y = *(const int *)b;
    return (x > y) - (x < y);                     // saturating subtraction, overflow-safe
}
int arr[] = {3, 1, 2};
qsort(arr, 3, sizeof(int), cmp_int);             // arr == {1,2,3}
```

### Linked list: manual ownership

In C, every `malloc` block belongs to *you*. A linked list holds pointers to nodes — who frees the nodes? The answer in C: *one* central `list_free` function. Multiple owners of the same node → double-free guaranteed.

```c
typedef struct Node { int value; struct Node *next; } Node;

Node *node_new(int v) {
    Node *n = malloc(sizeof *n);
    if (!n) abort();
    n->value = v; n->next = NULL;
    return n;
}

void list_free(Node *head) {
    while (head) { Node *next = head->next; free(head); head = next; }
}
```

### Callbacks as policy (map/filter/reduce over the list)

```c
typedef int (*IntFn)(int);
Node *list_map(Node *head, IntFn f) {
    Node *new_head = NULL, *tail = NULL;
    for (Node *cur = head; cur; cur = cur->next) {
        Node *n = node_new(f(cur->value));
        if (!new_head) new_head = n; else tail->next = n;
        tail = n;
    }
    return new_head;        // new list — caller must free it
}
```

### Why this matters

These two patterns — function-pointer policies and manual single-owner freeing — are exactly what Rust's `Box`/`Vec`/closures *displace*: Rust provides drop automatically and stores closures as typed `FnMut` values. Anyone who understands C understands *why* Rust needs these abstractions and how expensive (or error-prone) the manual version is.

### Pitfalls

- **Leaking on early return:** As soon as a callback loop does `return`, allocated nodes stay on the heap. In Rust, drop would clean up.
- **Double-free via shared pointer:** Two functions hold `Node*` and call `list_free` — double-free, ASan catches it.
- **Comparator UB on NULL/mismatched type:** `qsort` does not check that the comparator matches `size`.
- **Forgetting `next` backup before `free`:** `free(head); head = head->next;` is use-after-free; always save `next`.

**Task:** Build an `IntList` with `push`, `map`, `filter`, `print`, `free` and demonstrate it on square numbers — clean under ASan.

**Step by step:**

1. Create `day22/list.h` and `day22/list.c` + `day22/main.c`:

   > **Hints:**
   > - Declare `typedef struct Node { int value; struct Node *next; } Node;` and `typedef int (*IntFn)(int);`.
   > - Prototype `list_push`, `list_map`, `list_print`, and `list_free`.

   > **Hints:**
   > - `list_push`: `malloc` a node, set `value`/`next` to head, return the new head (prepend).
   > - `list_map`: iterate the source, build a *new* list node-by-node via `list_push(NULL, f(c->value))`, link each to a `tail`; never mutate the original.
   > - `list_print`: walk and `printf` each value.
   > - `list_free`: loop, but save `head->next` into a temp *before* `free(head)` (avoid use-after-free).

   > **Hints:**
   > - Build a list by `list_push`-ing 1..5, then print it.
   > - Build a mapped list using a `square` function cast to `IntFn`, and print both lists to prove the original stays intact.
   > - Free both lists exactly once each.

2. Build: `cc -std=c11 -Wall -Wextra -o day22 day22/list.c day22/main.c`.
3. Sanitize: `cc -fsanitize=address,undefined -g -o day22_asan day22/list.c day22/main.c && ./day22_asan`.
4. Provoke errors: comment out `list_free(b);` → ASan must report leaks. Comment out `Node *nx = head->next;` and replace with the use-after-free version → ASan crash.

- [ ] `cc -std=c11 -Wall -Wextra` compiles without warnings.
