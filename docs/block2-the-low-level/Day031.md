# Day 31: Zig + C Integration

**Block:** Block 2: The Low Level · Polyglot

> **Goal of the day:** You call a Zig function with C ABI from C that uses a Zig allocator, and call a C library from Zig via `@cImport` — and prove both directions with a runnable demo.

---

## 📖 Theory

### Bidirectional FFI

Zig communicates with C in two directions:

1. **Zig → C**: `@cImport` binds headers (compile-time bindgen), call as a normal function.
2. **C → Zig**: `export fn` with C-ABI types (`c_int`, `[*c]const u8`), C source calls via `extern`.

### C-ABI-compatible types

Zig types are **not** automatically C-ABI-compatible. Slices (`[]u8`) are pointer + length pairs, not a C type. For FFI you use:

| Zig | C |
| --- | --- |
| `c_int`, `c_uint` | `int`, `unsigned int` |
| `c_char` | `char` |
| `[*c]u8` | `char *` (C pointer, may be NULL) |
| `[*]const u8` + `usize` | `const char *` + `size_t` (slice as 2 args) |
| `bool` | `_Bool` |
| `?*T` (optional ptr) | `T *` (may be NULL) |

### `@cImport` — including headers

```zig
const c = @cImport({
    @cInclude("string.h");
    @cInclude("stdlib.h");
});
pub fn main() void {
    const s = c.strdup("hello");           // C function directly callable
    defer c.free(s);
    _ = c.puts(s);
}
```

No separate `bindgen` step, no C header parser — Zig's compiler parses the headers itself.

### Ownership across the boundary

The hardest problem: who frees memory? Convention:

- **C allocates → C frees.** Zig may only call `free` if the C allocator is known.
- **Zig allocates → Zig frees.** C gets pointer + length, may only free via a Zig `free` callback.

```zig
// Zig side
export fn zig_alloc_buffer(size: usize) [*c]u8 {
    return @ptrCast(g_alloc.raw(size));   // returns Zig-managed memory
}
export fn zig_free_buffer(ptr: [*c]u8, size: usize) void {
    g_alloc.raw_free(ptr, size);
}
```

### Why this matters

Polyglot systems live off FFI. Rust uses `bindgen` + `extern "C"` (Day 18), Zig does it more natively. The capstone (Day 34) needs exactly this: C/C++/Zig share a memory pool. Anyone who masters bidirectional ownership rules can mix libraries — e.g. call a C lib in Rust via a Zig adapter, or provide a Zig allocator for a C library.

### Pitfalls

- **ABI stability:** `export fn` is C-ABI — stable. Inner Zig calling convention is **not** stable (Zig pre-1.0), never export internal Zig ABI outward.
- **Slice ↔ C pointer:** Zig slice to C → pass `ptr` + `len` separately, or a null-terminated `[*c]const u8` (loses length info).
- **Strings / encoding:** Zig `u8` is a byte, not a char. UTF-8 strings in C → manually carry the length, `strlen` assumption is dangerous.
- **Callbacks:** function pointers as parameters → `callconv(.C)` is mandatory.
- **Panic across boundary:** a Zig panic across C FFI is UB — custom panic handler or `no_panic` build flag.

## 🛠️ Practice

**Task:** Demonstrate bidirectional integration: C calls a Zig `export fn` (with Zig allocator), Zig calls C `strdup`/`free` via `@cImport`.

**Step by step:**

1. `day31/build.zig`:

   > **Hints:**
   > - Static library `zigside` from `src/zigside.zig` with `linkLibC()`.
   > - Executable `app` from `src/main.c` via `addCSourceFile`; link both the library and libc.
   > - A `run` step depending on `addRunArtifact(exe)`.

2. `day31/src/zigside.zig`:

   > **Hints:**
   > - `@cImport` `<string.h>` and `<stdlib.h>` so you can call `c.strdup`/`c.free`.
   > - `export fn zig_uppercase_count(input: [*c]const u8) c_int`: convert via `std.mem.span(input)`, count `A`–`Z` bytes.
   > - `export fn zig_strdup_via_c(input) [*c]u8` returns `c.strdup(input)`; `export fn zig_free_c(ptr) void` calls `c.free(ptr)`.

3. `day31/src/main.c`:

   > **Hints:**
   > - `extern`-declare the three Zig functions, call `zig_uppercase_count` and `zig_strdup_via_c`/`zig_free_c` from `main`, and print the results.

4. Build & run: `cd day31 && zig build run`.

**Definition of Done (DoD):**

- [ ] `zig build run` prints `uppercase letters: 5` and `copy: Hello World From C`.
- [ ] `std.mem.span` converts `[*c]const u8` → `[]const u8` correctly (null-terminated).
- [ ] ASan run (Zig with `-fsanitize=address` via `exe.linkSystemLibrary("asan")` or a GCC build) shows 0 leaks.
- [ ] You can explain: why `strdup` memory must be freed via `c.free` (C allocator) and not via `gpa.free`.
- [ ] Commit: `git commit -m "day31: bidirectional zig+c ffi"`.
